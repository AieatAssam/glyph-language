# RFC 0005: Kernel: integers, booleans, bindings, functions, conditionals, loops, text output

- decided: 2026-11-20
- outcome: rejected
- accepted with supermajority: false
- reason: 2/5 approve, need 0.6667
- approve 2, reject 3, abstain 1

## Votes
- designer-min: reject. Nothing defines how a statement ends: the Lexical section never says which line ends end a statement, and RFC 0003 section 6 assigns that rule to this RFC. Add one rule (a NEWLINE ends a statement outside `( )` and `[ ]`, and `}` closes a block), and align tokens with RFC 0003 and the trap exit status with RFC 0004.
- designer-prag: approve. Each rule is a single sentence, every trap has a defined kind and exit status, and the test plan has run and compile-error tests for every code. One nit to fix before merge: the address example uses main.glyph, but RFC 0002 makes .gl the only source suffix.
- impl-1: reject. The kernel is well scoped, but as written it cannot be accepted. (1) Its lexical rules conflict with RFC 0003 as listed in that vote. (2) Its error codes ignore the block table in RFC 0004: E0101, E0104, E0108 and E0109 are name or effect errors that RFC 0004 puts in E0300-E0499, and E0102 and E0103 are type errors in E0200-E0299. (3) Traps exit with status 3, but RFC 0004 says status 1. (4) The example path uses '.glyph', but RFC 0002 says source files end in '.gl'. (5) 'A loop need not terminate... has no result' does not fit the constitution's rule that every program has exactly one defined result. Either state a defined outcome for non-termination, or justify the exception in the RFC.
- tester: reject. Reject as written. Its error codes do not follow RFC 0004's blocks: E0101 (unknown name), E0102 (type mismatch), E0105 (effect), E0106 (literal range) and E0109 (example) sit in the syntax block E0100-E0199, but belong to the name, type, effect and limits blocks. Its traps exit with status 3, while 0004 says 1. Its trap name 'divide by zero' differs from 0004's hyphenated form. Its tab rule conflicts with 0003, and its addresses use main.glyph, which conflicts with 0002's .gl rule. The design is sound; it needs these fixes and must agree with 0003 and 0004 before it can be implemented.
- user-1: approve. Covers what a small everyday program needs: integers, booleans, bindings, functions, if, while, and text output. Overflow, division by zero and stack exhaustion trap with defined results, which I want as a user.
- user-2: abstain. The summary says text output only prints Text literals, and it does not say how an Int or Bool reaches output. A program that parses data needs to print numbers, so I cannot judge the kernel as useful without that. I read the summary only and could not read the RFC text.
