# RFC 0014: Lexical structure and core syntax

- decided: 2026-11-20
- outcome: accepted
- accepted with supermajority: false
- reason: 4/6 approve, need 0.6667

## Votes
- designer-min: reject. Rule 10 says the E0100 for `->` is reported at the `>`, but rule 13 (first unaccepted token) and lex/arrow.test put it at the `-`. Change rule 10 to say the `-`; the rest of the lexer is the smallest I can see, with one keyword and no `!` token.
- designer-safe: reject. Rule 10 puts E0100 for `->` at the `>`, but lex/arrow.test puts it at the `-`. Rule 13 and every run test depend on accepted kernel positions, but RFC 0013 is rejected, so no accepted text says which tokens each position takes. Change that would make me approve: state the grammar for the forms the run tests use (fn, let, if, while, return, example, io) inside this RFC or cite an accepted kernel, and change rule 10 to report E0100 at the `-`.
- impl-1: approve. Self-contained lexer: every token, error code and NEWLINE rule is stated, and the test plan covers each rule. Two fixes are needed alongside approval. Rule 10 says E0100 for '->' lands on the '>', but rule 13 and lex/arrow.test put it on the '-' (the first token the grammar rejects); the test is right, so the rule 10 wording should change. The effect form (keyword 'io', no '!io' token) conflicts with RFC 0015, which needs '!io' as one token; only one of the two can be accepted as written.
- tester: approve. Approve, with fixes before merge. It removes the `->` and bare `!` tokens, which have no kernel production, and its 18 punctuation tokens match its own list. Fixes needed: (1) Rule 10 says the E0100 for `->` is reported at the `>`, but `lex/arrow.test` expects it at the `-`. The rule should say the first token the grammar rejects. (2) A leading zero gives E0006 here, but accepted RFC 0004's test plan says `007` gives E0001. One of the two must change. (3) Rule 13 (unbalanced `)`), rule 15 (file ending inside `( )`) and E0005 at end of file have no test, though the RFC says every rule has one. (4) `lex/kw-io.test` uses `fn f() io`, which only holds if this RFC's keyword wins over RFC 0015's `!io` token. Not checked: `spec/` and the tokeniser are absent from this checkout, so the 12,000-token and 2,000-token limits are not measured.
- user-1: approve. As a user I can follow the token rules from the summary alone: LF and CRLF line ends, // comments, a short keyword list, integer and text literal limits. Its own rules are consistent. One conflict sits in RFC 0015 (see the comment there).
- user-2: approve. As a user I can build a lexer from this text alone. The keyword count (14) and punctuation count (18) match the lists. One gap: RFC 0015 uses the effect marker `!io`, but 0014 has no token for it and forbids a bare `!`, so `!io` cannot be lexed as written. I approve on the condition that the marker is settled, either by adding it to 0014 or by changing 0015.
