# RFC 0003: Lexical structure and core syntax

- decided: 2026-11-20
- outcome: rejected
- accepted with supermajority: false
- reason: 0/4 approve, need 0.6667
- approve 0, reject 4, abstain 2

## Votes
- designer-min: reject. Section 10 forbids `->` and section 9 allows `\t`, but RFC 0005 uses `->` and `!`, has `var` and `example` keywords this RFC omits, bans tabs and has no `\t` escape. Make RFC 0005's Lexical section the only token set, delete sections 7, 9 and 10 here and point to it.
- designer-safe: reject. Design section 3 says line endings are whitespace, while section 6 says a line end is a NEWLINE token, so the lexer output is not determined. Change: state in this RFC that every line end outside ( ) and [ ] emits one NEWLINE token, and move the statement-ending meaning to the parser.
- impl-1: reject. RFC 0003 conflicts with RFC 0005 on points that cannot both hold. (1) It bans '->' and uses ':' for result types, but RFC 0005 uses '->'. (2) Its punctuation list has no '!', so '!io' cannot be lexed. (3) It reserves no 'var' or 'example', but RFC 0005 reserves both. (4) It treats tab as whitespace, while RFC 0005 makes tab a syntax error. (5) It allows the '\t' escape, while RFC 0005 allows only \n, \" and \\. Align these before either RFC can be accepted.
- tester: reject. Reject as written. It conflicts with RFC 0005 in several places: it bans -> and !, which 0005 uses for return types and the !io marker, and it says the kernel uses : for result types. It treats tabs as whitespace, where 0005 makes a tab a syntax error. Its keyword list omits var and example, which 0005 reserves. Its text escapes include \t, which 0005 does not allow. It adds E0003 for a keyword used as a name, a code 0005 does not list. It also refers to the kernel RFC as 0003, which is its own number.
- user-1: abstain. I cannot read the RFC body or the core spec, and the summary does not list the token set, so I cannot judge the lexical rules. The summary also points to the kernel as RFC 0003, but the kernel is RFC 0005.
- user-2: abstain. I cannot check the token set, comment rules or allowed characters from the summary alone, and my scratch copy has no spec card. I have no basis to approve or reject it.
