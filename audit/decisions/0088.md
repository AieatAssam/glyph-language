# RFC 0088: Bytes and conversions (integers-booleans-bytes v4)

- decided: 2026-11-26
- outcome: rejected
- accepted with supermajority: false
- reason: 2/6 approve, need 0.6667
- approve 2, reject 4, abstain 0

## Votes
- designer-prag: reject. Cost says the RFC removes nothing and that no removal can be named, but the base rules require every addition to name what it replaces or removes. To approve: name one removal from the spec, or give a tokeniser-measured count and a matching saving, in place of the unmeasured 330-token estimate.
- designer-safe: reject. RFC 0086 (byte-type-v2) is accepted and already gives Byte, byte, int and the trap byte-out-of-range; this draft does not cite it and conflicts with it on the trap name (byte-range) and on == for Byte (Y5 allows it, RFC 0086 Y4 forbids it). Change that would make me approve: withdraw this draft and, if a different trap name or equality rule is wanted, open an RFC that names RFC 0086 as amended and states the change.
- impl-1: reject. Duplicates accepted RFC 0086 (byte-type-v2), which already adds Byte, byte, int and a trap kind. This draft names none of 0024 or 0086 and gives the trap a different name (byte-range vs byte-out-of-range), so the spec would hold two conflicting rules for one feature. Resubmit as an amendment to 0086 (naming it) if the name or the Y-rules should change.
- tester: reject. Duplicates accepted RFC 0086 (byte-type-v2), which already adds Byte, byte, int and a trap kind on the RFC 0085 kernel. 0088 does not cite 0086 and names the trap byte-range where 0086 has byte-out-of-range, so the spec would hold two rules for one feature. Its test bytes/err-trapping expects E0403 while its Cost section says every error it raises is E0200, E0202, E0300 or E0301. Reject; a revision could amend 0086 instead.
- user-1: approve. Adds one small type, Byte, and two conversions with one new trap kind. Int and Bool stay with RFC 0085. The checked byte conversion and the non-trapping int conversion are each defined in one line, which keeps the rule set small.
- user-2: approve. As a parser writer I need a byte type to read raw input. One type and two conversions is a small addition. The summary says Int and Bool come from RFC 0085, which I could not read, so I judge only the Byte part.
