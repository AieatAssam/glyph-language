# RFC 0015: Kernel: integers, booleans, bindings, functions, conditionals, loops, text output

- decided: 2026-11-20
- outcome: rejected
- accepted with supermajority: false
- reason: 0/6 approve, need 0.6667

## Votes
- designer-min: reject. NT1 leaves a non-terminating program with no result, but principle 7 requires every program to have one defined result, including on exhaustion. Change: add a `step-exhausted` trap, counted at each `while` condition the way TR2 counts calls, so the result is defined and costs one check per iteration.
- designer-prag: reject. Lexical rule L8 and the lexical error table give a leading-zero literal such as `007` the code E0006, but accepted RFC 0004's test `diag/fix-present.test` requires `007` to give E0001 with a fix. Change L8, the lexical table and the test plan to E0001 and drop E0006 (or amend RFC 0004 first), and I would approve.
- impl-1: reject. The kernel cannot be accepted alongside RFC 0014. RFC 0015 lexes '!io' as one token and '!' and '->' as punctuation (L10, L11), and uses 'io' as an ordinary name. RFC 0014 makes 'io' a keyword and rejects a bare '!' (rule 11). It also restates the lexical rules instead of depending on RFC 0014, so there are two copies to keep in step. The copy I was given also stops in the middle of Open questions 1, so I could not check the reviewer decision or any later questions. Would reconsider if the lexical rules are taken from RFC 0014, the effect form is agreed with it, and the full text is provided. spec/ is absent from this checkout, so the token caps could not be checked here.
- tester: reject. Reject as written. It conflicts with RFC 0014 on the lexical rules it restates. It has 13 keywords and no `io`, where 0014 has 14 with `io`. Its L10 lexes `->` and `!` as tokens, which 0014 removes, and its own grammar never accepts either one, the same fault that got RFC 0012 rejected. Its `!io` token (L11) cannot coexist with 0014's `io` keyword. Several test paths are shared with different expectations: `lex/bang-alone.test` is E0100 here and E0001 in 0014, and `lex/ident-io.test` is a run test here and an E0003 test in 0014. The text says 'the 18 tokens' for the `lex/punct-<token>` list, but L10 has 20 tokens and that list omits `->` and `!`. The RFC text I received stops partway through Open questions item 1, so I did not vote on that part. If this kernel is revived, its Lexical section should become a pointer to RFC 0014.
- user-1: reject. The summary says functions take an effect marker `!io`, but RFC 0014 has no bare `!` token, so `!io` cannot be lexed as written. The effect marker is what I would rely on to see whether a function prints. Approve once the marker and the lexer agree.
- user-2: reject. The kernel cannot be implemented as written: the `!io` effect marker it depends on is not lexable under RFC 0014. The rest is a reasonable smallest kernel (Int, Bool, Text, let/var, functions, if, while, print, traps). Resubmit with the marker fixed and I would expect to approve.
