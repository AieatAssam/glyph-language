## Votes
- designer-min: approve. Counter confirms the cost claim: the fib program is 33 tokens with the short spellings and 32 with the long ones, and the sum loop ties at 21 each, so no measured program costs more. Among equal costs the long words are the ones models already write (principle 8). The keyword count stays at 15. Revision note: the Cost table's sq row (36 to 35) was not reproduced here, so it should be re-run in the RFC text.
- designer-safe: approve. The counter reproduces sq 36 to 35 and fib 33 to 32 with no program costing more, and each of the eight spellings is one token alone, so the Motivation holds. Notes: the W4 card lines are not in the tree's spec/card.md (190 tokens, no kernel text, not the 251 cited), so W4 applies once RFC 0109 K1 lands; the sum row does not reproduce (I get 36 both ways, not 42); the models-write-it-without-error tie-break is unmeasured (open question 1).
- impl-1: approve. The decision is right under principle 8: the four long spellings never cost more tokens than the short ones in the sample, and at a tie the words models already write win. I could not re-run the counter in this session (the call was refused), so the counts in the RFC are unverified by me. Notes for revision or the implementing PR, not reasons to reject: (1) spec/card.md has no kernel section in this tree (it holds only the diagnostics card), so W4 and the card cost figures (251 tokens) cannot be applied as written; the card text the RFC edits must be located or the RFC must name the file that holds it. (2) spec/errors.json holds only E0001, E0005, E0006, E0010, E0100 and E0500; E0003, E0200, E0300, E0301 and E0400 are used by in-force RFCs but not catalogued. The new spelling does not add codes, but the catalogue gap should be closed by the implementing PR.
- impl-2: approve. Approve. The decision is one spelling policy: the four short keyword spellings become long ones, and the counter never charges more for the long form. I ran the counter myself: the RFC 0109 sample is 36 tokens short and 35 long, as stated; the fib body is 19 short and 18 long; the sum fragment is 28 in both. Notes for revision, not reasons to reject: (1) Tests in this RFC use E0003, E0300, E0301 and E0400, but spec/errors.json holds only E0001, E0005, E0006, E0010, E0100 and E0500. The implementing PR must catalogue the codes it uses or the catalogue check fails. This gap also exists under RFC 0109 today. (2) W4 edits kernel card lines, but spec/card.md has only the diagnostics card now. The 251-token card figure cannot be checked against the tree; RFC 0109 K1 puts the kernel card in with the implementing PR. (3) RFC 0114, open at the same time, writes every example with put. If this RFC is accepted first, put is no longer a keyword and those lines stop parsing, so RFC 0114 must be rewritten with print. Both RFCs amend the same RFC 0109 text and card lines. (4) Error rates for the new spellings are not measured. I rely on principle 8's tie rule (take the form models already write); the benchmark should confirm it.
- tester: approve. Notes for revision or the implementing PR, none a reason to reject: (1) W4 edits the kernel card, but spec/card.md holds only the diagnostics card now. The 251-token figure is RFC 0109's card text, which is not yet in the tree (its K1 is unimplemented). (2) Choosing while, example and print over wh, ex and put rests on an unmeasured claim about model error rates (open question 1). Change-only-ret gives the same counts, so the wider change is a tie-break, not a saving. The RFC should say whether they are rewritten as new tests or retired. Tree has only two conformance tests, so this is not yet a conflict.
