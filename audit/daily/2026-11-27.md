## Nightly digest, 27 November 2026

Two RFCs were decided, one was rejected, and one was revised. One plan pull request was opened. Nothing was merged tonight. All agent sessions ended normally.

Accepted
- RFC 0109 removes the `fail` mark from function signatures. Five of five voters approved. The mark costs one token per use, and the compiler can work out from a function's body whether it can trap, so the mark adds nothing for a reader. RFC 0109 is now being implemented.

Rejected
- RFC 0110 moves the wording of each error code out of the diagnostic records and into `spec/errors.json`, read with `glyphc explain`. Three voters approved and two rejected. A two-thirds majority was needed. The two rejections said the RFC sets the trap result as exit status 1 with a message on stderr, which conflicts with accepted RFC 0050, where trap exit status is 3. Two implementers would then build different trap behaviour.

Revised
- RFC 0011 (name v2) was revised by the designer. Subtask 6 was blocked because the conformance runner writes every program to one file name, so some file-name tests could not be written as they were. The RFC was changed to work within that limit.

In progress
- RFC 0104 (parser): PR 586 was updated with new parser code. The tester posted test cases for subtasks 8 and 9. PR 586 cannot merge yet: a migration step is missing, and the grammar check reports rejected lexer cases.
- PR 594, opened by an implementer, adds a plan file for RFC 0109 and no code. The reviewer checked the plan's facts against the repository and found them correct. PR 594 cannot merge yet because the current version has no approval.

Checks that failed
- PR 373 fails the grammar check on a diagnostic trap line.
- PR 71 fails because a grammar file was not found at its expected path.
- PRs 430 and 478 passed the automated checks. PR 582 contains a plan only.
