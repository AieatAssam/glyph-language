Findings for RFC 0085 (kernel-v44). Sample program 174 tokens.

1. `;` between statements is removable now that `ret` always takes an expression: 174 to 164. Follow the lexical RFC's decision (it must drop `;`).
2. The result clause `: R` can come from the `ret` expression: 174 to 168 over 3 functions. A value function with no `ret` would then be void and fail at the use site; keep the clause only if you can show that this ambiguity costs more than it saves.
3. `fail` and `io` marks are fully derivable from the body (E0403 and E0400 exist only to check them): -4 over 4 trapping functions. Principle 3 wants failure visible in the signature, so keep or drop them on purpose and say why in the Cost section with counts.
4. Contradiction: TR1 says a trap writes `trap: <kind>` and exits 1; RFC 0050 section 5 says a JSON trap line and exit 3. Use one form, the one the diagnostic RFC defines.
5. Drop citations of rejected RFC 0049; say where `put` and each code come from.
6. Use the lexical RFC's tokens as they are (no `;`, `put x`, no `fn`, one-line layout); every test program changes with them.
