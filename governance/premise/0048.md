Findings for RFC 0048 (lexical-syntax-v4). Base program (fib + main) = 94 tokens.

1. Layout is deferred (open question 2). Decide it here: the canonical form, and `fmt` output, is one line with no indentation and a space only where two word tokens would otherwise merge (`fn main`, `ret n`), none around punctuation. The compiler rejects any other layout with a fix (principle 4). The kernel's indented `layout` test becomes a non-canonical-layout test.
2. Drop `;`. No statement starts with a token that can continue an expression, so statements can simply follow each other: 94 to 90 tokens. The one ambiguity is `ret` followed by a statement starting with a name; make `ret` the last statement of its block.
3. `put` takes its argument without parentheses (`put x`): 94 to 88 for three calls.
4. Top level holds only functions, so `fn` is redundant: `fib(n Int)Int{...}` (-1 per function). Pick one parameter/result form with the fewest tokens: `n: Int` and `): Int` cost 2 more than `Int n` / `)Int` per signature.
5. Zero-parameter declarations need no `()` (`main io{...}`): -2 per declaration. Calls keep `()`.
6. Comments cost tokens and the compiler ignores them; models do not need them (principle 8). Remove comment syntax.
7. `\n` costs one more token than a raw LF inside text. LF inside a text literal is content, not layout: accept it and drop the escape.

Fine as is: every keyword already costs one token; `and`/`or`/`not` cost no more than symbols; `<=`/`>=` beat `not (a > b)`.
