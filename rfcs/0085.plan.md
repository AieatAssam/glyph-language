# Plan: RFC 0085 Kernel (kernel-v44)

RFC 0085 is the kernel. It replaces RFC 0084 (rejected) and amends RFC 0048 in `fn_decl` (adds `fail`) and `stmt` (bare `ret` is removed). It needs the lexer and parser of `rfcs/0048.plan.md` first. This plan changes parts of that work, so it names each overlap in Conflicts 3. The checker and the code generator are new work. The plan writes no code.

## Current state in this checkout

- `compiler/stage0/src/kernel/` has `parse-expr.ts` (it emits E0500 at line 167; RFC 0048 subtask 8 removes that), `arith.ts`, `types.ts`, `rt-trap.ts`, `rt-count.ts` and `rt-print.ts`, each with a `.test.ts`. Read them before writing a new helper. This plan assumes only their file names.
- `compiler/stage0/src/parser/parse.ts` is the skeleton parser, for `fn NAME ( ) io { NAME ( INT ) }`. `compile.ts` and `codegen.ts` import it. RFC 0048 subtask 11 replaces it.
- There is no checker. `cli.ts` `check` answers "no front end yet" (exit 2) for every file (RFC 0048 subtask 12 changes this for syntax errors).
- `spec/errors.json` has E0001, E0005, E0006, E0010, E0100 and E0500. This RFC needs E0200, E0201, E0202, E0300, E0301, E0302, E0303, E0400 and E0403, and RFC 0048 needs E0003. Each is added by the first PR that emits it.
- `spec/card.md` has no kernel section.
- `conformance/kernel/print-one.test` (RFC 0020) runs `print(1)`. It passes now, and the gate reports 2 of 2 (RFC 0085 G-c).
- `toolkit/wasm-encoder.ts` (`ModuleBuilder`, `Op`, `importFunc`, `addFunc`, `setMemory`, `exportFunc`, `exportMemory`) is the only code generation path. Use it.

## Conflicts and decisions

1. **Prerequisite not opened.** RFC 0085 needs `retire-print-one` accepted before CI can pass. It is not in this assignment, so this plan does not open it. `print-one.test` passes until subtask 6, which reports the unknown name `print`. So subtasks 1 to 5 keep CI green, and subtasks 6 to 21 can be written but cannot merge until `retire-print-one` is accepted. Architect: open and accept it.
2. **Status.** The frontmatter says `accepted` and the header says `Status: draft`. The votes are four abstentions and one approval. This plan follows the frontmatter, as the assignment does. Acceptance, the cooldown (G-b) and the quorum are the orchestrator's decision. This plan does not settle them.
3. **Overlap with `rfcs/0048.plan.md`.** This plan needs 0048 subtasks 1 to 12 done first. It changes three of 0048's items: subtask 9 (`ret` takes an expression; this plan's subtask 2), subtask 10 (`fail` in `fn_decl`; this plan's subtask 1), and subtasks 17 and 18 (the run-test list and `spec/grammar.peg`). For 17, the tests named in RFC 0085's T0048 list are written by this plan's subtask 19. The other tests in 0048 subtask 17 stay there. For 18, both plans edit `spec/grammar.peg`. 0048 subtask 18 goes first, and this plan's subtask 20 adds only the `fail` and `ret expr` changes.
4. **Test name mismatch.** The RFC's `kc-text-cmp` program is `if 1 == true { }`. It has no text literal. It tests E3, so it is written in subtask 5 under the RFC's name.
5. **How examples are evaluated (EX3).** `check`, `build` and `run` must run each example. Decision: compile each example with the same code generator into a one-function wasm module, and run it in Node's `WebAssembly` API. A trap exits through `proc_exit`, and the example fails. A second interpreter in TypeScript is rejected because it is a second semantics to keep in step.
6. **Stable addresses (A1).** The RFC defines `<file>::<name>` and `<file>::<name>#<n>`, but gives no output field for them. Subtask 4 stores them in the checker's symbol table only. Architect: say where an address appears, if anywhere.
7. **Fix field for E0403.** The fix inserts or deletes the `fail` token. Subtask 10 emits it only if `diagnostic.ts` already has a fix field. The runner does not compare `fix`, so no test checks it.
8. **`rt-print.ts`.** Keep the file name. Subtask 12 changes what it writes, not what it is called.
9. **Test ownership.** Each test row in RFC 0085 is written by exactly one subtask. `kc-fail-order` (`fn main() fail io { }`, E0100 at `io`) is a parse error, so it is written in subtask 1, not subtask 10. Subtask 10 is checker-only, and C0 (RFC 0085) means the fail-mark check never runs on a file with a parse error, so the test cannot be owned there.

## Subtasks

Each line changes under 400 lines. Write each subtask's tests first, then the smallest code that passes them. Test files are `conformance/kernel/*.test`, with `id`, `rfc` and `kind` in the meta block. Compile-error tests give the code and byte-offset span in the JSON `expect-errors` form. Node tests run through `sbx node --test 'compiler/stage0/**/*.test.ts'`.

### Checker (new stage: `compiler/stage0/src/checker/`)

- [ ] 3. Checker skeleton and wiring. The checker walks the parsed program, collects diagnostics in source order, and records each expression's type in a side table for codegen. `cli.ts`: `check` runs the checker after the parser; a program with no error exits 0 (it was 2). `build` and `run` also run it and exit 1 with the records on stderr. Test `cli.test.ts` with fake writers: a valid file exits 0; nothing goes to stdout on an error. No rule yet. Depends on subtask 2 and 0048 subtask 12. Target under 200 lines.
- [ ] 4. Program-level names (RFC 0085 M1, F6, P1, A1). E0302 at end of file when there is no `main`; E0300 at the second `main`; E0200 when `main` has a parameter or result; E0300 at a function named `put`, `Int`, `Bool` or `fail`, and at a second function of the same name. Store each declaration's address in the symbol table (Conflicts 6). Add E0200, E0300 and E0302 to `spec/errors.json`. Tests: `kc-no-main`, `kc-dup-main`, `kc-main-sig`, `kc-dup`, `kc-fn-put`. Depends on 3. Target under 250 lines.
- [ ] 5. Expression types (RFC 0085 T1, T2, T4, E3, E5, E8, E9). Int literals above 9223372036854775807 are E0500, including after unary `-`, at the literal (T1). This unblocks RFC 0048 subtask 19. Operator operand types are checked (E3: E0200 at the operator, no report for the operands). Condition types for `if` and `wh` (E5). A failed expression takes `?` and reports nothing more (E8). Tests: `kc-type`, `kc-cmp-type`, `kc-bool-op`, `kc-text-cmp` (Conflicts 4), `kc-int-max`, `kc-int-min`. Depends on 4. Target under 350 lines.
- [ ] 6. Names and bindings (RFC 0085 B1 to B5, T6, F6, E0301 and E0303). `let` and `var` take the type of their expression. Use before declaration, an unknown name, and a function, `put`, `Int` or `Bool` used as a value are E0301 at the name. Assignment needs `var` (E0303 at the name); a type mismatch is E0200 at the expression. Parameters are declared in the body. A binding that shadows a function name, a parameter, or a reserved name is E0300. Add E0301 and E0303 to `spec/errors.json`. Tests: `kc-unknown`, `kc-use-before`, `kc-type-value`, `kc-fn-value`, `kc-assign-let`, `kc-assign-param`, `kc-assign-type`, `kc-dup-param`, `kc-dup-param-2`, `kc-reserved-put`, `kc-reserved-int`, `kc-reserved-fail`, `kc-binding-fn`. **From this subtask on, `print-one.test` fails (Conflicts 1); merge waits on `retire-print-one`.** Depends on 5. Target under 350 lines.
- [ ] 7. Calls, arity and returns (RFC 0085 E6, T5, F3, F4, F5). Argument count and types (E0200 at the argument, or at the callee for arity). A call with no result used as a value is E0200 at the call (`?`). `ret expr` must match the result type; `ret` in a function with no result is E0200 at the expression. A function with a result clause must return on every path (E0201 at its closing `}`; a `wh` never counts; an `if` counts only with an `else` where both blocks return). Recursion is not checked (F5). Add E0201 to `spec/errors.json`. Tests: `kc-arity`, `kc-void-value`, `kc-ret-value`, `kc-missing-ret`, `kc-if-else-partial`, `kc-wh-return`. Depends on 6. Target under 350 lines.
- [ ] 8. `put` and text literals (RFC 0085 P1, T3). `put(x) io` takes one `Int` or one text literal. Any other argument type, including `Bool`, is E0200 at the argument. Any other count is E0200 at `put`. A text literal anywhere else is E0200 at the literal, and its type is `?`. Tests: `kc-put-bool`, `kc-put-arity`, `kc-text-let`, `kc-text-arg`. Depends on 7. Target under 250 lines.
- [ ] 9. Effects (RFC 0085 F2). A function without `io` may not call an `io` function or `put`: E0400 at the callee name. Add E0400 to `spec/errors.json`. Tests: `kc-effect`, `kc-effect-call`. Depends on 8. Target under 150 lines.
- [ ] 10. Fail mark (RFC 0085 F7, C0). A body is trapping if it contains binary `+ - * / %`, unary `-`, a `wh` statement, or a call to a file function (a call to `put` does not count). The `fail` token is present exactly when the body is trapping; a wrong mark is E0403 at the function name. Insert or delete the token as the fix (Conflicts 7). C0: this check and example evaluation run only when no other error exists. Add E0403 to `spec/errors.json`. Tests: `kc-fail-missing`, `kc-fail-extra`, `kc-fail-main`. Depends on 9. Target under 250 lines.
- [ ] 11. Example types and effects (RFC 0085 EX1, EX2). The expression of `ex` must be `Bool` (E0200 at the expression). It may call only functions without `io`; an `io` call or `put` is E0400 at the callee name. Tests: `kc-example-type`, `kc-effect-example`. Depends on 10. Target under 150 lines.

### Code generation (`codegen.ts` and `kernel/`, through `toolkit/wasm-encoder.ts`)

- [ ] 12. `put` output and the trap line (RFC 0085 P2, TR1). `put` writes an `Int` in decimal with a leading `-`, then LF; a text literal writes its decoded bytes (RFC 0048 rule 9), then LF, through WASI `fd_write`. A trap writes `trap: <kind>` to stderr and exits 1 through `proc_exit`. This replaces the skeleton `print` in `codegen.ts`. Tests: `put-one`, `put-text`, `put-mixed`. Depends on 11. Target under 300 lines.
- [ ] 13. Integer arithmetic and its traps (RFC 0085 E1, E2). `+ - *` and unary `-` trap `overflow`. `/` and `%` truncate toward zero, and `%` takes the sign of the left operand. A zero divisor traps `divide-by-zero`. `MIN / -1` traps `overflow`; `MIN % -1` is 0. Use `kernel/arith.ts` and `kernel/rt-trap.ts`. Tests: `print-int`, `int-min`, `arith`, `rem-identity`, `min-mod`, `paren-nested`, and the trap tests `trap-overflow`, `trap-add`, `trap-sub`, `trap-neg`, `trap-min`, `trap-div`, `trap-mod`. Depends on 12. Target under 350 lines.
- [ ] 14. Comparisons and Bool operators (RFC 0085 E3, E4). `== !=` on two `Int` or two `Bool`; `< <= > >=` on `Int`; `and`, `or`, `not` on `Bool`, with `and` and `or` short-circuiting. Tests: `bool-ops`, `bool-or`, `cmp-ordering`, `cmp-eq`. Depends on 13. Target under 300 lines.
- [ ] 15. Bindings, assignment, blocks and `if` (RFC 0085 B1 to B3, C1, E7 for operands). Each `let` and `var` is a wasm local; shadowing an outer name gives a new local. Test: `let-var`, `let-bool`, `shadow`, `if-else-chain`, `layout`, `comment-line`. Depends on 14. Target under 300 lines.
- [ ] 16. Loops and the step budget (RFC 0085 C2, TR3). `wh` has no `break` or `continue`. Each call frame has its own counter, which adds 1 on each evaluation of a `wh` condition. Before the count would exceed 10000000, the run traps `step-exhausted`. Use `kernel/rt-count.ts` if it fits; read it first. Tests: `wh-sum`, `digit-sum`, `step-ok`, and the trap test `trap-step` (stdout `1`). Depends on 15. Target under 250 lines.
- [ ] 17. Functions, calls and the depth limit (RFC 0085 F1, F4, F5, E7, TR2). Parameters, results, `ret expr`, void functions that leave by falling off the end, recursion, and left-to-right evaluation of calls. `main` is depth 1; a call that makes depth 10001 traps `stack-exhausted`, checked at function entry. Tests: `fn-call`, `fn-result-io`, `fn-bool-param`, `fn-bool-result`, `fn-io`, `fn-void`, `fn-discard`, `fn-recursion`, `if-else-return`, `ret-early`, `eval-order`, `eval-order-ge`, `short-circuit`, and the trap test `trap-stack`. Depends on 16. Target under 380 lines.
- [ ] 18. Example evaluation (RFC 0085 EX3, E0202). `check`, `build` and `run` evaluate each example at depth 0 with a new loop counter, run only when C0 finds no error (Conflicts 5). `true` passes; `false` or a trap is E0202 from `ex` to the end of the expression. Add E0202 to `spec/errors.json`. Tests: `example-ok`, `kc-example`, `kc-example-trap`, `kc-example-budget`, `kc-example-stack`. Depends on 10, 16 and 17. Target under 300 lines.
