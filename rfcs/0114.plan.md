# Plan: RFC 0114 Reading standard input (input)

RFC 0114 is accepted (frontmatter). It amends RFC 0109 (kernel-v47): rule B5 (reserved names), rule TR1 (trap kinds), and the kernel card in `spec/card.md`. It adds one built-in, `input()`, one trap kind `input`, and one reserved name `input`. It adds no keyword and no new error code. This plan follows RFC 0114 and writes no code. It was checked against this session's scratch copy on 2026-11-27.

Verified with the protected counter (`sbx python3 -m tools.check.tokens --text`): `main io{put input()}` is 6 tokens, `main io{put get()}` is 6, and the sum program is 31. These match the RFC's Cost table. The card cost (251 now, 298 after) is not measured here: `spec/card.md` has no kernel card yet, because RFC 0109 plan subtask 21 adds it.

- `compiler/stage0/src/kernel/rt-trap.ts` lays out memory as: table 0 .. 8K-1 (K kinds, 8 bytes each), iovec at 32, nwritten at 40, trap lines from 64. With four kinds the table ends at byte 31, and the trap lines end at byte 142. Its comment says "rt-trap uses 0 .. 143".
- `compiler/stage0/src/kernel/rt-print.ts` hard-codes `NWRITTEN = 40` ("same word rt-trap uses"), and reserves 256 .. 304 for `print_int` and `print_text`.
- `toolkit/wasm-encoder.ts`: `importFunc` throws if any function was added before it. `setMemory` and `exportMemory` are used once, in `addTrapRuntime`. `addData` takes an offset and bytes.
- `toolkit/run.ts` and `toolkit/wasi-browser.ts` both feed `stdin` to fd 0, so `fd_read` on fd 0 gets the test's `stdin` section. `tools/check/conformance.py` already reads `stdin` and checks `trap` tests with `expect-stderr` as a substring.
- `spec/errors.json` has no E0300, E0301 or E0400 yet. RFC 0109 plan adds them (its Diagnostics convention). RFC 0114 adds no code.
- `input` is not a keyword in RFC 0104 or RFC 0109, so the lexer reads it as an ordinary name.

## Conflicts and decisions

1. **The fifth trap kind overlaps the trap iovec (blocks nothing, must be fixed in subtask 2).** With five kinds the trap table covers bytes 0 to 39. The iovec sits at 32 to 39, so the table's last entry (`input`, bytes 32 to 39) shares bytes with the iovec. `rt-trap`'s trap function writes the iovec at run time over those entry bytes. The current order happens to copy each value to itself, so the output is correct today, but the layout is wrong and fragile. Decision: subtask 2 moves the iovec and nwritten words above the table. Proposed: iovec at 40 (8 bytes), nwritten at 48 (4 bytes), trap lines still from 64. The trap lines then end at byte 154 (79 + 12 bytes for `trap: input\n`), which is below the 256 that `rt-print` reserves. `NWRITTEN` in `rt-print.ts` moves to 48 in the same PR. The layout comments in both files are updated. The implementer checks these numbers against the lines before editing.
2. **A digit terminator must not be consumed (I3c), but `fd_read` consumes every byte it reads.** Reading `1-2` with two `input()` calls must give `1` then `-2`. If the first call consumes `-`, the second call reads `2`. Decision: the byte reader keeps one byte of lookahead across calls, in a memory cell or a mutable global (whichever `ModuleBuilder` supports; check first). The program cannot see it (I7). Subtask 3 tests it and subtask 4 uses it. Conformance row `input-no-consume` covers it. The RFC does not state this; the PR body says so.
3. **A stdin read error is not covered by the RFC.** `fd_read` can return an errno other than 0. The RFC says nothing about it. Decision: a non-zero errno is treated as end of input, so the call traps `input` (I5a). This is a defined result, which principle 7 requires. The architect may amend RFC 0114 if another result is wanted. The PR body says so. No conformance test can reach this path; subtask 3's node test covers it with a fake `fd_read`.
4. **The `fd_read` import is added only for programs that call `input`.** `importFunc` must run before any local function, so codegen has to know from the checked program whether `input` is used. Decision: programs with no `input` call get no new import and produce the same bytes as before. Their conformance rows stay byte-identical. Subtask 6 tests this.
5. **The trap-kind check in RFC 0109 subtask 13 changes.** RFC 0109 Conflicts 9 says subtask 13 checks `types.ts` against the four TR1 kinds. RFC 0114 amends TR1 to five. Decision: when subtask 2 lands before 0109 subtask 13, 0109 subtask 13's check expects five kinds, in the order `overflow`, `divide-by-zero`, `stack-exhausted`, `step-exhausted`, `input`. The PR body says so.
6. **Test ids and file names.** The RFC writes test ids as `input/<name>`. Decision: each file is `conformance/kernel/input-<name>.test`, its `--- meta` has `id: input/<name>`, `rfc: 0114` and its `kind`. This follows RFC 0109 plan's convention for `kernel/` files.
7. **Rows added beyond the RFC's Test plan.** Subtask 1 adds `input-no-consume`, `input-max`, `input-range-neg`, `input-lead-zero`, `input-err-fn` and `input-err-example`. Each covers a rule the RFC states (I3c, I3d, I1, I2) that the RFC's own rows do not reach. Adding tests is allowed; no RFC test is edited.
8. **Spans in the compile-error tests.** Byte spans are checked in JSON form. Offsets are counted from the start of the file. `f Int{ret input()}main io{put f()}` puts `input` at bytes 10 to 15. `main io{put input}` puts it at 12 to 17. `main io{let input=1}` puts it at 12 to 17. `input Int{ret 1}main io{put input()}`, the function-name row, puts the name at 0 to 5. `f Int{ret 1}ex input()==1 main io{put f()}` puts it at 15 to 20.
