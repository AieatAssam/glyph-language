# Plan: RFC 0086 Byte type on the current kernel (byte-type-v2)

RFC 0086 is accepted (frontmatter). It amends RFC 0024 and builds on RFC 0085 (kernel-v44, accepted). It adds the value type `Byte` (integers 0 to 255), the built-ins `byte` and `int`, the trap kind `byte-out-of-range`, reserved names `Byte`, `byte` and `int`, one extension of the fail-mark rule (F7 of RFC 0085), and spec and card edits. This plan was checked on 2026-11-26 against this session's scratch copy. Nothing was built or run. Its test list is the one in RFC 0086, which gives full programs, so no snippet needs a wrapper.

Subtasks 1 and 2 need only the runtime and types, which exist now. Subtasks 3 to 12 wait on RFC 0085's implementation, which has no plan yet (Conflicts 1).

## State in this checkout

- `compiler/stage0/src/kernel/` holds the runtime and types, with their node tests: `types.ts` (TRAP_KINDS has four kinds; TRAP_LINE; MAX_DEPTH; MAX_STEPS), `rt-trap.ts`, `rt-print.ts`, `rt-count.ts`, `arith.ts`, and `parse-expr.ts` (the expression parser, built to RFC 0020).
- Not present for RFC 0085: the declaration and statement parsers, the checker (scope, types, fail mark, examples), kernel codegen, `spec/core/kernel.md` (`spec/core/` holds only `diagnostic.md` and `name.md`), and the `# Card: kernel` section of `spec/card.md` (the card has only `# Card: diagnostics`).
- `rfcs/0085.plan.md` does not exist.
- `spec/errors.json` has E0005, E0100 and E0500. It does not have E0200, E0202, E0300, E0301 or E0403, the codes RFC 0086 uses.
- `rfcs/0024.plan.md` has 11 subtasks, none ticked.
- `tools/check/conformance.py` (lines 10 to 12) compares a `compile-error` test's code and span line. A `trap` test checks exit status and that `expect-stderr` is a substring of stderr.

## Conflicts and decisions

1. **RFC 0085 has no plan (blocking).** Subtasks 3 to 12 need its parser, checker and codegen. Decision: the subtasks name the RFC 0085 module each touches. Each one waits until `rfcs/0085.plan.md` exists and the subtasks it depends on have landed. If a named module is missing when you reach a subtask, stop and report it. Architect: write the RFC 0085 plan before any of 3 to 12.
2. **RFC 0024 plan is superseded.** RFC 0086 replaces RFC 0024's design. Decision: do not execute `rfcs/0024.plan.md`. Three of its decisions change under RFC 0086: (a) no `builtin::byte` or `builtin::int` addresses (RFC 0086 Y12 adds none); (b) `put` replaces `print`; (c) no statement wrapper is needed, because RFC 0086 gives whole programs. Architect: record RFC 0024 as superseded (RFC 0086 open question 3).
3. **Representation of `Byte`: an i32 holding 0 to 255.** This is carried over from the RFC 0024 plan. `byte` range-checks its i64 argument and wraps it with `i32WrapI64` (`toolkit/wasm-encoder.ts` line 173, opcode 0xa7). `int` widens with `i64ExtendI32U` (line 174, opcode 0xad). Both ops exist, so no toolkit change is needed.
4. **The trap table overlaps at five kinds.** `rt-trap.ts` puts the fd_write iovec at `IOVEC = 32`, which is 32 to 39. The table takes 8 bytes per kind from address 0, so five kinds fill 0 to 39, and kind 4's entry sits on the iovec. The overlap writes the same bytes back, so it happens to work, but the layout comment in `rt-trap.ts` is then false. Decision: move `IOVEC` to 48 (bytes 48 to 55 are free). `NWRITTEN` stays at 40, which `rt-print.ts` also uses. The trap lines run from 64. The four current lines take 79 bytes (64 to 142), and `trap: byte-out-of-range` plus LF adds 24, so the lines end at 166. That is below `rt-print.ts`'s DIGITS region at 256. Subtask 1 makes this change and tests it.
5. **Trap kind index.** `byte-out-of-range` is index 4 in TRAP_KINDS, after RFC 0085's four kinds in TR1 order.
6. **Error codes.** RFC 0086 adds no code. It uses E0200, E0202, E0300, E0301 and E0403, which RFC 0085 defines. The constitution requires each code to be in `spec/errors.json` before it is emitted. The first PR that emits a code adds its entry, with the meaning from RFC 0085's table. Subtasks 4 to 8 check the catalogue and add a missing entry in the same PR. Never change an entry once it is in.
7. **Test format.** Every test under `conformance/bytes/` has a `--- meta` block with `id`, `rfc: 0086` and `kind`. The publisher refuses an update if one of these is missing. Run tests have `expect-stdout` and `expect-exit`. Trap tests have `expect-exit` and `expect-stderr`. Compile-error tests use `CODE LINE` in `expect-errors`. The runner does not compare the span column or the `fix` text that RFC 0086 gives in its table, so the PR body must say those are unchecked.
8. **Node unit test.** `kernel/types.test.ts` asserts four trap kinds. Subtask 1 updates that one assertion and says so in the PR body. No conformance test is edited.
9. **MAX_STEPS does not match RFC 0085.** `types.ts` line 30 sets `MAX_STEPS = 1000000000`. RFC 0085 TR3 says 10000000. This is not part of RFC 0086. Subtask 1 does not touch it. The RFC 0085 plan must fix it.
10. **Roadmap (RFC 0086 open question 4).** `architecture/ROADMAP.md` (M2b) says no new RFC is proposed before the first merge puts a compiler on `main`. This plan does not decide that. The orchestrator does.
11. **No address for `Byte`, `byte` or `int`.** RFC 0086 Y12 adds none. Principle 9 of the constitution may ask for one (RFC 0086 open question 2). This plan follows the RFC.

## Subtasks

Write each subtask's tests first, as new files. Each subtask changes under 400 lines and touches one stage where it can. Node tests go in `compiler/stage0/src/kernel/*.test.ts`. Conformance tests are new files under `conformance/bytes/`. Never edit an existing conformance test. No dependency is added.

### Runtime and types (no RFC 0085 plan needed)

- [ ] 1. Trap kind and layout (Y8). In `types.ts`, append `byte-out-of-range` to TRAP_KINDS and add `'byte-out-of-range': 'trap: byte-out-of-range'` to TRAP_LINE. In `rt-trap.ts`, move `IOVEC` from 32 to 48 and rewrite the layout comment to match Conflicts 4. Tests first: `rt-trap-byte.test.ts` (new) runs a harness that calls `trap(4)` and expects stderr `trap: byte-out-of-range`, exit 1, and empty stdout. In `types.test.ts` (line 20), change the four-kind assertion to five kinds and rename the test. `rt-trap.test.ts` must still pass for kinds 0 to 3. Target under 150 lines.
- [ ] 2. Type `Byte` and the built-in table (Y1, Y5, Y12). In `types.ts`, add `export type Byte = number` and `export const BYTE_MAX = 255`, with a comment citing Y1. New `compiler/stage0/src/kernel/builtins.ts`: a table with exactly two entries, `byte: (Int) => Byte` and `int: (Byte) => Int`. Both are pure and carry no effect mark. There are no addresses (Y12). Tests first: `builtins.test.ts` (new) checks the two entries and their signatures, that neither has `io` or `fail`, and that `BYTE_MAX` is 255. Target under 150 lines.

### Parser (blocked on RFC 0085's declaration parser)

- [ ] 3. Type productions (Y2). Blocked on RFC 0085's `parse-decl.ts`. Add `"Byte"` to `ptype` and `rtype` only. Do not add a `let` annotation (B1) or a literal (Y3). Tests first: `parse-byte.test.ts` (new, node) checks that `fn f(b: Byte): Byte { }` parses, that `fn f(): Byte { }` parses, that `let b: Byte = 1` is E0100 at `:`, and that `fn f(t: Text) io { }` is E0100 at `Text`. Target under 150 lines.

### Checker (blocked on RFC 0085's checker)

- [ ] 4. Reserved names (Y7). Add `Byte`, `byte` and `int` to the names that F6 and B5 reject (E0300 at the new name). Reject `Byte` used as a value (E0301). Tests first, as conformance tests with `kind: compile-error`: `bytes-err-top-name` (`fn byte(n: Int): Int { ret n }` and `fn main() io { }`, E0300 at line 1), `bytes-err-local-name` (`fn main() io { let int = 1 }`, E0300 at line 1), and `bytes-err-value` (`fn main() io { put(Byte) }`, E0301 at line 1). Add E0300 and E0301 to `spec/errors.json` if no earlier PR did. Target under 200 lines.
- [ ] 5. Call typing for `byte` and `int` (Y5, Y6). The checker resolves a call to `byte` or `int` through `builtins.ts` (subtask 2). The argument must match exactly (E6), else E0200 at the argument. Tests first: `bytes-err-int-arg` (`fn main() io { put(int(1)) }`, E0200 at line 1), `bytes-err-byte-arg` (`fn main() io { put(int(byte(byte(1)))) }`, E0200 at line 1), and `bytes-err-put` (`fn main() io { put(byte(1)) }`, E0200 at line 1). Add E0200 to `spec/errors.json` if absent. Depends on 2 and 4. Target under 250 lines.
- [ ] 6. Operators reject `Byte` (Y4). Under RFC 0085 E3 and E9, every operator in Y4 gives E0200 at the operator when an operand is `Byte`. This covers unary `-` too. Tests first: `bytes-err-add` (`let a = byte(1) + byte(2)`), `bytes-err-eq` (`if byte(1) == byte(1) { }`), and `bytes-err-order` (`if byte(1) < byte(2) { }`), each E0200 at the operator, with its `fn main() io { }` wrapper as RFC 0086 gives it. Depends on 5. Target under 200 lines.
- [ ] 7. Byte flows (Y10). Bindings (B1), assignment to a `var` (B2), argument passing (E6), and return (F4) accept `Byte`. Tests first: `bytes-err-arg` (`fn f(b: Byte) io { }` and `fn main() io { f(1) }`, E0200 at the `1`), and a node test `checker-byte-flow.test.ts` (new) that accepts a `Byte` binding, an assignment to a `var` and a pass to a function. Depends on 3 and 6. Target under 200 lines.
- [ ] 8. Fail mark (Y9). Extend F7 of RFC 0085 so that a call to `byte` makes a body trapping and a call to `int` does not. Tests first: `bytes-err-fail-mark` (`fn main() io { put(int(byte(1))) }`, E0403 at line 1). Also add `bytes-err-extra-fail` (new, not in RFC 0086's table): `fn g(b: Byte): Int fail { ret int(b) }` and `fn main() io fail { put(g(byte(1))) }`, E0403 at line 1 (the extra mark is on `g`). Add E0403 to `spec/errors.json` if absent. Depends on 5. Target under 150 lines.

### Codegen (blocked on RFC 0085's codegen)

- [ ] 9. Codegen for `byte` and `int` (Y5, Y8). `byte(n)` evaluates `n` as i64, calls the trap function with kind 4 when `n` is below 0 or above 255, and otherwise wraps to i32 with `i32WrapI64`. `int(b)` widens with `i64ExtendI32U`. Tests first, as conformance tests: `bytes-convert` (run, stdout `0`, `255`, `200`), `bytes-trap-high`, `bytes-trap-neg`, `bytes-trap-after` (stdout `1`), and `bytes-trap-in-fn` (trap tests, `expect-exit` 1, `expect-stderr` `trap: byte-out-of-range`). Programs and expected output are RFC 0086's. Depends on 1, 2, 5 and 8. Target under 250 lines.
- [ ] 10. `Byte` bindings, parameters and results (Y1, Y10). A `let` or `var` of type `Byte` is one i32 local. Parameters and results are i32, following RFC 0085's function codegen. Tests first, as run tests: `bytes-bind` (stdout `65`), `bytes-param-result` (stdout `7`), `bytes-order-via-int` (stdout `1`), and `bytes-int-no-fail` (new, not in RFC 0086's table: `fn g(b: Byte): Int { ret int(b) }` and `fn main() io fail { put(g(byte(1))) }`, stdout `1`). Depends on 9. Target under 200 lines.
- [ ] 11. Examples with `Byte` (Y11). Tests first: `bytes-example` (run: `fn f(): Int fail { ret int(byte(65)) } ex f() == 65` and `fn main() io fail { put(f()) }`, stdout `65`) and `bytes-err-example` (compile-error: `fn f(): Int fail { ret int(byte(256)) } ex f() == 256`, E0202 at the line of `ex`). Depends on 9 and RFC 0085's example evaluation (EX3). Target under 150 lines.
