# Plan: RFC 0004 Diagnostic style

Subtasks 1 to 8 need nothing outside RFC 0004. Subtasks 9 to 11 are BLOCKED until the conflicts below are settled and the lexer and checker from RFCs 0003 and 0005 exist. Do not start a blocked subtask; if the first unticked line is blocked, stop and report that.

## Conflicts to settle first

- Runner format. `tools/check/conformance.py` `compile-error` runs `glyphc check FILE --json`, reads `span.start` as a `[line, column]` pair, reads `fix.edits` as a list, and compares only (code, line). RFC 0004 has no `--json` flag (JSON Lines is the only format), `span.start` is a byte offset integer, `fix` is one object `{span, replacement}`, and the tests compare code, span and fix. The runner cannot check RFC 0004 as written. Only the architect can change `tools/`.
- Test kinds. RFC 0004 uses a `check` kind for `diag/catalogue` and `diag/retired`. `TEST_KINDS` in the runner is `run, compile-error, trap, fmt, fix`.
- Trap wording and exit status. RFC 0004 §5 and `diag/trap-line` say `trap: divide-by-zero` and exit 1. RFC 0005 (rejected) says `trap: divide by zero` and exit 3. `gates.py` treats a trap as exit 1. Pick one.
- Code blocks. RFC 0005 puts effect and duplicate-name errors (E0105, E0108) inside the syntax block, where RFC 0004 §4 would put effects in E0400 and names in E0300. This RFC does not fix it; whoever revives RFC 0005 must re-block its codes.
- Missing tree. `compiler/stage0/src/` and `spec/` do not exist in this checkout, although `compiler/ACTIVE` names stage0. Subtasks 1 to 8 create what they need under those paths. The spec core path (assumed `spec/core.md`) needs confirming.
