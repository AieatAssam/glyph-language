# Plan: RFC 0024 Byte type and conversions (byte-type)

RFC 0024 is accepted. It adds the value type `Byte`, the built-in functions `byte` and `int`, one trap kind (`byte-out-of-range`), three grammar productions and some reserved names. Every change extends RFC 0020, so every subtask needs the kernel from `rfcs/0020.plan.md`. This plan was checked against the checkout as it is now. Present: `compiler/stage0/src/` (`main.ts`, `cli.ts`, `codegen.ts`, `compile.ts`, `trap.ts` and their tests), `compiler/stage0/src/kernel/` (`types.ts`, `rt-trap.ts`, `rt-print.ts`, `rt-count.ts`, `arith.ts`, `parse-expr.ts` and their tests), `spec/` (`card.md`, `errors.json`, `grammar.peg`, `VERSION`, `core/diagnostic.md`, `core/name.md`), `conformance/kernel/print-one.test`, `toolkit/wasm-encoder.ts`, `tools/check/`, and `bin/glyphc`. Absent: `spec/core/kernel.md` (created by RFC 0020 subtask 26) and `conformance/bytes/` (created by subtasks 8 and 10 here). Also absent are the RFC 0020 modules this plan edits: `parse-decl.ts`, `scope.ts`, `types-expr.ts`, `types-stmt.ts`, `cg-expr.ts`, `cg-stmt.ts` and `cg-fn.ts`. `rfcs/0020.plan.md` names them by bare file name and creates them in its subtasks 8 to 16. ## Conflicts and decisions

- **Status.** The frontmatter says `accepted`; the body says `Status: draft`. This plan treats the RFC as accepted, as `rfcs/0020.plan.md` does.
- **Wasm representation of `Byte` (decision).** The RFC does not fix one. A `Byte` is an `i32` holding 0 to 255. `byte` range-checks its `i64` argument and then wraps with `i32WrapI64`; `int` widens with `i64ExtendI32U`. This keeps 8-bit values at their natural width. Both ops are already in the toolkit op table.
- **One existing node assertion changes (decision).** RFC 0020 subtask 1 has `types.test.ts`, which asserts that the trap strings equal RFC 0020 TR1's four kinds. Adding `byte-out-of-range` makes that assertion false. Subtask 1 updates that one assertion to the five kinds and says so in its PR body. No conformance test is edited. Node unit tests from RFC 0020 are not conformance tests, so this is the one permitted edit to an existing test.
- **Name suppression (decision).** RFC 0024 expects exactly one record for `print(Byte)` (E0301). RFC 0020 does not say what happens to a use the scope checker has already rejected. This plan decides that a name rejected by scope has no type, and the type checker reports nothing for it. Subtask 3 implements this, and the tests in subtask 10 rely on it.
- **Compile-error tests need a `main` (decision).** RFC 0024 gives some compile-error snippets without `main`. RFC 0020 M1 then adds E0302, which the test's record list does not expect. A compile-error test takes one of two forms:
  - A statement-only snippet has its statements wrapped in `fn main() io { }`. This is the same rule the RFC's test plan uses for run tests (RFC 0024 line 109).
  - A snippet that declares top-level `fn`s is never wrapped. Its top-level `fn` declarations stay at top level, unwrapped, and `fn main() io { }` is appended after them. RFC 0020 G5 makes a `fn` inside a block E0100 at `fn`, so wrapping a top-level `fn` would make the test fail for the wrong reason. The affected tests are `bytes/err-top-name`, `bytes/err-param-type` and `bytes/err-return-type`.
  - The wrap is never applied to a top-level `fn`. A snippet that already defines `main` gets no wrap and no appended `main`.
- **Two tests added beyond the RFC's list.** RFC 0024 Y8 says a `Byte` follows the argument and return rules of RFC 0020 (E8, F4), but its test plan has no compile-error test for either. This plan adds `bytes/err-param-type` (`f(byte(1))` where the parameter is `Int`, E0200 at the argument) and `bytes/err-return-type` (`return byte(1)` in a function returning `Int`, E0200 at `byte(1)`). No rule changes.
- **Compile-error test format.** The runner checks code and line only (see `rfcs/0020.plan.md`, Conflicts). Subtask 10 writes tests in that format. RFC 0004 section 7 wants code and span; that check follows when the runner changes.
- **Example rule (Y8) adds no checker rule.** Y8 says a `Byte` may appear in an example only as an operand of `int` or `byte`, or as a call argument. Y4, Y5a and RFC 0020 E3 already reject every other use. Subtask 9 tests this.
- **`byte(256)` compiles (Y10).** RFC 0020 E9 means the checker folds nothing outside examples, so this needs no change. Subtask 9 tests it.
- **Builtin address form (Y12).** `builtin::byte` and `builtin::int` are a second address form beside RFC 0020 A1's `<file>::<name>`. Subtask 4 defines them as constants. Nothing else reads them yet.
- **No new diagnostic codes.** Every code the RFC uses (E0100, E0200, E0202, E0300, E0301) is already emitted by the RFC 0020 plan. No `spec/errors.json` entry is added here.

## Subtasks

Write each subtask's tests first. Each subtask changes under 400 lines and touches one stage where it can. Node tests go in `compiler/stage0/src/kernel/*.test.ts`, so the gate's `node --test 'compiler/stage0/**/*.test.ts'` runs them. Conformance tests are new files under `conformance/bytes/`. Never edit an existing conformance test. No dependency is added.

- [ ] 1. Value type and trap kind (Y1, Y9). In `compiler/stage0/src/kernel/types.ts`, add `Byte` to the value types and `byte-out-of-range` to the trap kinds, with trap text `trap: byte-out-of-range`. In `rt-trap.ts` (RFC 0020 subtask 2), add the fifth kind as a data segment with index 4. Tests: `types-byte.test.ts` (new) checks the kind's text and that `Byte` is a value type; `rt-trap-byte.test.ts` (new) calls `trap(4)` from a harness and expects stderr `trap: byte-out-of-range`, exit 1, and empty stdout. Also update the one assertion in `types.test.ts` (see Conflicts): the `deepEqual` on `TRAP_KINDS` in the test named `there are exactly four trap kinds, in TR1 order` (line 21). Its expected list gains `byte-out-of-range` at index 4, and the test name changes to match. The other `types.test.ts` tests check individual lines and keep passing. This subtask touches types and runtime, so the PR body says why. Depends on RFC 0020 subtasks 1 and 2. Target under 150 lines.

- [ ] 2. Type productions (Y1, Y2, Y3). In `parse-decl.ts` (RFC 0020 subtask 8), add `"Byte"` to `type`, `ptype` and `rtype`. `Text` in `ptype` and `rtype` stays E0100 (T6). A `Byte` has no literal form (Y3), so the parser gives no `Byte` literal production. Test `parse-byte.test.ts` (new): `let b: Byte = e` parses; `fn f(b: Byte): Byte { }` parses; `fn f(t: Text) io { }` and `fn f(): Text { }` are E0100 at `Text`. Depends on RFC 0020 subtask 8. Target under 150 lines.

- [ ] 3. Reserved names and value use (Y6, Y7). In `scope.ts` (RFC 0020 subtask 9), add `Byte`, `byte` and `int` to the names that F6 and B5 reject (E0300, for function, parameter and binding names). Add `Byte` to the names that T7 and F6 reject as values (E0301). Apply the suppression rule in Conflicts: a rejected name has no type. Test `scope-byte.test.ts` (new): `fn byte(n: Int): Int { return n }`, `fn int`, `fn Byte`, `let int = 1` and a parameter named `byte` each give E0300 at the name; `print(Byte)` and `let b = Byte` give E0301 at `Byte`, with no second record. Depends on RFC 0020 subtask 9 and subtask 2. Target under 150 lines.

- [ ] 4. Built-in signatures and call typing (Y5, Y5a, Y12). New file `compiler/stage0/src/kernel/builtins.ts`: a table with `byte: (Int) => Byte` and `int: (Byte) => Int`, both pure with no effect marker, and the stable addresses `builtin::byte` and `builtin::int`. Scope resolves a call to one of these names through the table, not as an unknown name. The argument type must match exactly (E8, E0200), so `int(1)`, `byte(b)` with `b: Byte`, and `byte(byte(1))` are E0200. Test `builtins.test.ts` (new): the table and the two addresses; each E0200 case, with the span at the argument; `int(byte(1))` and `byte(65)` pass; a call to `byte` inside a function without `io` passes (the built-ins are pure). Depends on RFC 0020 subtasks 9 and 11, and on subtask 3. Target under 250 lines.

- [ ] 5. Byte in operators and in value positions (Y4, Y8, Y8a). In `types-expr.ts` (RFC 0020 subtask 10), every operator rejects a `Byte` operand with E0200 at the operator: `+ - * / %`, unary `-`, `== !=`, `< <= > >=`, and `and or not`. In `types-stmt.ts` (RFC 0020 subtask 11), `print` rejects a `Byte` argument (P1), and `if` and `while` reject a `Byte` condition (E7). Binding (B1), assignment to a `var` (B2), passing as an argument (E8), return (F4), and parameter and result types accept `Byte`. Test `types-byte.test.ts` (new): `byte(1) + byte(2)`, `byte(1) == byte(1)`, `byte(1) < byte(2)`, `-byte(1)`, `print(byte(1))`, `let b: Byte = 1` and `if byte(1) { }` each give E0200; `let b: Byte = byte(65)`, `var c = byte(66)`, `c = b`, and a call that passes and returns a `Byte` all check. Depends on subtasks 2 and 4, and RFC 0020 subtasks 10 and 11. Target under 300 lines.

- [ ] 6. Codegen for `byte` and `int` (Y5, Y9, Y10). In `cg-expr.ts` (RFC 0020 subtask 14): `byte(n)` evaluates `n` as `i64`, checks `0 <= n <= 255`, calls `rt.trap(4)` if the check fails, and otherwise wraps to `i32` with `i32WrapI64`. `int(b)` extends the `i32` to `i64` unsigned with `i64ExtendI32U`. The argument is evaluated before the check (E10). Test `cg-byte-expr.test.ts` (new): `int(byte(0))` is 0; `int(byte(255))` is 255; `byte(256)` and `byte(-1)` each trap `byte-out-of-range` with exit 1 and empty stdout; `print(f())` runs `f` before the check when `f` prints. Depends on subtasks 1 and 4 and RFC 0020 subtask 14. Target under 200 lines.

- [ ] 7. Codegen for `Byte` bindings, parameters and results (Y1, Y8). In `cg-stmt.ts` (RFC 0020 subtask 15), a `let` or `var` of type `Byte` is one `i32` local, and assignment copies it. In `cg-fn.ts` (RFC 0020 subtask 16), `Byte` parameters and results are `i32`. The PR touches two codegen files, both in the codegen stage. Test `cg-byte-bind.test.ts` (new): `id(b: Byte): Byte { return b }` with `print(int(id(byte(7))))` prints `7`; `let b: Byte = byte(65)` then `var c = byte(66)`, `c = b`, `print(int(c))` prints `65`. Depends on subtask 6 and RFC 0020 subtasks 15 and 16. Target under 200 lines.

- [ ] 10. Compile-error conformance tests (`conformance/bytes/`). Add the eleven compile-error tests in RFC 0024's test plan, plus the two added in Conflicts (`err-param-type`, `err-return-type`). Two rules decide the form of each snippet:
