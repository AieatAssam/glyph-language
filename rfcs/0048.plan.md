# Plan: RFC 0048 Lexical structure and core syntax (lexical-syntax-v4)

RFC 0048 is accepted (frontmatter). It replaces the lexical rules of RFC 0014 and the statement and layout rules of RFC 0020. Most of the lexer is already built to RFC 0014 (subtasks 1 to 10 of `rfcs/0014.plan.md` are ticked), and `kernel/parse-expr.ts` is built to RFC 0020 (subtask 6 of `rfcs/0020.plan.md`). This plan changes that code. The lexer and parser work, and the compile-error tests that need only the parser, can be built and tested now. Run tests, the grammar file and the checker are blocked on an accepted kernel (see Conflicts 1).

## Current state in this checkout

- `compiler/stage0/src/lexer/` is built to RFC 0014. It still has a `NEWLINE` kind (`token.ts`), the keywords `while`, `return` and `example`, no `;` token (`punct.ts` has 18 tokens), CR LF as one line end (`source.ts`, `trivia.ts`, `text.ts`), and the NEWLINE stage (`newline.ts`).
- `compiler/stage0/src/kernel/` has `parse-expr.ts`, `arith.ts`, `types.ts` and the `rt-*` files. `parse-stmt.ts` and `parse-decl.ts` do not exist.
- `compiler/stage0/src/parser/parse.ts` is the walking-skeleton parser for `fn NAME ( ) io { NAME ( INT ) }`. It skips NEWLINE. `compile.ts`, `codegen.ts` and `parser/parse.test.ts` import it.
- `spec/grammar.peg` is the skeleton grammar, with `print` and single-line spacing.
- `spec/core/` holds `diagnostic.md` and `name.md`. There is no `lexical.md`. `spec/card.md` exists.
- `conformance/` holds only `kernel/print-one.test`.
- `spec/errors.json` has E0001, E0005, E0006, E0010, E0100 and E0500. E0003 is missing.
- `tools/check/conformance.py`: a `compile-error` test may give `expect-errors` as a JSON object. The object's `code`, `span` and `fix` are compared where the object gives them. So the RFC 0048 test plan can be written in full, with spans.

## Conflicts and decisions

1. **Kernel.** RFC 0048 says its meaning is defined by kernel-v9 (RFC 0049), and its run tests use `put`. RFC 0049 is rejected. Decision: write no run test, no checker and no `spec/grammar.peg` change until an accepted kernel exists. Syntax-only tests are not blocked, because the parser rejects those programs before any meaning is needed. Architect: accept a kernel that uses `put`, `wh`, `ret` and `ex`.
2. **Existing conformance test.** `conformance/kernel/print-one.test` (RFC 0020) uses `print(1)`. Under RFC 0048, `print` is an ordinary name, so the test cannot pass once a checker runs. Decision: do not edit it (base rule: no edits to existing conformance tests). Architect: retire it by owner decision.
3. **E0500 owner.** RFC 0048 rule 8 puts E0500 in the checker. `kernel/parse-expr.ts:167` emits it in the parser, per `rfcs/0020.plan.md` subtask 6. Decision: subtask 8 removes it from the parser. The E0500 tests wait for the checker (subtask 19).
4. **E0003 position and block** (RFC 0048 open questions 4 and 5). Decision: follow RFC 0048. E0003 is reported at the keyword in a name position (G3), by the parser. Its catalogue entry is added by subtask 10, the first emitter. Whether it sits in the lexical or the syntax block is for the architect; this plan does not move it.
5. **Leading zero** (RFC 0048 open question 7). RFC 0048 gives E0006. RFC 0004's `diag/fix-present` expects E0001. `lexer/int.ts` already emits E0006. Decision: follow RFC 0048. Architect: settle RFC 0004.
6. **Node tests.** `lexer/*.test.ts` and `parser/parse.test.ts` encode the superseded rules (CR LF valid, NEWLINE, `while`, `return`, `example`). They are node unit tests, not conformance tests, so this plan edits and deletes them. Each deletion is preceded by reading the file. No conformance test in this plan is edited. Ticked lines in `rfcs/0014.plan.md` and `rfcs/0020.plan.md` stay ticked as history. This plan supersedes them where they conflict.
7. **RFC 0014 compile-error tests.** `rfcs/0014.plan.md` subtask 13 was blocked on the runner format. The runner now has the JSON form (above), so the lexer compile-error tests that RFC 0048 keeps are unblocked (subtask 16). Not written, because they test retired rules: `lex/punct-semicolon` (`;` is now a token), `lex/ws-crlf` (CR is now E0001), `lex/kw-while`, `lex/kw-return`, `lex/kw-example` (renamed keywords), and `lex/newline-in-group` and `lex/newline-blank` (NEWLINE is gone). The RFC 0014 run tests that name `print` are written with `put`, as RFC 0048 says the kernel's test programs do. Their names and expected output stay the same.
8. **Layout** (RFC 0048 open question 2). The compiler checks no layout. No subtask.
9. **Lexer error order.** Rule 13 (one lexical error, no tokens after it) matches the existing design in `lexer/index.ts`: the byte check runs first and the scan stops at its offset. No change.
10. **Gate.** The gate's grammar rule (rule 10 in `tools/check/run.py`) counts only accepting-kind tests. Syntax-only compile-error tests do not cover productions. So `spec/grammar.peg` (subtask 18) waits for run tests.
