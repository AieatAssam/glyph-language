# Plan: RFC 0035 Text length, byte access and equality (text-query)

RFC 0035 is accepted. It adds two total built-ins, `text_len` and `text_byte`, and `==` and `!=` on two `Text` operands. It amends RFC 0020 T3 (where `Text` may appear), E3 (equality operand types) and F6 (reserved names). It adds no grammar production, no trap kind and no diagnostic code.

## Prerequisites outside this plan

RFC 0020's kernel plan (`rfcs/0020.plan.md`) is the base this plan changes. Subtasks 1 to 6 there are ticked. The checker and codegen files this plan edits do not exist yet:

- `kernel/scope.ts` (RFC 0020 subtask 9), `kernel/types-expr.ts` (subtask 10), `kernel/types-stmt.ts` (subtask 11), `kernel/cg-expr.ts` (subtask 14), `kernel/cg-stmt.ts` (subtask 15), `kernel/cg-fn.ts` (subtask 16), `kernel/build.ts` and the CLI (subtasks 17 and 18), `spec/core/kernel.md` (subtask 26).
- Subtask 3 below needs those files, so it waits for them. Subtasks 1, 2 and 6 need only what exists now.
- `compiler/stage0/src/lexer/text.ts` already implements TX1. It emits E0005 for any backslash sequence other than `\n`, `\"` and `\\`, and E0001 for a control character. Subtask 2 is therefore tests only.
- The toolkit has every encoder op this plan uses: `i32Load8U`, `i32Eq`, `i32Eqz`, `i32LtS`, `i32GeS`, `i64LtS`, `i64GeS`, `i32WrapI64`, `i64ExtendI32U`, and `addData`. No change to `toolkit/` is needed. Do not edit it.
- Run tests need the CLI from RFC 0020 subtask 18 (`check --json` for compile-error tests). Until it lands, the gate fails for reasons outside this plan. Say so in the PR body.

## Conflicts and decisions

- Equality test prints a Bool. RFC 0035's test plan gives `print("ab" == "ab")` prints `true`. RFC 0020 P1 says `print` takes exactly one `Int` or `Text`, and `print(true)` is E0200. So that test cannot compile. Decision: write `text/equal.test` with `if` and print `1` or `0`. The architect should amend RFC 0035's test plan. This is a new test, so no existing test is edited.
- RFC 0020 plan may contradict TX6. Its subtask 24 lists `err-text-op` and its subtask 10 says `"a" == "b"` is E0200. Decision: subtask 3 changes that unit assertion in `types-expr.test.ts`, which is a unit test, not a conformance test, and says so in the PR body. Before RFC 0020 subtask 24 is written, the architect should make sure `err-text-op` does not use `Text ==` as its error case (use `+` or `<` instead). Nothing here edits an existing conformance test.
- Mixed-type `==` code (TX8). RFC 0035 leaves the code to issue #31. Decision: emit E0200, the mismatch code RFC 0020 already uses, and mark it provisional in code and the PR body. Add a unit test only, not a conformance test, until #31 closes. If #31 picks a different code, it changes in one place.
- Ordering of `Text` and RFC 0037. RFC 0037 (accepted) supersedes TX7 for `<`: under its OR1 and OR2, `<` on two `Text` operands is a `Bool` comparison. `<=`, `>` and `>=` stay E0200 on `Text` under its OR4, so TX7 still holds for them. This plan implements TX7 as written, so `<` on `Text` gives E0200 here until RFC 0037's subtasks land, and that change belongs to RFC 0037's plan, not this one. No test in this plan uses `<` on `Text`. The ordering test in subtask 8 uses `<=`, which stays E0200 in both RFCs, so it does not break when RFC 0037 lands. No existing conformance test is edited.
- Reserved names for bindings. RFC 0035 says `text_len` and `text_byte` are reserved under F6, but is silent on `let text_len = 1`. Decision: reject it with E0300, as RFC 0020 B1 does for function names. The architect should confirm.
- Equality is not counted by TR3. The `Text` equality loop is bounded by the byte length, not by a user `while`, so it does not call `tick`. Only user `while` iterations count toward the step limit.
- Built-in table. `text_len`, `text_byte`, `print` and the type names all need one reserved list and one signature table. Subtask 1 creates it; the scope, type and codegen files read it. This avoids the duplicated name lists the constitution's "one way" principle rules out.
- Roadmap. RFC 0035 open question 1 says `ROADMAP.md` forbids a new RFC before the first compiler merges onto `main`. `ROADMAP.md` is not in this checkout, so this plan cannot confirm it. The orchestrator should decide. This plan is written as requested.

## Subtasks

- [ ] 1. Add `compiler/stage0/src/kernel/builtins.ts`. It exports `BUILTINS`, with `text_len: (Text) -> Int` and `text_byte: (Text, Int) -> Int`, both with no effects (TX2), and `RESERVED_NAMES`, which is `print`, `Int`, `Bool`, `Text`, `text_len` and `text_byte` (TX5). Test `builtins.test.ts`: the two signatures match TX2 exactly; the reserved list has the six names; no effect flag is set. No dependencies beyond `kernel/types.ts`. Under 100 lines.

- [ ] 2. Literal tests (TX1). Add `conformance/text/tab-escape.test` (compile-error, `print("\t")`, E0005 at the backslash) and `conformance/text/bad-escape.test` (compile-error, `print("\q")`, E0005). Write them in the runner's `expect-errors` form, with `id`, `rfc: 0035` and `kind` in the `--- meta` block. The lexer already gives these codes, so if a test fails, the cause is in `lexer/text.ts`. Fix it there with a test, and say so in the PR body. Depends on RFC 0020 subtask 18 for `check --json`. Under 80 lines.

- [ ] 3. Equality types (TX6, TX7, TX8). Change `kernel/types-expr.ts` (RFC 0020 subtask 10) so `==` and `!=` accept two `Text` operands and return `Bool`. `<`, `<=`, `>` and `>=` on `Text` give E0200 at the operand (TX7; `<` is superseded by RFC 0037 OR1, see Conflicts). A mixed `==` gives E0200 at the operand (TX8, provisional). Update the one assertion in `types-expr.test.ts` that says `"a" == "b"` is E0200 (see Conflicts). Add `types-text-eq.test.ts`: `"a" == "b"` passes; `"a" != "b"` passes; `"a" <= "b"` is E0200; `"a" == 1` is E0200; `1 != "a"` is E0200. Depends on RFC 0020 subtasks 9 and 10. Under 200 lines.

- [ ] 4. Built-in calls (TX2, TX3, TX5). Change `kernel/types-stmt.ts` (RFC 0020 subtask 11) so a call to `text_len` or `text_byte` is checked against `BUILTINS`. Wrong arity or argument type gives E0200 at the argument. The result type is `Int`. Using a built-in name as a value gives E0301 (F6, as for user functions). A user function, parameter, `let` or `var` named `text_len` or `text_byte` gives E0300 (from `scope.ts`, RFC 0020 subtask 9, reading `RESERVED_NAMES`). Add `types-builtins.test.ts`: `text_len("a")` passes; `text_len(1)` is E0200; `text_byte("a")` is E0200; `text_byte("a", "b")` is E0200; `let f = text_len` is E0301; `fn text_len() { }` is E0300; `let text_byte = 1` is E0300. Depends on subtask 1 and RFC 0020 subtasks 9 and 11. Under 300 lines.

- [ ] 5. Where Text may appear (TX9, TX10). Change the T3 rule in `kernel/types-expr.ts` to the TX9 list: `let` or `var` initialiser or assignment, `print` argument, operand of `==` or `!=`, and first argument of `text_len` or `text_byte`. Any other `Text` position is E0200 at the expression, as T3 gives today. TX10 is unchanged, so a `Text` parameter or result stays E0100 from RFC 0020 subtask 8. Add `types-text-place.test.ts`: `text_byte(t, 0)` with `var t = "hi"` passes; `text_byte("a", 0) + 1` is E0200; `let n: Int = "a"` is E0200; `print(text_len("a") == "b")` is E0200 (Int against Text, TX8). Depends on subtask 3 and RFC 0020 subtask 11. Under 200 lines.

- [ ] 6. Runtime helpers (TX2, TX6). Add `compiler/stage0/src/kernel/rt-text-query.ts`: `addTextRuntime(m)` defines three functions in the module builder. `text_len(p: i32, l: i32) -> i64` returns `l` extended to `i64`. `text_byte(p: i32, l: i32, i: i64) -> i64` checks the range on the `i64` value first: if `i < 0` or `i >= extend(l)`, it returns `-1`; otherwise it loads `i32Load8U` at `p + wrap(i)` and extends it. The range check must come before the wrap, so an index of 2^32 gives `-1`, not byte 0. `text_eq(p1, l1, p2, l2) -> i32` returns 0 when the lengths differ, and otherwise loops over the bytes and returns 0 or 1. The file is named `rt-text-query.ts` so it does not collide with the text-order runtime file in RFC 0037's PR. Test `rt-text-query.test.ts` with a harness module that places bytes with `addData` and runs through `run()`: `text_len("")` is 0; `text_byte("hi", 1)` is 105; index 2, index -1, index 4294967296 and index 4294967297 each give -1; `text_eq("ab", "ab")` is 1, `("ab", "abc")` is 0, `("", "")` is 1, and `("a", "b")` is 0. Depends on the toolkit only. Under 250 lines.

- [ ] 7. Codegen (TX2, TX6, TX9). Change `kernel/cg-expr.ts` (RFC 0020 subtask 14) so: each `Text` operand is pushed as a pointer and a length, from a literal or a `Text` local pair (RFC 0020 subtask 15). `text_len` and `text_byte` evaluate their arguments left to right, then call the subtask 6 helpers from `rt-text-query.ts`. `==` pushes both pairs left to right and calls `text_eq`; `!=` calls it and then `i32Eqz`. Test `cg-text.test.ts`: a harness returns `text_byte("hello", 1)` as 101; `text_len("hello")` as 5; `"ab" != "abc"` as 1; a `var` pair `text_byte(t, 0)` as 104; and an argument-order case prints in order. Depends on subtasks 3, 4, 5 and 6, and RFC 0020 subtasks 14 and 15. Under 250 lines.

- [ ] 8. Run conformance (TX1 to TX9). Add these new files under `conformance/text/`, each with its `--- meta` block:
  - `len.test` (run): `print(text_len("hello"))` gives `5`; `print(text_len(""))` gives `0`.
  - `byte.test` (run): `print(text_byte("hello", 1))` gives `101`.
  - `byte-range.test` (run): `print(text_byte("hi", 2))` gives `-1`; `print(text_byte("hi", -1))` gives `-1`.
  - `equal.test` (run): `if "ab" == "ab" { print(1) }` and `if "ab" != "abc" { print(1) }`, output `1` and `1`. Do not print a Bool (see Conflicts).
  - `escapes.test` (run): `print(text_len("\n"))`, `print(text_len("\""))` and `print(text_len("\\"))` each give `1`.
  - `var.test` (run): `var t = "hi"` then `print(text_byte(t, 0))` gives `104`.
  - `builtin-name.test` (compile-error): `fn text_len() { }` gives E0300.
  - `cmp-text.test` (compile-error): `if "a" <= "b" { }` gives E0200. This uses `<=`, not `<`, because RFC 0037 OR1 makes `<` on two `Text` operands a `Bool` comparison. `<=` stays E0200 under RFC 0037 OR4, so this test stays true after RFC 0037 lands, and it is never edited.
  Every test is in `fn main() io { }` unless it defines `main`. Use `expect-stdout` and `expect-exit` for run tests, and `expect-errors` for compile-error tests. Depends on subtasks 2, 4, 5 and 7, and RFC 0020 subtasks 18 and 20. Under 300 lines.

- [ ] 9. Spec and card. Amend `spec/core/kernel.md` (RFC 0020 subtask 26): replace the T3 sentence with the TX9 list, add the Text case to E3, add the two built-in names to F6, and add TX2 (the table) and TX1 (a note that the escapes are as RFC 0014 defines them). Add two lines to `spec/card.md`: the two signatures, and "`text_byte` gives `-1` out of range". There is no trap line, because nothing here traps. The grammar gets no change, because no production is added; gate rule 10 still needs each existing production to be hit by a test, and this plan adds none. Run `tools/check/tokens.py`; the core must stay at or below 12,000 tokens and the card at or below 2,000. Depends on subtask 8 and RFC 0020 subtask 26. Under 150 lines.
