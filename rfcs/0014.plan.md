# Plan: RFC 0014 Lexical structure and core syntax

RFC 0014 is accepted. Subtasks 1 to 12 can be built and tested with node tests, using the RFC 0004 record and catalogue and the RFC 0011 CLI. No accepted RFC defines a kernel, so no run test can pass yet, and subtasks 13 to 15 are blocked (see below).

## Prerequisites outside this plan

- RFC 0004 (accepted, not implemented). Subtasks 10 and 12 need `spec/errors.json`, `compiler/stage0/src/diagnostic.ts` (record and `toJsonLine`), `span.ts` (byte offset to line and column) and `message.ts`. They come from `rfcs/0004.plan.md` subtasks 1, 2, 4, 5 and 8. If a file is missing when you reach the subtask, stop there and report it. Do not create a stand-in.
- RFC 0011 (accepted). `bin/glyphc` runs `compiler/stage0/src/main.ts`, which does not exist yet. Subtask 11 needs `cli.ts` and the source-file rule from `rfcs/0011.plan.md` subtasks 3 and 4.
- Spec layout. `tools/check/tokens.py` counts `spec/core/**/*.md` and `spec/card.md`. `spec/` does not exist in this checkout. This plan adds `spec/core/lexical.md`. The card lines go into `spec/card.md`, which RFC 0004 subtask 8 creates.
- Gate baseline. Rule 4 of `tools/check/run.py` needs `bin/glyphc --version` to work, and rule 10 needs `spec/grammar.peg`. Until the prerequisites land, the gate fails for reasons outside this plan. Say so in the PR body; do not work around it.

## Conflicts and decisions

- Kernel. RFC 0014 takes its parser contract from RFC 0013 (kernel-v2). RFC 0013 is rejected, and so are RFC 0005 and RFC 0015 (kernel-v3). No accepted RFC defines `fn`, `let`, a call, `print` or `main`. Consequence: every run test (subtask 14) is blocked, and so are the parser and checker codes E0003, E0100 and E0500 (subtask 15).
- Runner format (`tools/check/conformance.py`). (a) The `compile-error` kind passes `--json` and compares only `(code, line)`. RFC 0004 removed `--json` and uses byte-offset spans. RFC 0014 section 7 wants code, span and fix compared. (b) Each `.test` holds one `source`, so RFC 0014's multi-file tests (`tab`, `punct-bracket`, `text-bad-escape`, `int-too-big`) have to be split into one file per case. (c) Only the architect can change `tools/`. This is the same conflict as `rfcs/0004.plan.md` and `rfcs/0011.plan.md`.
- Grammar file. Rule 10 of `tools/check/run.py` requires every production in `spec/grammar.peg` to be hit by a test of an accepting kind. The lexical rules in RFC 0014 are not written as PEG productions in this plan. They live in spec prose and in node tests. If the architect wants them in the PEG, their run tests must exist first.
- Order of errors (rule 16, "first lexical error"). This plan takes "first" to mean the smallest start offset. The whole-file byte check (subtask 1) and the token scanners run separately, so the driver (subtask 9) must merge their errors by offset. It must not return whichever check ran first.
- Lexer result on error. This plan returns the error and no tokens. Rule 16 can be read either way; the caller only sees the record.
- Open questions in the RFC. Question 2 (CR LF) and question 3 (where E0003 sits) are not settled. This plan follows the RFC as written: CR LF is one line end, and E0003 stays in the lexical block. Reopen both before subtask 15.
- Status. The RFC body says "Status: draft" and the frontmatter says `accepted`. This plan treats it as accepted.

## Subtasks

Write each subtask's tests first. Each subtask changes one lexer stage, and each stays under 400 changed lines. Node tests live in `compiler/stage0/src/lexer/*.test.ts`, so the existing `node --test 'compiler/stage0/**/*.test.ts'` gate runs them.

- [x] 1. Add `compiler/stage0/src/lexer/source.ts` exporting `checkBytes(buf: Buffer): LexError | null`, and the type `LexError = {code, start, end}`. It checks only the context-free rules: invalid UTF-8 (E0001 at the first invalid byte); U+FEFF anywhere (E0001); control characters U+0000 to U+001F and U+007F, except LF and the CR of a CR LF pair (E0001 at that character, which includes tab and a lone CR). Test `source.test.ts`: each case above, a valid CR LF file passes, and a tab inside what would be a comment or a text literal is also an error. Target under 200 lines.

- [x] 2. Add `compiler/stage0/src/lexer/token.ts`: the `Kind` enum with the 14 keyword kinds, the 18 punctuation kinds, and `IDENT`, `INT`, `TEXT`, `NEWLINE`, `EOF`; the `Token` type `{kind, start, end, text?}`; the keyword spelling table and the punctuation spelling table. Test `token.test.ts`: the keywords equal the RFC's list in order; the punctuation spellings equal the 18 tokens; every kind value is unique (rule 12). Target under 150 lines.

- [x] 3. Add `compiler/stage0/src/lexer/trivia.ts`: `skipTrivia(buf, pos)` consumes spaces, LF, and CR LF as one line end, and `//` comments up to but not including the next line end. It returns the new position and the line-end spans it passed, for subtask 8. It does not consume a tab, since subtask 1 has already rejected it. Test `trivia.test.ts`: CR LF is one span of two bytes; a comment ends before its LF; a comment ends before the CR of a CR LF; `"` inside a comment is ignored; a line end at end of file. Depends on subtask 2.

- [x] 4. Add `compiler/stage0/src/lexer/ident.ts`: `lexWord(buf, pos)` reads an ASCII letter or `_`, then ASCII letters, digits or `_`. A lowercase keyword word gives its keyword kind; anything else is `IDENT`. A byte of 0x80 or more at a token start is E0001 at that character, decoded as one scalar. Test `ident.test.ts`: `_a`, `Count2`, `x_9`, `Int`, `Bool`, `Text`, `print` and `main` are `IDENT`; `Fn` and `IO` are `IDENT`; `io` is the `io` keyword; `é` at a token start is E0001 with the span of that character. Depends on subtask 2.

- [ ] 5. Add `compiler/stage0/src/lexer/int.ts`: `lexInt(buf, pos)` reads `0`, or a digit from 1 to 9 and digits. It records the digits as written. A digit sequence that starts with 0 and has more than one digit is E0006 at the literal's span. It does no range check; that belongs to the checker (E0500). Test `int.test.ts`: `0`, `12`, `9223372036854775807` and `9223372036854775808` are `INT` with no error; `007` and `00` are E0006 with the full span. Depends on subtask 2.

- [ ] 6. Add `compiler/stage0/src/lexer/text.ts`: `lexText(buf, pos)` reads from `"` to the next `"`. The escapes `\n`, `\"` and `\\` decode to bytes. Any other backslash sequence is E0005 at the backslash and the next character. A line end (LF, or the CR of a CR LF) or the end of file before the closing quote is E0005, with the span from the opening quote to the end of that line or file. The value is the decoded UTF-8 bytes. Test `text.test.ts`: each escape; `"a//b"` is text, not a comment; `\t` and `\q` are E0005; unterminated at LF; unterminated at end of file; a valid non-ASCII character is accepted. Depends on subtask 2.

- [ ] 7. Add `compiler/stage0/src/lexer/punct.ts`: `lexPunct(buf, pos)` takes the longest of the 18 tokens, with at most one character of lookahead. A `!` not followed by `=` is E0001 at the `!`. A printable ASCII character outside the set (`;`, `[`, `]`, `.`, `#`, `'`, `?`, `@`, `$`, `^`, `&`, `|`, `~`, backtick, and `\` outside text) is E0001 at that character. Test `punct.test.ts`: each of the 18 tokens; `==`, `!=`, `<=` and `>=` are one token each; `=>` is `=` then `>`; `->` is `-` then `>`; `let a = !true` is E0001 at `!`; each listed character is E0001. The driver (subtask 9) calls `skipTrivia` before this, so `//` never reaches it. Depends on subtask 2.

- [ ] 8. Add `compiler/stage0/src/lexer/newline.ts`: the NEWLINE and EOF rules (rules 14 and 15). Input is the token stream and the line-end spans from subtask 3. State is the parenthesis depth (`(` adds one; `)` subtracts one and stops at zero), a flag for whether any token has been emitted, and the last kind emitted. Test `newline.test.ts`: `a` line end `b` gives one NEWLINE; several blank lines give one; blank lines at the start give none; a line end inside `( )` gives none; a `)` at depth zero leaves the depth at zero; a file with no final line end still gets the final NEWLINE; a file that ends inside `(` gets no NEWLINE from that end, and the EOF token is always last. Depends on subtasks 2 and 3.

- [ ] 9. Add `compiler/stage0/src/lexer/index.ts` exporting `lex(buf: Buffer): {tokens, error}`. It runs `checkBytes` (subtask 1) first and stops the scan at its offset. Then it loops over `skipTrivia`, `lexWord`, `lexInt`, `lexText` and `lexPunct`, feeding the results to the NEWLINE stage (subtask 8). The error reported is the one with the smallest start offset (see Conflicts). On any error the result has no tokens. Test `lex.test.ts`: a valid file gives its token kinds in order, ending in EOF; an empty file gives only EOF; an E0005 at byte 10 with a tab at byte 30 reports E0005; a tab at byte 5 with an E0005 at byte 10 reports E0001; an invalid byte stops the scan. Target under 250 lines. Depends on subtasks 1 to 8.

- [ ] 10. Add `compiler/stage0/src/lexer/records.ts`: turns a `LexError` into an RFC 0004 record through `diagnostic.ts` and `toJsonLine`. The span comes from `span.ts`. Messages pass the checks in `message.ts`. Add catalogue entries to `spec/errors.json` only for E0001, E0005 and E0006, which are the codes this PR first emits (RFC 0014: a code is added by the PR that first emits it). Test `records.test.ts`: field order; no `fix` key; line and column of an error on line 3; each message passes `message.ts`; each code is in `spec/errors.json` once. Depends on subtask 9 and RFC 0004 subtasks 1, 2, 4 and 5.

- [ ] 11. In `compiler/stage0/src/cli.ts` (RFC 0011 subtask 3), `check`, `run` and `build` lex a source file after the source-file check. On a lexical error, write one record with `toJsonLine` to stderr and return 1. On success, fall through to RFC 0011's "no front end yet" result, which returns 2. Test `cli.test.ts` with fake writers: each lexical error gives exit 1 and one line; a valid file gives exit 2 with the RFC 0011 message; no stdout in either case. Depends on subtasks 9 and 10 and RFC 0011 subtasks 3 and 4.

- [ ] 12. Write the lexical section into `spec/core/lexical.md`: design rules 1 to 16 and the lexical rows of the error table (E0001, E0005, E0006); the E0003, E0100 and E0500 rows follow RFC 0014 as written. Add the card lines to `spec/card.md`: the fourteen keywords, the eighteen punctuation tokens, the token kinds, and the NEWLINE rule. Run the token counter (`tools/check/tokens.py`) and confirm the core is at most 12,000 tokens and the card at most 2,000, the limits that `governance/RULES.md` sets. The core also holds RFC 0004's diagnostic section, so the total is what counts. Prose needs no conformance test (see Conflicts). Depends on RFC 0004 subtask 8.

- [ ] 13. BLOCKED on the runner format conflict. Write the 16 compile-error tests that only the lexer can produce: `lex/bad-utf8`, `lex/bom`, `lex/cr-alone`, `lex/tab-code`, `lex/tab-comment`, `lex/tab-text`, `lex/ident-ascii`, `lex/punct-semicolon`, `lex/punct-bracket-open`, `lex/punct-bracket-close`, `lex/punct-dot`, `lex/bang-alone`, `lex/text-bad-escape-t`, `lex/text-bad-escape-q`, `lex/text-unterminated` and `lex/int-leading-zero`. Each one is a separate `.test` file under `conformance/lex/` with one `source`. Do not write them until the architect fixes the runner's format (Conflicts, first bullet). A pass under the current runner would not check span or fix, which RFC 0014 section 7 requires. Never edit an existing test.

- [ ] 14. BLOCKED on an accepted kernel with `print`. Write the 39 run tests from RFC 0014's test plan: `lex/ident-run`, `lex/int-run`, the 14 `lex/kw-<word>` tests, the 18 `lex/tok-<token>` tests, `lex/comment-line`, `lex/ws-crlf`, `lex/newline-in-group`, `lex/newline-blank` and `lex/text-escape`. Each uses `fn main`, `let` or an expression, so the parser and a kernel RFC must exist first. Once a kernel is accepted, re-plan this subtask against it. Do not write the tests against a rejected RFC.

- [ ] 15. BLOCKED on the parser (E0003, E0100) and the checker (E0500). Write `lex/ident-keyword`, `lex/ident-io`, `lex/arrow`, and the two `lex/int-too-big` tests. Before this PR, resolve RFC 0014 open question 3, because it decides which block E0003 belongs to. Add each catalogue entry in the PR that first emits it. Depends on a kernel and on a parser and checker, none of which exist.
