# Plan: RFC 0104 Lexical structure and core syntax (lexical-syntax-v6)

RFC 0104 is accepted. It replaces RFC 0048 for tokens and syntax, amends RFC 0004 (two expected results), RFC 0014 (rules 3, 5, 7, 8, 13 to 15 as restated) and RFC 0050 (the `diag/record-shape` line). Its meaning for forms is given by RFC 0105 (`kernel-v46`), which is present in `rfcs/0105-kernel-v46.md`.

Subtasks 1 to 12 need nothing outside this repo. The conformance tests that need a working `check` path are blocked (B1). Do not start a blocked subtask until its block is cleared.

## Blocked decisions and dependencies

- **B1. No front end yet (blocks conformance compile-error and run tests; not node tests).** `compiler/stage0/src/cli.ts` answers `check FILE` with `glyphc: no front end yet`, exit 2. The runner needs exit 1 and records from `check` for `compile-error` tests. The same blocker is B4 in `rfcs/0050.plan.md`. One wiring change in `main.ts`/`cli.ts` (owned by the RFC 0014 or RFC 0020 plan) clears both. Until it lands, every `v6-err-*`, `v6-fmt-*` and `v6-` run conformance test waits. The node tests in each subtask do not wait.

- **B2. Retirements turn the gate red (blocks a green gate, not the code).** `conformance/lex/v4-lf-only.test` (present) expects a line feed to be whitespace. After subtask 3 it fails, because RFC 0104 rule 4 makes a line feed E0002. Agents may not edit or delete it. The subtask 3 PR reports it red in its body and waits for the owner's `rules_changed` commit. The other retirements in RFC 0104 (`lex/punct-semicolon`, `lex/comment-line`, `lex/kw-fn`, `lex/kw-while`, `lex/kw-return`, `lex/kw-example`, `lex/text-escape`, `lex/text-unterminated`, `lex/int-leading-zero`, `lex/newline-in-group`, `lex/newline-blank`, `lex/ws-crlf`) are not in this checkout. Where a new subtask would break one that does exist, the PR says so.

- **B3. `kernel/print-one` and kernel code use `fn` and `print` (blocks nothing in the lexer; watch subtask 1).** After subtask 1, `fn`, `print`, `while`, `return` and `example` are identifiers. `conformance/kernel/print-one.test` uses `print` and `fn`. RFC 0104 says its retirement is gated by RFC 0105 (G-c). Subtask 1 must check `compiler/stage0/src/kernel/` for any keyword test on those words. If the kernel parser depends on them, do not change kernel code here; report it in the PR body and stop that part. Architect decision needed only if the kernel parser cannot run without them.

- **B4. Catalogue shape and ownership of new entries (affects subtasks 3, 5, 7, 10).** `spec/errors.json` still has a `message` key for each entry. RFC 0050 plan subtask 2 removes it. This plan adds the E0002 and E0003 entries and writes only `code` and `meaning`. If RFC 0050 subtask 2 has not landed when subtask 3 opens, write the entry with `code` and `meaning` only and say so in the PR body. The `message` key then goes in the RFC 0050 PR. This plan owns both new entries. E0002 is added by subtask 3, its first emitter. E0003 is added by subtask 10, its first emitter (the parser). No other plan adds either entry; a plan that names E0003 for `spec/errors.json` must refer to this plan's subtask 10 instead of adding a second entry.

- **B5. Changed meaning text for E0001 and E0005.** Both `meaning` strings in `spec/errors.json` describe comments and the old text rules, which RFC 0104 removes. This plan changes the `meaning` text only. It does not change any code, number or block. The basis is RFC 0050 section 4: each `meaning` is a noun phrase of at most ten words, and the current E0001 and E0005 texts are longer than that. The E0005 text also says "no closing quote before a line end", which RFC 0104 rule 9 no longer allows (a raw LF is content). Proposed texts: E0001 `invalid byte or character in source` (6 words); E0005 `malformed text literal: unknown escape or no closing quote` (9 words). Subtask 2 changes the E0001 text (comments are gone) and subtask 4 changes the E0001 and E0005 texts. Architect to confirm the text change in the PR review.

- **B6. Parser location and team split.** The parser is new. This plan creates `compiler/stage0/src/parser/`. The kernel parser in `compiler/stage0/src/kernel/parse-expr.ts` is for RFC 0105 forms and is left as it is. If a later plan wants them merged, that is a new RFC.

- **B7. E0006 fix (closes `rfcs/0050.plan.md` B3 for this grammar).** RFC 0104 rule 8 gives the fix. `007` gives replacement `7` and `00` gives `0`. This resolves the question RFC 0050 plan B3 raised for the accepted lexical rules. Subtask 5 uses it.

- **B8. Formatter for `lex/v6-fmt-canon` (kind `fmt`).** No formatter is in this checkout. Only `tools/check/conformance.py` and `run.py` know the `fmt` kind. The `fmt` test waits for a formatter. Subtask 3 gives the canonical-gap check that a formatter would need.

- **B9. Sequencing with RFC 0050 plan.** Both touch `compiler/stage0/src/lexer/records.ts`. RFC 0050 subtask 1 changes the record writer and removes `message`. Subtask 5 here adds a `fix` to E0006. Land RFC 0050 subtask 1 first, or rebase the fix onto it. Do not copy a second record writer.

## Subtasks

Write each subtask's tests first. Each changes fewer than 400 lines and touches one stage (lexer, parser, checker, spec, catalogue, tests). The PR body for any subtask touching two stages says why. Node tests live in `compiler/stage0/src/**/*.test.ts`. Conformance tests go in `conformance/lex/` (names `v6-...`) and `conformance/parse/` (new directory) with `rfc: 0104` in the meta block. Never edit an existing conformance test.

- [x] 1. Keywords, `compiler/stage0/src/lexer/token.ts` and `ident.ts`. Exactly fifteen keywords: `let var if else wh ret true false and or not ex io put fail`. Remove `fn`, `while`, `return`, `example` and `print` from the keyword list, so they lex as `IDENT`. Add token kinds for `put`, `fail`, `wh`, `ret`, `ex`. Keep `if`, `else`, `true`, `false`, `and`, `or`, `not`, `io`, `let`, `var`. Tests first in `token.test.ts` and `ident.test.ts`: each of the fifteen lexes as its own kind; `fn`, `while`, `return`, `example`, `print` lex as `IDENT`; `Int`, `Bool` lex as `IDENT`. Add `lex/kw-fail` as a node test (conformance `lex/` test waits for B1 if it is compile-error). Check `kernel/` for keyword use per B3. Target under 150 lines.

- [x] 2. Punctuation and trivia, `compiler/stage0/src/lexer/punct.ts` and `trivia.ts`. The token set is exactly the seventeen of rule 10: `( ) { } , = == != < <= > >= + - * / %`. Remove `;`, `:` and `//` comments from the lexer; `//` becomes two `/` tokens and the parser rejects them (E0100). Remove the comment trivia path. `!` not followed by `=` is E0001 (rule 11). Keep longest match with at most one character of lookahead. Tests first in `punct.test.ts`: the seventeen tokens; `=>` is `=` then `>`; `->` is `-` then `>`; `;`, `:`, `#`, `!` alone are E0001 at the character; `a//b` gives two `/` tokens. Remove or replace the `punct-semicolon` and `comment-line` node tests that assert the old behaviour only by adding new tests; do not edit conformance files. Target under 200 lines.

- [x] 3. Layout and control characters, `compiler/stage0/src/lexer/newline.ts` and a new `lexer/gap.ts`. Implements rules 2, 3, 4 and 4a/4b. Each gap between two adjacent tokens (and before the first and after the last) is checked in this order: a control character in it (U+0000 to U+001F, U+007F, including TAB and CR) is E0001 at the first such character; otherwise a gap not equal to the canonical gap is E0002 with span the gap (zero-length where a space is missing between two word tokens) and fix replacing the gap with the canonical gap (one space between two word characters, nothing otherwise). LF outside text is part of a gap and E0002. Tests first in `newline.test.ts` and a new `gap.test.ts`: `main io{` LF `put 1}` gives E0002 at bytes 8 to 9 with empty replacement; `main io{put  1}` gives E0002 at bytes 11 to 13 with replacement ` `; `main io{put 1put 2}` gives zero-length E0002 at 13; `main io{put (1)}` gives E0002 at 11 to 12; ` main io{}` gives E0002 at 0 to 1; `main io{}` followed by LF gives E0002 at 9 to 10; a tab in a gap is E0001. Add E0002 to `spec/errors.json` (code and `meaning` only, per B4; proposed meaning `non-canonical layout: a gap that is not the canonical gap`, ten words, per RFC 0050 section 4). Expect `lex/v4-lf-only` red (B2). Target under 300 lines.

- [x] 4. Source text and characters, `lexer/source.ts`, `lexer/ident.ts`, `lexer/text.ts`. Rules 1, 2, 6, 9 except the escape table. Invalid UTF-8 is E0001 at the first bad byte; a BOM (U+FEFF) is E0001 wherever it is; an identifier is an ASCII letter or `_` then ASCII letters, digits or `_`; a non-ASCII character outside text is E0001. Text literal: raw LF is content (byte 0x0A); escapes are `\"` and `\\` only; any other `\` sequence is E0005 at the backslash and the next character; an unterminated literal at end of file is E0005 at the span from the opening quote to end of file (the line feed does not end it). Remove the `\n` escape. Update `meaning` text for E0001 and E0005 in `spec/errors.json` to the texts in B5. Tests first in `text.test.ts`, `source.test.ts`, `ident.test.ts`: `"x"` value `x`; `"a` LF `b"` value `a`+LF+`b`; `"a\"b\\c"` value `a"b\c`; `"\n"` is E0005 at 12 to 14 of `main io{put"\n"}`; `put"ab` at end is E0005 at 11 to 14; a BOM at byte 0 is E0001. Target under 300 lines.

- [x] 5. Integer literals, `lexer/int.ts` and `lexer/records.ts`. Rule 8. `0` is one literal; a leading zero followed by more digits (`007`, `00`) is E0006 with fix replacing the literal with its digits without leading zeros, keeping one digit (`007` to `7`, `00` to `0`). The fix record is `{"span":{...},"replacement":"..."}`. A literal above 9223372036854775807 is E0500 reported by the checker, applied before unary `-`; the lexer does not report it. Depends on RFC 0050 subtask 1 for the fix key (B9). Tests first in `int.test.ts` and `records.test.ts`: `007` gives E0006 at 0 to 3 with fix `{span 0..3, "7"}`; `00` gives fix `"0"`; `0` and `10` are fine; the E0500 test checks `9223372036854775807` ok and `9223372036854775808` E0500 at its span. Target under 150 lines.

- [x] 6. First-error rule, `lexer/index.ts` and `lexer/lex.ts`. Rule 13: the lexer reports the first lexical error (E0001, E0002, E0005, E0006) and emits no tokens after it. Tests first in `lex.test.ts`: a file with a bad gap at byte 4 and a bad character at byte 9 gives one record at byte 4 and no tokens; a file with no error gives the token list and EOF. Depends on 3, 4 and 5. Target under 120 lines.

- [x] 7. Parser skeleton and declarations, new `compiler/stage0/src/parser/decl.ts`, `parser/index.ts`. Grammar: `program`, `decl`, `param`, `ptype`, `rtype`, `block` (empty block, and `ret` as the last item). A declaration with no parameters has no parentheses. Marks follow the grammar order: result type, `io`, `fail`, then block, then `ex` clauses (G5 and G10). Tests first in `parser/decl.test.ts` (node, against the token list from subtasks 1 to 6): `main io{}` parses; `f(n Int)Int fail{ret n+1}`; `f io Int{}` gives E0100 at `Int`; `f fail io{}` gives E0100 at `io`; `f()Int{}` gives E0100 at `)`; `main io{ex 1}` gives E0100 at `ex` (G5); `fn main io{}` gives E0100 at `main` (G12); an empty `program` is accepted. Add E0100 entry use only, no new code. Target under 350 lines. Depends on 1 and 2. Done with two deferred parts: a `ret` value and `ex` expressions take an expression parser, which is subtask 9, so `f(n Int)Int fail{ret n+1}` is a node test marked todo until then; a non-empty statement list is subtask 8.

- [x] 8. Statements, `parser/stmt.ts`. Grammar: `let IDENT = expr`, `var IDENT = expr`, `IDENT = expr`, `IDENT ( [args] )`, `put expr`, `if expr block [else block]`, `wh expr block`, `ret [expr]`. G1: no separator; G2: `ret` must be last, so `{ret put 1}` gives E0100 at `put` and `{ret x=1}` gives E0100 at `=`; G7: `else if` is E0100 at `if`; G11: `let a Int=1` is E0100 at `Int`. Tests first in `parser/stmt.test.ts`: each form parses; each named position gives the E0100 in RFC 0104's table (`v6-err-ret-mid`, `v6-err-else-if`, `v6-err-let-type`) as node tests. Target under 350 lines. Depends on 7.

- [x] 9. Expressions, `parser/expr.ts`. Grammar: `expr = and_expr { or }`, `and_expr { and }`, `cmp_expr` (no chaining, G6), `add_expr` (`+ -`), `mul_expr` (`* / %`), `unary` (`- not`), `primary` (`INT`, `TEXT`, `true`, `false`, `IDENT [ ( args ) ]`, `( expr )`). G8: `if`, `wh`, `ret`, `let`, `var`, `put`, `ex`, `io`, `fail` in an expression position are E0100 at the keyword. A statement cannot start with `(`, a unary or a binary operator (no such statement form; expression statements are E0100, `main io{1+2}` at byte 8). Tests first in `parser/expr.test.ts`: `1<2<3` gives E0100 at the second `<` (byte 15 of `main io{put 1<2<3}`); `if` as an expression gives E0100 at `if`; precedence `1+2*3` and `not false and true or false`; `put-((4))` parses. Target under 300 lines. Depends on 8. Also: pass `parser/expr.ts` into `parse()` in place of the stub in `parser/index.ts`, and turn the todo test `f(n Int)Int fail{ret n+1} parses` in `parser/decl.test.ts` into a real test.

- [x] 10. Keyword and EOF errors, `parser/errors.ts`. G3: a keyword where an `IDENT` is required is E0003 at the keyword (declaration name, parameter name, name after `let` or `var`); other misplaced keywords are E0100. G13: at end of file, where the grammar needs more, E0100 at the `EOF` token (`main io{put 1` gives span 13 to 13). This plan owns the E0003 entry in `spec/errors.json`: subtask 10 is its first emitter, so no other plan adds a second entry. Add E0003 with code and `meaning` only (B4), proposed meaning `keyword where an identifier is required` (six words, RFC 0050 section 4). Tests first in `parser/errors.test.ts`: `let let=1` gives E0003 at 0 to 3; `main io{let let=1}` gives E0003 at 12 to 15; `io io{}` gives E0003 at 0 to 2; `f(ret Int)io{}` gives E0003 at 2 to 5; `f(t Text)io{}` gives E0100 at 4 to 8 (G4); `main io{put 1` gives E0100 at 13 to 13. Target under 250 lines. Depends on 7 to 9.
