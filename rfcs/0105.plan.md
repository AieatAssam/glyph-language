# Plan: RFC 0105 Kernel integers, booleans, bindings, functions, conditionals, loops, text output (kernel-v46)

RFC 0105 replaces RFC 0085 (kernel-v44) and builds on `lexical-syntax-v6` (RFC 0104, accepted in front matter). It defines the `put`, `fail`, `ex` and `ret` forms, the F7 fail-mark rule, the E0200 to E0403 checks, the trap line `trap: <kind>` with exit 1 (TR1), and the kernel card (K1). This plan was written on 2026-11-27 from the RFC text and the files of this checkout. Nothing was built or run. Each test named here is a new file; no existing conformance test is edited.

Subtasks 1 to 4 need only the runtime and can start now. Subtasks 5 to 19 depend on the lexer and parser of `lexical-syntax-v6`, which I did not check line by line (Conflicts 3). Subtask 8 and subtask 19 must not land before `retire-print-one` is accepted (Conflicts 1).

## State in this checkout

- `compiler/stage0/src/kernel/` holds the runtime and types with their node tests: `types.ts` (TRAP_KINDS has four kinds, TRAP_LINE, MAX_DEPTH = 10000, MAX_STEPS = 1000000000), `rt-trap.ts` (writes the trap line to stderr through fd_write and calls proc_exit(1)), `rt-print.ts`, `rt-count.ts`, `arith.ts`, and `parse-expr.ts`.
- Not present: the declaration, block and statement parsers; the checker; kernel codegen; `spec/core/kernel.md`; the `# Card: kernel` section of `spec/card.md`.
- `spec/errors.json` has E0001, E0005, E0006, E0010, E0100 and E0500. It has none of E0003, E0200, E0201, E0202, E0300, E0301, E0302, E0303, E0400 or E0403.
- `conformance/kernel/print-one.test` is `fn main() io { print(1) }` with `rfc: 0020`. It passes today and fails under RFC 0105 (G-c).
- `rfcs/0085.plan.md` exists in `rfcs/`, although the 0086 plan says it does not. This plan does not depend on it, because RFC 0105 replaces RFC 0085's design. Read it only for the module names it uses.

## Conflicts and decisions

1. **`retire-print-one` is not accepted (blocking for subtasks 8 and 19).** Under RFC 0105 `print-one.test` cannot pass, and the gate will fail on any PR that removes `print` or changes its syntax. Decision: subtasks 1 to 7, 9 to 18 and 20 to 21 do not change `print` and may land. Subtasks 8 and 19 wait until the orchestrator accepts `retire-print-one`. Do not edit `print-one.test` (Never). Architect: open and accept `retire-print-one` before the parser reaches `put`.
2. **Trap line and exit status already match TR1.** `rt-trap.ts` writes the kind line and calls `proc_exit(1)`. So subtask 1 is a check and an extension, not a rewrite. Decision: keep the existing layout and extend it. Known gap: `MAX_STEPS = 1000000000` in `types.ts` line 30 does not match TR3 (10000000). Subtask 3 fixes it, and says so in its PR body.
3. **Lexer and grammar are assumed to follow `lexical-syntax-v6`.** The RFC gives the grammar by reference. I did not verify that `compiler/stage0/src/lexer/` and `spec/grammar.peg` already match RFC 0104. Decision: subtask 5 first checks the lexer against RFC 0104's tests. If they differ, stop and report it. Do not edit the lexer to match RFC 0105 alone. Architect: confirm RFC 0104 has a conformance set and a grammar that subtask 5 can check.
4. **Error codes enter the catalogue with their first emitter.** Constitution: no code outside `spec/errors.json`. Decision: each subtask that first emits a code adds its entry in the same PR, with the meaning and span from RFC 0105's Diagnostics table and RFC 0093. Never change an entry once it is in. E0003, E0200, E0201, E0202, E0300, E0301, E0302, E0303, E0400, E0403 are added by subtasks 10 to 16.
5. **Example evaluation (EX3) runs in-process.** `check`, `build` and `run` each evaluate examples. Decision: each example is compiled as a Bool function through the same codegen as `main`, then run with the compiler's runtime. The run uses a fresh loop counter at depth 0. If no runtime path exists for this in `compiler/stage0/src/`, subtask 17 stops and reports it.
6. **Test format.** Every new test has a `--- meta` block with `id`, `rfc: 0105` and `kind`. Run tests use `expect-stdout` and `expect-exit`. Trap tests use `expect-exit: 1` and `expect-stderr`. Compile-error tests use the code and line in `expect-errors`. The runner does not compare the span column or the `fix` text in RFC 0105's tables. The PR body must say that these are unchecked.
7. **Test location.** New tests go in `conformance/kernel/`, named as RFC 0105's Test plan names them (for example `put-one`, `trap-div`). Node tests go in `compiler/stage0/src/kernel/*.test.ts` or next to the stage they test.
8. **Gate caps.** Each subtask stays under 400 changed lines. Subtask 20 (the spec and card) may need to split if the core spec measures over 12000 tokens. Measure with `sbx python3 -m tools.check.tokens` before opening the PR.
9. **Syntax used in every test.** Programs are in canonical layout: one line, no separator, no comments. Use `put` without parentheses and `n Int` parameters.

## Subtasks

Write each subtask's tests first, as new files. Then write the smallest code that passes them. Keep each subtask to one stage where possible.

### Runtime (no parser needed)

- [ ] 1. Trap line check and extension (TR1, E1, E2). In `rt-trap.ts` and `types.ts`, confirm that the trap line is exactly `trap: <kind>` with LF and exit 1, and that the four kinds match TR1 (`overflow`, `divide-by-zero`, `stack-exhausted`, `step-exhausted`). Tests first: `rt-trap-kernel.test.ts` (new) checks each kind's stderr line and exit status, and that nothing else is written to stderr. Target under 150 lines.
- [ ] 2. Integer arithmetic (E1, E2, T1). In `arith.ts`, check `+ - *` overflow, unary `-` on the minimum, `/` and `%` truncating toward zero, `%` taking the sign of the left operand, `MIN/-1` trapping `overflow`, `MIN%-1` giving `0`, and a zero divisor trapping `divide-by-zero`. Tests first in `arith.test.ts` (extend with new cases; do not change existing ones). Target under 200 lines.
- [ ] 3. Depth and step counters (TR2, TR3). In `rt-count.ts`, the depth check traps `stack-exhausted` when depth would be 10001, with `main` at depth 1 and examples at depth 0. The per-frame loop counter traps `step-exhausted` before an addition would exceed 10000000. Fix `MAX_STEPS` in `types.ts` to 10000000 and say so in the PR body. Tests first in `rt-count.test.ts`. Target under 150 lines.
- [ ] 4. Output format (P2). In `rt-print.ts`, `put` of an `Int` writes decimal with a leading `-` when negative, then LF. `put` of text writes the bytes, then LF. Tests first in `rt-print.test.ts`: `0`, `-7`, `9223372036854775807` and the minimum `-9223372036854775808`. Target under 150 lines.

### Lexer and parser (lexer and grammar must match `lexical-syntax-v6`, Conflicts 3)

- [ ] 5. Lexer check for kernel words and literals (lexical G3, T1, E0500). Confirm that `put`, `fail`, `let`, `var`, `wh`, `ret`, `if`, `else`, `ex`, `io`, `Int`, `Bool`, `true`, `false`, `not`, `and`, `or` are keywords, and that an integer literal above 9223372036854775807 is E0500. Add tests in `lexer/kernel-words.test.ts` (new) only for the kernel cases. Do not add lexer rules beyond RFC 0104. Target under 150 lines.
- [ ] 6. Expression parser (precedence, G6, E0100). Extend `parse-expr.ts` to the precedence table in RFC 0105 (`or`, `and`, comparisons without chaining, `+ -`, `* / %`, unary `- not`, call, literal, name, parenthesis). Binary operators are left-associative. A chained comparison is E0100. Tests first in `parse-expr.test.ts` (new cases). Target under 250 lines.
- [ ] 7. Declaration and block parser (L1, L3, F1, EX1). Parse `NAME [ "(" NAME T, ... ")" ] [ R ] [ "io" ] [ "fail" ] block { "ex" expr }`, with no parentheses for a declaration without parameters. `fn main io{}` is E0100 at `main`. `ex` after a non-declaration is E0100 at `ex`. Tests first in `parse.test.ts` (new cases). Target under 300 lines.
- [ ] 8. Statement parser (L2, P1, C1, C2). Parse `let`, `var`, assignment, a call statement, `put` with exactly one expression, `if` with block-only `else`, `wh`, and `ret` with or without an expression as a block's last item. `put 1 2` is E0100 at `2`. `put(1,2)` is E0100 at `,`. A statement never starts with an operator, `(` or a literal. Tests first in `parse.test.ts`. **Waits for `retire-print-one` (Conflicts 1).** Target under 300 lines.

### Checker (one diagnostic per subtask, each adds its codes to `spec/errors.json`)

- [ ] 9. Types of literals and operators (T2, T3, T5, T6, E3, E8, E9). Check `Bool` and `Int` operand types, `==` and `!=` on two `Int` or two `Bool`, `and` `or` `not` on `Bool`, the `if` and `wh` condition being `Bool`, text only as the whole argument of `put` (E0200 elsewhere), a void call used as a value (E0200), a type or function name used as a value (E0301). Failed expressions take a recovery type `?` with no further diagnostic. Add E0200 and E0301 to `spec/errors.json`. Tests first: one compile-error test per row of RFC 0105's compile-error table in this area. Target under 350 lines.
- [ ] 10. Bindings and scope (B1 to B5, F6). `let` immutable, `var` mutable, assignment only to `var` (E0303 otherwise), unknown name E0301, use before declaration E0301, parameters declared as `let` at the body's start, duplicate or reserved names E0300, `put` and `fail` as names E0003, function names unique (E0300). Add E0003, E0300, E0303 to `spec/errors.json`. Target under 350 lines.
- [ ] 11. Calls and arity (E6, E7, F5). Argument count and types must match the parameters (E0200 at the argument, or at the callee name for a count error). Evaluation is left to right. Recursion is allowed. Add no new codes. Target under 250 lines.
- [ ] 12. Return analysis (F3, F4, C2). A block returns if its last item is `ret`, or an `if` with `else` whose two blocks both return. A `wh` never returns. A result clause whose body does not return is E0201 at the closing `}`. `ret e` with a mismatch or a value in a no-result function is E0200 at `e`. Bare `ret` in a result function is E0200 at `ret`. Add E0201 to `spec/errors.json`. Target under 250 lines.
- [ ] 13. Effects and entry point (F2, M1, P1 effect). A function without `io` may not call an `io` function or `put` (E0400 at the callee name, or at `put`). `main` must be unique (E0300 for a second), have no parameters or result (E0200 at `main`), and exist (E0302 at the end-of-file token). Add E0302, E0400 to `spec/errors.json`. Target under 300 lines.
- [ ] 14. Examples check (EX1, EX2, C0). `ex e` must be `Bool`, call no `io` function (E0400 at the callee), and cannot contain `put` (E0100 there). The examples check runs only when no other error is reported (C0). Target under 250 lines.
- [ ] 15. Fail mark (F7, E0403). A body is trapping if it has a binary `+ - * / %`, a unary `-`, a `wh`, or a call to a function declared in the file (`put` does not count), outside its examples. The `fail` token must be present if and only if the body is trapping. A wrong mark is E0403 at the function name. The fix is a zero-length insert of ` fail` at the `{`, or a delete of the space and `fail`. Add E0403 to `spec/errors.json`. Tests: `kc-fail-missing`, `kc-fail-extra`, `kc-fail-main`. Target under 300 lines.
- [ ] 16. Example evaluation (EX3, E0202, TR1 at check time). Compile each example as a Bool function through the same codegen (Conflicts 5) and run it; `false` or a trap is E0202 from `ex` to the end of `e`. Add E0202 to `spec/errors.json`. **Depends on subtask 17.** Target under 300 lines.

### Codegen (uses `toolkit/wasm-encoder.ts` `ModuleBuilder` and `Op`)

- [ ] 17. Expression and binding codegen (E1, E2, E4, E7, B1). Emit `Int` and `Bool` expressions, `let` and `var`, assignment, `and` and `or` with short-circuit, comparisons, and `+ - * / %` calling the runtime's trap checks from subtask 2. Tests first: the run tests `let-var`, `bool-ops`, `short-circuit`, `cmp-ordering`, `arith`, `min-mod`, `digit-sum`, `int-min`. Target under 350 lines.
- [ ] 18. Functions, calls and control (F1, F5, TR2, TR3, C1, C2). Emit functions with parameters and results, calls, bare `ret`, `if`, `wh`, and the depth and step counters from subtask 3 at function entry and at each `wh` condition. Tests first: `fn-call`, `fn-result-io`, `fn-bool-param`, `fn-io`, `fn-void`, `fn-recursion`, `if-else-return`, `ret-bare`, `shadow`, `example-ok`, and the trap tests `trap-stack` and `trap-step`. Target under 400 lines; split if it reaches 400.
- [ ] 19. `put` and `main` (P1, P2, M1). Emit `put` through WASI `fd_write` and `main` as the export. Tests first: `put-one`, `print-int`, `put-text`, `trap-overflow`, `trap-add`, `trap-min`, `trap-div`. **Waits for `retire-print-one` (Conflicts 1).** Target under 300 lines.

### Spec and card

Fix only the kernel tests and entries. Target under 100 lines.
