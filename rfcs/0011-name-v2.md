# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the spec title, the source file rule, and the one diagnostic record that the rule writes.

## Motivation

The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, `bin/glyphc` and the site. Keeping that name costs nothing. The check job and the publisher need one fixed source suffix before any lexer exists. The rule reads only the path, before the file is read, so it is a file-name rule even though its code sits in the lexical block.

## Design

Normative.

1. The language name is `Glyph`. The spec title is `Glyph`.
2. A path is a source file when the part after its last `/` ends in `.gl` and is longer than `.gl`. Matching is case-sensitive. `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. `main.glyph`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/` and the empty string are not.
3. The executable is `glyphc`. Its subcommands are `check`, `run` and `build`. Later RFCs define what they do.
4. When `glyphc check`, `run` or `build` is given a path that is not a source file, it does not read the path. It writes exactly one record to standard error, in the form of RFC 0004 section 2, writes nothing to standard output, and exits with status 1:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix`
5. `E0010` is the code of this RFC. Its entry in `spec/errors.json` has the meaning "the path given is not a source file". Other RFCs may cite `E0010`; none may give it another meaning. The message keeps `.gl` as written. The full stop inside the extension is not a sentence break (owner ruling, below).

## Alternatives

- **Keep "Glyph" as a codename and pick a name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension question open.
- **Pick a new name.** Rejected. Every existing file and tool would change. Name collisions were not checked, because this session has no network access. A later RFC can rename the language while renaming is still cheap.
- **No source-file rule.** Rejected. The publisher and check job need one suffix.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1.
- **Give the code another prefix.** Rejected. RFC 0004 fixes `E` followed by four digits.

## Cost

Measured with `sbx python3 -m tools.check.tokens` on the spec text this RFC requires (design 1, 2 and 4 in compact form):

- Core spec: adds 100 tokens.
- Spec card: adds 11 tokens (`Glyph` and `Source: *.gl, compiler glyphc`).
- Removes nothing.
- Diagnostics: one code, `E0010`. It is already in `spec/errors.json` and is the only code this RFC uses.
- Grammar: no production is added, so grammar coverage is unchanged.

## Test plan

- **run:** `conformance/name/run-title.test`. A `main.gl` prints `Glyph` with `print`. No accepted RFC defines `print` yet, so this test waits for one.
- **compile-error (node test):** `compiler/stage0/src/cli.test.ts`. For each of `check`, `run` and `build`, and each of `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`, stderr is exactly the record in design 4 and the exit status is 1. The conformance runner writes every input as `main.gl` (`tools/check/conformance.py`), so a file-name case cannot be a `.test` file.
- **unit:** `compiler/stage0/src/source-file.test.ts` covers every example in design 2.
- **catalogue:** `compiler/stage0/src/e0010.test.ts` checks that `E0010` appears once in `spec/errors.json` with the meaning in design 5, and that its message passes the message checker in `compiler/stage0/src/message.ts`.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- The conformance runner cannot name an input other than `main.gl`. A meta key for the input name would let file-name cases become `.test` files. Only the architect can add it.
- RFC 0005's example `main.glyph::add` does not match design 2. A kernel RFC should use `main.gl::add`.
- The name has not been checked against trademarks or existing software.


## Owner ruling (2026-11-20)

The one-sentence rule in RFC 0004 section 2 does not treat a full stop inside a file name or extension, such as `.gl` or `main.gl`, as a sentence break. The RFC 0011 message `source file does not end in .gl` is valid as written. The message checker in `compiler/stage0/src/message.ts` must accept it, with a test. This settles the conflict between RFC 0004 and RFC 0011 (issues 54 and 59).
