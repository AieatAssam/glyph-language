# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min
Status: draft

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name, the source file extension, and one diagnostic code, `E0010`.

## Motivation

The name is already used in `README.md`, `docs/SPEC.md`, `bin/glyphc` and the site. Changing it would touch all of them before any kernel exists.

The check job and the publisher need one fixed source suffix before any lexer exists. The check runs on the file name before the file is read, so it does not depend on valid content.

## Design

Normative.

1. The language name is `Glyph`. The spec title is `Glyph`. The name is case-sensitive.
2. The spec core is `spec/core.md`. The spec card is `spec/card.md`.
3. A path is a source file when the part after its last `/` ends in `.gl` and has at least one character before `.gl`. The match is case-sensitive. These are source files: `main.gl`, `dir/prog.gl`, `a.b.gl`. These are not: `.gl`, `dir/`, the empty string, `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`.
4. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. Later RFCs define what they do.
5. When `glyphc` is given a path that is not a source file, it does not open the file. It writes exactly one record to stderr, in the JSON Lines form of RFC 0004 section 2, and exits with status 1. Nothing is written to stdout. The record has:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix` field.
6. The message in rule 5 is valid under RFC 0004 section 2. A full stop followed by a letter inside a file name, such as the one in `.gl`, is part of the name, not a sentence break. The message checker must accept the message, and a test must show it.
7. `E0010` is added to `spec/errors.json` with the message in rule 5 and the meaning `the path given is not a source file`. Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and decide later.** Rejected. It postpones a decision that costs nothing now and leaves the extension open.
- **Pick a new name.** Rejected. Every existing file and tool would change. Name collisions were not checked. A later RFC can rename the language, which stays cheap until a release exists.
- **No extension rule.** Rejected. Sources need one suffix to be found.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second spelling of one thing, which breaks principle 1.
- **A `GLY` code prefix.** Rejected. RFC 0004 uses `E` and four digits only.

## Cost

Counter output from `tools/check/tokens.py`:

- Card source line `Source: *.gl, compiler glyphc`: 8 tokens. The card also gains the title line `Glyph`.
- Diagnostic message `source file does not end in .gl`: 8 tokens, in `spec/errors.json`.
- Core spec: adds the title, the rules in Design 2 to 6, and the `glyphc` line. The core count is taken by the implementing PR with the counter. This RFC removes nothing from the core.
- Grammar: no production is added, so grammar coverage is unchanged.
- Diagnostics: one new code, `E0010`.

## Test plan

Node tests run in the gate `node --test 'compiler/stage0/**/*.test.ts'`.

- **compile-error (node):** `compiler/stage0/src/cli.test.ts`. For each of `check`, `run` and `build`, the paths `prog.txt`, `PROG.GL`, `main.glyph` and missing `missing.txt` each give exactly the record in Design 5, exit status 1, nothing on stdout, and no ENOENT.
- **file-name rule (node):** `compiler/stage0/src/source-file.test.ts`. Each path in Design 3 gets its stated result.
- **catalogue (node):** `compiler/stage0/src/e0010.test.ts`. `E0010` appears once in `spec/errors.json`, lies in the block E0001 to E0099, has the message and meaning above, and its message passes `checkMessage` in `message.ts`.
- **run:** `conformance/name/run-title.test`. A `main.gl` prints `Glyph` with `print`. It is written only after a kernel RFC that defines `print` is accepted and implemented.

No conformance compile-error test is used for the file-name rule. The conformance runner writes every `.test` input to `main.gl` and has no key for another input file name, so `prog.txt` and `PROG.GL` cannot be inputs. The node tests above cover those cases until the runner can name an input file. That runner change is outside this RFC.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- A second source extension, if ever wanted, needs a later RFC that justifies it.
- The name has not been checked against existing software or trademarks.
- A kernel RFC that defines `print` must write its address example as `main.gl::add`, not `main.glyph::add`.
