# RFC draft: The language name

Class: language
Slug: name-v2

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name, the source file suffix, and one diagnostic code for a path that is not a source file.

## Motivation

The repository already uses the name Glyph in its README, spec, compiler command and site. Keeping it changes nothing. The toolchain needs one fixed suffix to find sources before any lexer exists. The check runs on the path before the file is read, so it works when the content is not valid Glyph. That is why it is a file-name rule, even though its code is in the lexical block.

## Design

Normative.

1. The language name is `Glyph`. The spec title is `Glyph`. Names are case-sensitive, and `Glyph` is the only spelling.
2. A path is a source file when the part after its last `/` ends in `.gl` and has at least one character before `.gl`. The match is case-sensitive. `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. `PROG.GL`, `main.glyph`, `prog.txt`, `main.gl.bak`, `.gl`, `dir/` and the empty path are not.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. Later RFCs define what they do with a source file.
4. When `glyphc check`, `glyphc run` or `glyphc build` is given a path that is not a source file, it does not open the file. It writes to standard error exactly one record, as one JSON line in the form of RFC 0004 section 2, and writes nothing to standard output. It then exits with status 1. The record is:

```
{"code":"E0010","severity":"error","message":"source file does not end in .gl","span":{"file":"prog.txt","start":0,"end":0,"line":1,"column":1}}
```

   Here `file` is the path as given on the command line. The record has no `fix` field.
5. Code `E0010` is entered in `spec/errors.json` with the message in (4) and the meaning "the path given is not a source file". It lies in the lexical block (RFC 0004 section 4). The message is valid under RFC 0004 section 2: a full stop inside a name such as `.gl` does not end a sentence.

## Alternatives

- **Pick a new name.** Rejected. Every existing file and tool would change, and no reason given outweighs that cost. Collision with other software was not checked, because this session has no network access. A later RFC can rename the language; renaming is cheap until a release exists.
- **No suffix rule.** Rejected. Tools need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name a source, which breaks principle 1 of the constitution.
- **Use a `GLY` code prefix.** Rejected. RFC 0004 section 2 fixes `E` followed by four digits.

## Cost

Counted with `tools/check/tokens.py`.

- Spec core: adds the text below, 70 tokens. It is the core addition as written:
  "Glyph. Source files end in `.gl`, case-sensitive: the part after the last `/` ends in `.gl` with at least one character before it. Compiler `glyphc` with subcommands `check`, `run`, `build`. A path that is not a source file: E0010, status 1, file not read."
- Spec card: adds `Glyph` and `Source: *.gl, compiler glyphc`, 10 tokens.
- Record in (4): 45 tokens. This RFC has no example program, so no program's cost changes.
- Removes: nothing.
- Diagnostics: one new code, `E0010`.
- Grammar: no production is added, so grammar coverage is unchanged.

## Test plan

- run: `conformance/name/run-title.test`. A `main.gl` prints `Glyph` with the output operation of the kernel RFC.
- compile-error (node): `compiler/stage0/src/cli.test.ts`. For each of `check`, `run` and `build`, and each path `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`: the return value is 1, standard output is empty, standard error is exactly the record in (4) with that path, and no file-system error such as ENOENT is reported for a missing path.
- node: `compiler/stage0/src/source-file.test.ts`. Each path in (2) gives the stated result.
- node: `compiler/stage0/src/e0010.test.ts`. `E0010` is listed once in `spec/errors.json` with the message and meaning in (5), and that message passes the message rules.

The conformance runner gives every source the name `main.gl`, so the file-name cases are node tests and not conformance tests.

## Open questions

- A conformance test for the file-name cases needs the runner to take an input file name other than `main.gl`. That change is outside this RFC.
- Whether a second suffix is ever needed. This RFC says no; a later RFC must justify any second suffix.
- The name has not been checked against existing software or trademarks.
