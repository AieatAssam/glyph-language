# RFC 0011: The language name

Class: language
Slug: name-v2
Author: designer-min

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`, as already used in `bin/glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name, the one source file suffix the toolchain needs, and the one diagnostic code that rule uses.

## Motivation

The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Any other name would mean renaming all of that before any kernel code exists. The publisher and the check job need one fixed suffix to recognise language sources, so the suffix is fixed here.

The file-name rule runs on the path before the file is read, so it works even when the content is not valid Glyph. Its code sits in the lexical block because it is a lexical-level check on the input.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`. Spelling is case-sensitive; `Glyph` is the only spelling used in the spec.
2. A path is a source file when the part after its last `/` ends in `.gl`, and at least one character comes before `.gl`. The match is case-sensitive and the suffix is the last one only. So `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/`, and the empty path are not.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC names them and defines nothing else about them.
4. When `check`, `run` or `build` is given a path that is not a source file, `glyphc` does not read the file. It writes exactly one record to stderr in the JSON Lines form defined by RFC 0004 section 2, with:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`. The file is not read, so the span is the start of the file.
   - no `fix` field.
   It writes nothing to stdout and exits with status `1`.
5. The message in item 4 is valid under the RFC 0004 section 2 message rules. A full stop inside a file name, such as in `.gl`, is not a sentence break. The message checker in `compiler/stage0/src/message.ts` must accept this message. It is not a special case: the checker's rule for full stops is that a full stop followed by a letter is part of a name.
6. `spec/errors.json` contains this entry exactly once: `{"code": "E0010", "message": "source file does not end in .gl", "meaning": "the path given is not a source file"}`. Codes are never reused.
7. Item 2 applies to the path as given to `glyphc`. A path with no file name part, such as `dir/`, is not a source file.

## Alternatives

- **Keep "Glyph" as a codename and pick a name later.** Rejected. It postpones a decision that costs nothing now and leaves the suffix open.
- **Pick a new name.** Rejected. Every existing file and tool would need changing. Collision with other software was not checked, because this session has no network access. A later RFC can rename the language if needed.
- **No suffix rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1.
- **A `GLY` diagnostic prefix.** Rejected. RFC 0004 fixes the `E` plus four digits form.

## Cost

Counted with the protected counter on the card line `Source: *.gl, compiler glyphc`: 8 tokens. The spec card gains one title line `Glyph` and that source line. The core spec gains the name, the suffix rule (items 1 to 3) and the file-name rule (items 4 to 7). The core count is taken when the spec is written; the first implementing PR runs the counter and reports the figure.

- **Adds:** one diagnostic code, `E0010`, with its message and meaning.
- **Removes:** nothing.
- **Grammar:** no production is added, so grammar coverage is unchanged.

## Test plan

- **run:** `conformance/name/run-title.test`. A `main.gl` that prints `Glyph` with `print`. `print` must be defined by an accepted kernel RFC before this test can pass.
- **compile-error:** node tests in `compiler/stage0/src/cli.test.ts`. For each of `check`, `run` and `build`, with paths `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`: the stderr is exactly the record in item 4, stdout is empty, the exit status is `1`, and the file is not read (no ENOENT or other read error). A `.gl` path does not produce E0010.
- **unit:** `compiler/stage0/src/source-file.test.ts` covers the examples in item 2. `compiler/stage0/src/e0010.test.ts` checks that the `spec/errors.json` entry exists once, that its code is in E0001 to E0099, and that its message passes `message.ts`.

The file-name cases are not conformance tests. The conformance runner writes every test input to `main.gl`, so it cannot give `glyphc` a path such as `prog.txt`. This RFC does not change the runner.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- Conformance compile-error cases for item 4 need the runner to accept an input file name. Until a runner RFC adds that, the node tests above are the compile-error tests.
- `run-title.test` depends on an accepted kernel RFC that defines `print`.
- RFC 0005's address example `main.glyph::add` must read `main.gl::add` under this RFC. That change belongs to RFC 0005.
