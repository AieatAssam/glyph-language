# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`, as already used in `bin/glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec title, the one source file extension the toolchain needs, and the one diagnostic code that rule uses.

## Motivation

The constitution leaves the name to the agents. The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. The cheapest name is the one already in use.

The file extension is needed now. The check job and the publisher need one fixed suffix to recognise language sources.

The check runs on the file name before the file is lexed, so it works even when the content is not valid Glyph. That is why it is a file-name rule, even though its code sits in the lexical block.

Under RFC 0004 section 2, a full stop inside a file name, such as in `.gl` or `main.gl`, is not a sentence break (owner ruling, 2026-11-20). So the message `source file does not end in .gl` is valid.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`.
2. A source file uses the extension `.gl`. The extension is lower case. A path is a source file when its last suffix is exactly `.gl`, and the part before it is not empty. A path such as `main.glyph` or `prog.GL` is not a source file.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC does not define those subcommands; later RFCs do.
4. Names in this RFC are case-sensitive. `Glyph` is the only spelling of the name in the spec.
5. When `glyphc` is given a path that is not a source file, it does not read the file. It writes exactly one diagnostic record to standard error, as defined by RFC 0004 section 2, and exits with status 1. Nothing is written to standard output. This applies to each subcommand in (3), and also when the path does not exist. The record is:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`. The file is not read, so the span is the start of the file.
   - no `fix`. Renaming the file is the author's choice, not a mechanical edit.
6. The code `E0010` is listed in `spec/errors.json` with the message in (5) and the meaning "the path given is not a source file". Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and pick a new name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension question open.
- **Pick a new name.** Rejected. Every existing file and tool would need changing, and no reason is given that outweighs that cost. Renaming stays cheap until a release exists.
- **No file extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1.
- **Use a diagnostic code from the `GLY` prefix.** Rejected. RFC 0004 fixes the `E` plus four digits format and has no other prefix.

## Cost

- **Adds:** the name in the spec title and the rule for `.gl` (about 30 tokens in the core spec). One new diagnostic code, `E0010`, with its message (about 20 tokens in the core spec).
- **Removes:** nothing.
- **Spec card:** one title line, `Glyph`, and one line `Source: *.gl, compiler glyphc`. Net change is about 10 tokens. The card stays far under its 2,000-token cap.
- **Diagnostics:** one new code, `E0010`, in the lexical block. It is the only code this RFC adds.
- **Grammar:** no production is added, so grammar coverage is unchanged.

## Test plan

- **compile-error:** `compiler/stage0/src/cli.test.ts`, the test "a path that is not a source file gives the E0010 record and exits 1, for each subcommand". It runs `check`, `run` and `build` on `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`. Each run must give exactly the record in Design (5) with its own `file` value, no `fix`, exit status 1 and empty standard output. `compiler/stage0/src/main.test.ts` checks the same record through the built entry point.
- **run:** `conformance/name/run-title.test`. A kernel program `main.gl` prints `Glyph` with `print`. `print` and its text output are defined by the kernel RFC, not by this one. The test is written once that definition is in force.
- The file-name cases are node tests and not `.test` files. The conformance runner writes every source to `main.gl` and cannot name another input file.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- Whether the language should accept a second extension later. This RFC says no. A later RFC must remove or justify any second suffix.
- The name has not been checked against existing software or trademarks.
