# RFC: The language name

Class: language
Slug: name-v2
Author: designer-min

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec title, the one source file suffix, and one diagnostic code for a path that lacks that suffix.

## Motivation

The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command `bin/glyphc`, and the site. Renaming would touch all of them before any kernel code exists. The check job and the publisher also need one fixed suffix to recognise language sources.

The check runs on the path before the file is read, so it works even when the content is not valid Glyph. That is why it is a file-name rule, even though its code sits in the lexical block.

A full stop inside a file name, such as the one in `.gl`, is not a sentence break under RFC 0004 section 2. The message `source file does not end in .gl` is valid (owner ruling, 2026-11-20).

## Design

Normative.

1. The name of the language is `Glyph`, case-sensitive. It is the spec title.
2. A source file is a path whose last suffix is exactly `.gl`, case-sensitive. The part after the last `/` must have at least one character before `.gl`. So `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. `.gl`, `dir/`, the empty string, `main.glyph`, `prog.txt`, `PROG.GL` and `main.gl.bak` are not.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC names them and does not define them; later RFCs do.
4. When `glyphc check`, `glyphc run` or `glyphc build` is given a path that is not a source file, it does not open the file. It writes exactly one diagnostic record to stderr, in the JSON Lines form RFC 0004 section 2 defines, and exits with status 1. Nothing is written to stdout. The record has:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix`
   A path that is not a source file and does not exist gets the same record, not a file-not-found error. This RFC does not define what happens for a `.gl` path that is missing.
5. `E0010` is an entry in `spec/errors.json` with `meaning` "the path given is not a source file". Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and decide later.** Rejected. It postpones a decision that costs nothing now and leaves the suffix open.
- **A different name.** Rejected. Every existing file and tool would change for no gain. Collisions with other software and trademarks were not checked, because this session had no network access. A later RFC can rename the language while renaming is still cheap.
- **No suffix rule.** Rejected. Tools need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same file, which breaks principle 1.
- **A `GLY` code prefix.** Rejected. RFC 0004 fixes the `E` plus four digits form.

## Cost

Counted with `tools/check/tokens.py`:

- **Spec card:** the two lines `Glyph` and `Source: *.gl, compiler glyphc` are 11 tokens. The card grows by 11.
- **Diagnostic entry:** the `E0010` entry in `spec/errors.json`, `{"code":"E0010","message":"source file does not end in .gl","meaning":"the path given is not a source file"}`, is 29 tokens.
- **Spec core:** the title and the suffix rule (items 1 and 2) are added to the core spec. That file does not exist yet, so its count is not taken here.
- **Removes:** nothing.
- **Grammar:** no production is added.

## Test plan

These node tests run in the existing gate, `compiler/stage0/**/*.test.ts`:

- `compiler/stage0/src/source-file.test.ts`: the source-file cases in item 2, each as expected.
- `compiler/stage0/src/cli.test.ts`: for each of `check`, `run` and `build`, the paths `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`. Each gives exactly the record in item 4, exit status 1, empty stdout, and no file-system error.
- `compiler/stage0/src/e0010.test.ts`: `spec/errors.json` has `E0010` exactly once, its code is in `E0001` to `E0099`, and its message passes `checkMessage` in `compiler/stage0/src/message.ts`.
- `compiler/stage0/src/message.test.ts`: `source file does not end in .gl` passes `checkMessage` with no problems.

Conformance tests:

- **run:** `conformance/name/run-title.test`. A `main.gl` prints `Glyph` with `print`. This test waits for a kernel RFC that defines `print` (Open questions).
- **compile-error:** the node tests above are the compile-error tests for item 4. The conformance forms `conformance/name/bad-extension.test` and `conformance/name/upper-extension.test` are in Open questions.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- **Conformance input names.** The conformance runner writes every test source to `main.gl`. So the conformance compile-error forms of item 4 (`glyphc check prog.txt`, `glyphc check PROG.GL`) cannot be expressed yet. Adding an input-name key is a change to `tools/`, which this RFC does not make. The node tests above cover the same rule meanwhile.
- **Kernel address example.** The kernel RFC's `main.glyph::add` example must read `main.gl::add` so that it agrees with item 2. That RFC's author must make the change.
- **Print.** The run test needs a kernel RFC that defines `print`.
- **Second suffix.** This RFC allows only `.gl`. A later RFC must justify any second suffix.
- **Name check.** The name has not been checked against other software or trademarks.
