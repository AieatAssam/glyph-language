# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min
Status: draft
Attempt: 2 (replaces RFC 0002, rejected)

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`, as already used in `bin/glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec title, the one source file extension the toolchain needs, and the one diagnostic code that rule uses.

## Motivation

The constitution leaves the name to the agents. The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Every other choice would mean renaming all of that before any kernel code exists. The cheapest name is the one already in use.

The file extension is needed now. The check job and the publisher need one fixed suffix to recognise language sources. Without an RFC, each component would pick its own.

Attempt 1 (RFC 0002) was rejected for four objections. This attempt keeps everything the voters accepted and changes only what they objected to:

- **Diagnostic code format (designer-safe, impl-1, tester).** Attempt 1 used `GLY0001`. RFC 0004 section 2 requires `E` followed by four digits, and section 4 assigns blocks. The code is now `E0010`, in the lexical block `E0001`-`E0099`. No other RFC in `rfcs/` uses `E0010`. Drafts already use E0001 to E0004 for lexical errors, so the next free number in the block is used.
- **Wrong owner of `print` (tester).** Attempt 1's run test said `print` comes from RFC 0003. `print` is defined in RFC 0005 (kernel). RFC 0003 is the lexical RFC. The run test now cites RFC 0005.
- **Address example conflict (tester).** RFC 0005 section "Stable addresses" gives the example `main.glyph::add`. The suffix `.glyph` is not `.gl`, so under this RFC that file is not a source file. This RFC does not edit RFC 0005. The correct example is `main.gl::add`. RFC 0005 must be corrected before it is accepted. See Open questions.

The check runs on the file name before the file is lexed, so it works even when the content is not valid Glyph. That is why it is a file-name rule, even though its code sits in the lexical block.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`. The word "codename" is removed from `README.md` when the first RFC that creates `spec/` is implemented. This RFC does not edit that file.
2. A source file uses the extension `.gl`. The extension is lower case. A path is a source file when its last suffix is exactly `.gl`. A path such as `main.glyph` or `prog.GL` is not a source file.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`, as in the repository's notes. This RFC does not define those subcommands; later RFCs do.
4. Names in this RFC are case-sensitive. `Glyph` is the only spelling of the name in the spec.
5. When `glyphc` is given a path that is not a source file, it does not read the file. It writes exactly one diagnostic record, as defined by RFC 0004 section 2, and exits with a nonzero status:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`. The file is not read, so the span is the start of the file.
   - no `fix`. Renaming the file is the author's choice, not a mechanical edit.
   - Exit status: `1`, the status the repository uses for a compile error. Nothing is written to standard output.
6. The code `E0010` is added to `spec/errors.json` by the first implementing PR, with the message above and the one-line meaning "the path given is not a source file". Codes are never reused.
7. The rule applies to the path as given, before any other check. `.gl` alone, and a path ending in `/`, are not source files. The part of the path tested is the text after its last `/`, and that text must have at least one character before `.gl`.

## Alternatives

- **Keep "Glyph" as a codename and pick a new name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension question open.
- **Pick a new name.** Rejected. Every existing file and tool would need changing, and no reason is given that outweighs that cost. Collision with other projects was not checked, because this session has no network access. If a collision is found later, a new RFC can rename the language. Renaming is cheap until a release exists.
- **No file extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1. RFC 0005's `main.glyph` example is therefore a conflict to be fixed there, not a reason to add the suffix here.
- **Use a diagnostic code from the `GLY` prefix.** Rejected. RFC 0004 fixes the `E` plus four digits format and has no other prefix.

## Cost

- **Adds:** the name in the spec title and the rule for `.gl` (about 30 tokens in the core spec). One new diagnostic code, `E0010`, with its message (about 20 tokens in the core spec).
- **Removes:** nothing. The word "codename" is already outside the spec.
- **Spec card:** one title line, `Glyph`, and one line `Source: *.gl, compiler glyphc`. Net change is about 10 tokens. The card stays far under its 2,000-token cap.
- **Diagnostics:** one new code, `E0010`, in the lexical block. It is the only code this RFC adds.
- **Grammar:** no production is added, so grammar coverage is unchanged.

## Test plan

The file-name rule is tested in two places. The node tests run now, in the existing gate `node --test 'compiler/stage0/**/*.test.ts'`. They are the tests of record for this RFC until the conformance runner can take an input file name. The conformance tests are gated, as stated below.

Node tests (buildable now):

- `compiler/stage0/src/source-file.test.ts`: `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/` and the empty string are not.
- `compiler/stage0/src/cli.test.ts`: for each of `check`, `run` and `build`, the paths `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt` each write exactly the record in Design item 5 to standard error, write nothing to standard output, return 1, and do not read the file (no `ENOENT` for `missing.txt`). A `.gl` path does not produce `E0010`.
- `compiler/stage0/src/e0010.test.ts`: `spec/errors.json` contains `E0010` exactly once, with the message from Design item 5, in the block `E0001`-`E0099`.
- `compiler/stage0/src/message.test.ts`: `checkMessage("source file does not end in .gl")` returns no problems. The full stop inside `.gl` is not a sentence break (owner ruling below).

Conformance tests (gated on the runner, not yet buildable):

- **compile-error:** `conformance/name/bad-extension.test`. `glyphc check prog.txt` gives exactly one record, as JSON: `{"code":"E0010","severity":"error","message":"source file does not end in .gl","span":{"file":"prog.txt","start":0,"end":0,"line":1,"column":1}}`, with no `fix` field and exit status 1. The runner compares `code`, `span` and `fix`, as RFC 0004 section 7 requires.
- **compile-error:** `conformance/name/upper-extension.test`. `glyphc check PROG.GL` gives `E0010`, because the extension is lower case only.
- **run:** `conformance/name/run-title.test`. A program `main.gl` prints `Glyph` with `print`. `print` is not defined by any accepted RFC yet, so this test waits for an accepted kernel RFC.

Gate reason for the two compile-error files: `tools/check/conformance.py` writes every `.test` source to `main.gl` (line 212), and `parse_test` reads no meta key that names another input file. A `prog.txt` or `PROG.GL` input therefore cannot be expressed, and both files would fail the gate if added now. They are added in the same change that gives the runner an input-file-name key. That runner change belongs to the architect, because `tools/` is not written by implementers. Until then the node tests above cover the cases, and no conformance file for these names is to be added.

No grammar production is added, so the coverage script has nothing new to match.

## Open questions

- **RFC 0005 must change its address example.** Its `main.glyph::add` must read `main.gl::add` for this RFC and RFC 0005 to agree. This RFC cannot make that change, because RFC 0005 is not its file. Its author or the orchestrator must make the change before RFC 0005 is accepted.
- **Status of the run test.** `print` is not defined by any accepted RFC at this revision, so `conformance/name/run-title.test` waits. The node tests and the compile-error conformance files (once the runner allows them) do not depend on it.
- **Runner input-name key.** The two compile-error conformance files need a runner key that names the input file. Owner: architect, in `tools/check/conformance.py`. Until it exists, the node tests are the tests of record.
- Whether the language should also accept a second extension later. This RFC says no. A later RFC must remove or justify any second suffix.
- The name has not been checked against existing software or trademarks. That needs a network check outside this session.


## Owner ruling (2026-11-20)

The one-sentence rule in RFC 0004 section 2 does not treat a full stop inside a file name or extension, such as `.gl` or `main.gl`, as a sentence break. The RFC 0011 message `source file does not end in .gl` is valid as written. The message checker in `compiler/stage0/src/message.ts` must accept it, with a test. This settles the conflict between RFC 0004 and RFC 0011 (issues 54 and 59).
