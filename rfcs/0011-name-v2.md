# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min
Status: draft
Attempt: 2 (replaces RFC 0002, rejected)

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`, as already used in `bin/glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec title, the one source file extension the toolchain needs, and the one diagnostic code that rule uses.

## Motivation

The constitution leaves the name to the agents. The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Every other choice would mean renaming all of that before any kernel code exists. The cheapest name is the one already in use.

Attempt 1 (RFC 0002) was rejected for four objections. This attempt changes only what the voters objected to:

- **Diagnostic code format (designer-safe, impl-1, tester).** Attempt 1 used `GLY0001`. RFC 0004 section 2 requires `E` followed by four digits, and section 4 assigns blocks. The code is now `E0010`, in the lexical block `E0001`-`E0099`. No other RFC in `rfcs/` uses `E0010`.
- **Wrong owner of `print` (tester).** Attempt 1's run test said `print` comes from RFC 0003. `print` is defined in RFC 0005 (kernel). RFC 0003 is the lexical RFC. The run test now cites RFC 0005.
- **Address example conflict (tester).** RFC 0005 section "Stable addresses" gives the example `main.glyph::add`. That file is not a source file under this RFC. This RFC does not edit RFC 0005. See Open questions.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`. The word "codename" is removed from `README.md` when the first RFC that creates `spec/` is implemented. This RFC does not edit that file.
2. A source file uses the extension `.gl`. The extension is lower case. Take the part of the path after its last `/`. That part is a source file when it ends in `.gl` and has at least one character before `.gl`. Examples: `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. `main.glyph`, `prog.GL`, `main.gl.bak`, `.gl`, `dir/` and the empty string are not.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`, as in the repository's notes. This RFC does not define those subcommands; later RFCs do.
4. Names in this RFC are case-sensitive. `Glyph` is the only spelling of the name in the spec.
5. When `glyphc` is given a path that is not a source file, it does not read the file. It writes exactly one diagnostic record, as defined by RFC 0004 section 2, to stderr, writes nothing to stdout, and exits with status 1:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`. The file is not read, so the span is the start of the file.
   - no `fix`. Renaming the file is the author's choice, not a mechanical edit.
6. The code `E0010` is added to `spec/errors.json` by the first implementing PR, with the message above and the one-line meaning "the path given is not a source file". Codes are never reused. The message passes the RFC 0004 message rules as the message checker in `compiler/stage0/src/message.ts` applies them: a full stop inside `.gl` is not a sentence break (owner ruling, 2026-11-20).

## Alternatives

- **Pick a new name.** Rejected. Every existing file and tool would need changing. Collision with other projects was not checked, because this session has no network access. A later RFC can rename the language if a collision is found.
- **No file extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1.

## Cost

- **Adds:** the name in the spec title and the rule for `.gl` (about 30 tokens in the core spec). One new diagnostic code, `E0010`, with its message (about 20 tokens in the core spec).
- **Removes:** nothing. The word "codename" is already outside the spec.
- **Spec card:** one title line, `Glyph`, and one line `Source: *.gl, compiler glyphc`. Net change is about 10 tokens. The card stays far under its 2,000-token cap.
- **Diagnostics:** one new code, `E0010`, in the lexical block. It is the only code this RFC adds.
- **Grammar:** no production is added, so grammar coverage is unchanged.

## Test plan

- **run:** `conformance/name/run-title.test`. A kernel program `main.gl` prints `Glyph` with `print`. `print` and its text output are defined in RFC 0005 (kernel). This test cannot run until RFC 0005 is accepted and implemented.
- **compile-error:** `compiler/stage0/src/cli.test.ts`. It calls the `run` function of `cli.ts` with fake writers, for each of `check`, `run` and `build`, on `prog.txt`, `PROG.GL`, `main.glyph` and a missing `missing.txt`. Each call writes exactly the one record of Design item 5 to stderr, nothing to stdout, returns 1, and does not read the file (no ENOENT). For `prog.txt` the record is `{"code":"E0010","severity":"error","message":"source file does not end in .gl","span":{"file":"prog.txt","start":0,"end":0,"line":1,"column":1}}` with no `fix` field.
- **unit:** `compiler/stage0/src/source-file.test.ts`. It checks every example in Design item 2 through `isSourceFile`.
- **unit:** `compiler/stage0/src/e0010.test.ts`. The `E0010` entry exists once in `spec/errors.json`, its code is in `E0001`-`E0099`, and its message passes the message checker.

The two conformance files `conformance/name/bad-extension.test` and `conformance/name/upper-extension.test` are not in this plan. The runner writes every input to `main.gl` (see Open questions).

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- **Conformance form of the E0010 cases.** `tools/check/conformance.py` writes every input to `main.gl` and has no meta key that names another input file, so a conformance test cannot give a path that is not a source file. If the runner gains such a key, the two cases in the test plan above should also become conformance files named `conformance/name/bad-extension.test` and `conformance/name/upper-extension.test`, with the same expected record. Until then the node tests are the compile-error tests for this RFC.
- **RFC 0005 must change its address example.** Its `main.glyph::add` must read `main.gl::add` for this RFC and RFC 0005 to agree. This RFC cannot make that change, because RFC 0005 is not its file. Its author or the orchestrator must make the change before RFC 0005 is accepted.
- **Status of the dependency.** The run test depends on RFC 0005, which is currently rejected. If RFC 0005 is not accepted, the run test waits. The compile-error and unit tests do not depend on it.
- Whether the language should also accept a second extension later. This RFC says no. A later RFC must remove or justify any second suffix.
- The name has not been checked against existing software or trademarks. That needs a network check outside this session.

## Owner ruling (2026-11-20)

The one-sentence rule in RFC 0004 section 2 does not treat a full stop inside a file name or extension, such as `.gl` or `main.gl`, as a sentence break. The RFC 0011 message `source file does not end in .gl` is valid as written. The message checker in `compiler/stage0/src/message.ts` must accept it, with a test. This settles the conflict between RFC 0004 and RFC 0011 (issues 54 and 59).
