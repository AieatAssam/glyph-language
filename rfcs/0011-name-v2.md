# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min
Status: draft

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`, as already used in `bin/glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec title, the one source file extension the toolchain needs, and the one diagnostic code that rule uses.

## Motivation

The constitution leaves the name to the agents. The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Every other choice would rename all of that before any kernel code exists. The cheapest name is the one already in use.

The file extension is needed now. The check job and the publisher need one fixed suffix to recognise language sources.

The extension check runs on the file name before the file is read or lexed, so it works even when the content is not valid Glyph. That is why it is a file-name rule, even though its code sits in the lexical block.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`. The word "codename" is removed from the title line of `README.md` by the first implementing PR that creates `spec/`. This RFC does not edit that file.
2. A source file uses the extension `.gl`. The extension is lower case. A path is a source file when its last suffix is exactly `.gl`. A path such as `main.glyph` or `prog.GL` is not a source file.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC does not define those subcommands; later RFCs do.
4. Names in this RFC are case-sensitive. `Glyph` is the only spelling of the name in the spec.
5. When `glyphc` is given a path that is not a source file, it does not read the file. It writes exactly one diagnostic record, as defined by RFC 0004 section 2, to stderr, and exits with a nonzero status. Nothing goes to stdout.
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`. The file is not read, so the span is the start of the file.
   - no `fix`. Renaming the file is the author's choice, not a mechanical edit.
6. The code `E0010` is added to `spec/errors.json` with the message above and the meaning "the path given is not a source file". Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and pick a new name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension question open.
- **Pick a new name.** Rejected. Every existing file and tool would need changing, and no reason is given that outweighs that cost. Collision with other projects was not checked, because this session has no network access. If a collision is found later, a new RFC can rename the language. Renaming is cheap until a release exists.
- **No file extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1.
- **Use a diagnostic code from another prefix.** Rejected. RFC 0004 fixes the `E` plus four digits format.

## Cost

Counted with `tools.check.tokens`:

- **Adds to the core spec:** the title and the `.gl` rule. The spec text is not yet written; the implementing PR measures it. Rule-level estimate only.
- **Adds the message:** `source file does not end in .gl` is 8 tokens.
- **Spec card:** adds the line `Glyph` and the line `Source: *.gl, compiler glyphc`, 10 tokens in total. The card stays far under its 2,000-token cap.
- **Removes:** nothing.
- **Diagnostics:** one new code, `E0010`, in the lexical block. It is the only code this RFC adds.
- **Grammar:** no production is added, so grammar coverage is unchanged.

## Test plan

- **run:** `conformance/name/run-title.test`. A kernel program `main.gl` prints the text `Glyph` with `print`. `print` is spelled as RFC 0113 states it and is defined by the kernel RFC in force.
- **compile-error (CLI):** in `compiler/stage0/src/cli.test.ts`, `glyphc check prog.txt` writes exactly one record on stderr, `{"code":"E0010","severity":"error","message":"source file does not end in .gl","span":{"file":"prog.txt","start":0,"end":0,"line":1,"column":1}}`, with no `fix` field, writes nothing to stdout, and exits nonzero. The test compares `code`, `span` and `fix`.
- **compile-error (CLI):** the same test file, `glyphc check PROG.GL` gives `E0010`, because the extension is lower case only. `glyphc check missing.txt` gives the same record with no read attempt, so no ENOENT appears.
- These file-name cases are node tests, not `.test` files. The conformance runner writes every source to `main.gl`, so it cannot name a file with another name.
- **message check:** `compiler/stage0/src/message.test.ts` asserts that the message `source file does not end in .gl` passes the RFC 0004 message rules. The full stop in `.gl` is not a sentence break.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- Whether the language should also accept a second extension later. This RFC says no. A later RFC must remove or justify any second suffix.
- The name has not been checked against existing software or trademarks. That needs a network check outside this session.


## Owner ruling (2026-11-20)

The one-sentence rule in RFC 0004 section 2 does not treat a full stop inside a file name or extension, such as `.gl` or `main.gl`, as a sentence break. The RFC 0011 message `source file does not end in .gl` is valid as written. The message checker in `compiler/stage0/src/message.ts` must accept it, with a test. This settles the conflict between RFC 0004 and RFC 0011 (issues 54 and 59).
