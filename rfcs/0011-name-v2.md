# RFC draft: The language name

Class: language
Slug: name-v2

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec title, the one source file extension the toolchain needs, and the one diagnostic code that rule uses.

## Motivation

The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Keeping that name costs no renaming. The check job and the publisher need one fixed suffix to recognise language sources, so the suffix is fixed here.

The file-name check runs before the file is read, so it works even when the content is not valid Glyph. That is why its code sits in the lexical block.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`. Names in this RFC are case-sensitive, and `Glyph` is the only spelling the spec uses.
2. A path is a source file when the part after its last `/` ends in `.gl` and has at least one character before `.gl`. The match is case-sensitive. `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/` and the empty string are not.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC defines no behaviour for them beyond item 4.
4. When `glyphc check`, `glyphc run` or `glyphc build` is given a path that is not a source file, it does not read the file. It writes exactly one record to standard error, in the form RFC 0004 section 2 defines, and exits with status 1. Standard output stays empty. The record has these fields, in this order:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`. The file is not read, so the span is the start of the file.
   - no `fix` field. Renaming the file is the author's choice, not a mechanical edit.
5. `E0010` is added to `spec/errors.json` with that message and the meaning "the path given is not a source file". It is the only diagnostic code this RFC adds. Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and decide the name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension question open.
- **Pick a new name.** Rejected. Every existing file and tool would change. Collision with other software has not been checked; a later RFC can rename the language, which stays cheap until a release exists.
- **No file extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1.
- **Use a code with another prefix.** Rejected. RFC 0004 section 2 fixes the `E` followed by four digits form, and section 4 fixes the blocks.

## Cost

Token counts were not measured for this revision. Each implementing PR that adds spec text runs `tools/check/tokens.py` on it before merge.

- **Core spec:** adds the title line `Glyph`, one section stating the `.gl` rule (items 1 to 4 above), and one catalogue entry for `E0010`. No existing text is removed.
- **Spec card:** adds two lines, `Glyph` and `Source: *.gl, compiler glyphc`.
- **Diagnostics:** one new code, `E0010`, in the lexical block.
- **Grammar:** no production is added, so grammar coverage is unchanged.

## Test plan

- **run:** `conformance/name/run-title.test`. Source `fn main() io { print("Glyph") }`. Expected stdout is `Glyph` followed by LF, and expected exit is 0. `print` is defined in RFC 0020 (kernel), section "Entry point and print".
- **compile-error (node):** `compiler/stage0/src/cli.test.ts`. For each of the subcommands `check`, `run` and `build`, and each of the paths `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`, the process writes exactly this line to standard error, writes nothing to standard output, and exits 1: `{"code":"E0010","severity":"error","message":"source file does not end in .gl","span":{"file":"<path>","start":0,"end":0,"line":1,"column":1}}`. No file-read error appears for `missing.txt`.
- **node:** `compiler/stage0/src/source-file.test.ts`. Every path in item 2 gets its stated answer.
- **node:** `compiler/stage0/src/e0010.test.ts`. `E0010` appears exactly once in `spec/errors.json`, with the message and meaning in item 5, and in the lexical block `E0001` to `E0099`. Its message passes the message rules in `compiler/stage0/src/message.ts`.

The compile-error tests are node tests because the conformance runner always writes the input as `main.gl` (`tools/check/conformance.py`), so no `.test` file can give a path that is not a source file.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- Whether the language should accept a second extension later. This RFC says no. A later RFC must justify any second suffix.
- The name has not been checked against existing software or trademarks. That needs a network check outside this session.

## Owner ruling (2026-11-20)

The one-sentence rule in RFC 0004 section 2 does not treat a full stop inside a file name or extension, such as `.gl` or `main.gl`, as a sentence break. The RFC 0011 message `source file does not end in .gl` is valid as written. The message checker in `compiler/stage0/src/message.ts` must accept it, with a test. This settles the conflict between RFC 0004 and RFC 0011 (issues 54 and 59).
