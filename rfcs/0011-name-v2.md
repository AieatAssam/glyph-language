# RFC 0011: The language name

Class: language
Slug: name-v2

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`. This RFC adds no grammar and no runtime behaviour. It fixes the name in the spec, the one source-file suffix the toolchain needs, and one diagnostic code for that rule.

## Motivation

The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Keeping that name costs nothing. The check job and the publisher need one fixed suffix to recognise language sources, so the rule is fixed now.

The check runs on the file name before the file is read, so it works even when the content is not valid Glyph. Its code is in the lexical block because it is a lexical rule about source files.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title in `spec/core.md` is `Glyph`. The title line of `README.md` is `Glyph`, with no codename note.
2. A path is a source file when its last path component ends in exactly `.gl` and has at least one character before `.gl`. The match is case-sensitive. `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/` and the empty string are not.
3. The compiler executable is `glyphc`. This RFC names its subcommands `check`, `run` and `build`. Later RFCs define them.
4. When `glyphc check`, `glyphc run` or `glyphc build` is given a path that is not a source file, it does not open the file. It writes exactly one diagnostic record to stderr, in the form RFC 0004 section 2 defines, with these values:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix` field.

   Nothing is written to stdout. The exit status is 1. The message is one sentence: the full stop inside `.gl` is part of a file name, not a sentence break.
5. `E0010` is added to `spec/errors.json` with the message in item 4 and the meaning `the path given is not a source file`. No other entry changes.
6. `spec/core.md` gains a section that states the `.gl` rule in item 2, names `glyphc` and its three subcommands, and refers to `E0010` by code. `spec/card.md` gains the lines `Glyph` and `Source: *.gl, compiler glyphc`.

## Alternatives

- **Keep the codename and decide the name later.** Rejected. It leaves the extension open, and the toolchain needs it now.
- **Pick a new name.** Rejected. Every existing file and tool would change, and no reason outweighs that cost. Renaming stays cheap while no release exists.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing.
- **No file-extension rule.** Rejected. The publisher and check job need one suffix to find sources.

## Cost

Counted with `tools/check/tokens.py`:

- The run test program `fn main() io { print("Glyph") }` is 10 tokens. It uses only `print(Text)` from RFC 0020, which is in force.
- The two spec card lines `Glyph` and `Source: *.gl, compiler glyphc` are 10 tokens together. The card stays far under its 2,000-token cap.
- The core spec change (the `.gl` section and the `glyphc` line) is not counted in this RFC. The implementing PR must run the counter on `spec/core.md` and report the result. The core stays under 12,000 tokens.
- Removes: nothing.
- Adds: one diagnostic code, `E0010`.
- Grammar: no production is added, so grammar coverage is unchanged.

## Test plan

- **run:** `conformance/name/run-title.test`. Meta: `id: name/run-title`, `rfc: 0011`, `kind: run`. Source: `fn main() io { print("Glyph") }`. Expected stdout: `Glyph`. Expected exit: `0`. `print(Text)` is defined in RFC 0020.
- **compile-error (node tests, `compiler/stage0/src/`):** the source-file rule and the diagnostic cannot be expressed as a conformance `.test`, because the conformance runner always writes its input to `main.gl`. These tests are therefore node tests run by the existing `node --test` gate:
  - `source-file.test.ts`: every path in item 2 gives the stated result.
  - `cli.test.ts`: for each of `check`, `run` and `build`, the paths `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt` each write exactly the record in item 4, to stderr, with exit 1, and nothing to stdout. The file is never opened (a missing file gives no ENOENT). A `.gl` path does not give `E0010`.
  - `e0010.test.ts`: `spec/errors.json` contains `E0010` exactly once; its code is in the range `E0001` to `E0099`; its message passes `checkMessage` in `compiler/stage0/src/message.ts`.

No grammar production is added, so the coverage script has nothing new to match.

## Open questions

- The name has not been checked against existing software or trademarks.
- A later RFC may add a second source suffix. This RFC adds none.
