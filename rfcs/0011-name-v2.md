# RFC 0011: The language name

Class: language
Slug: name-v2
Author: designer-min

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name, the source-file extension, and one diagnostic code, `E0010`, for a path that is not a source file.

## Motivation

The name is already used in `README.md`, `docs/SPEC.md`, `bin/glyphc` and the site. The cheapest name is the one already in use. The check job and the publisher need one fixed suffix to recognise language sources, and the check must run on the file name before the file is read, so it cannot wait for a lexer.

## Design

Normative.

1. The language name is `Glyph`. The spec title is `Glyph`. Names are case-sensitive.
2. A path is a source file when the part after its last `/` ends in `.gl` and has at least one character before `.gl`. The match is case-sensitive. `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/`, and the empty string are not.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. Later RFCs define what they do.
4. When `glyphc check`, `glyphc run` or `glyphc build` is given a path that is not a source file, it does not read the file. It writes exactly one diagnostic record, in the form of RFC 0004 section 2, to standard error, and exits with status 1. Nothing is written to standard output. The record is:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix`. Renaming the file is the author's choice.
5. A message may contain a full stop inside a file name, such as the `.gl` in `source file does not end in .gl`. That full stop does not break the one-sentence rule of RFC 0004 section 2. This is the owner's ruling of 2026-11-20. The message checker must accept the message in item 4.
6. `E0010` is entered in `spec/errors.json` with the message in item 4 and the meaning `the path given is not a source file`.
7. The title line of `README.md` drops `(working codename)` in the change that creates `spec/`.

## Alternatives

- **Keep "Glyph" as a codename and fix the name later.** Rejected. It leaves the extension question open and costs nothing to settle now.
- **Pick a different name.** Rejected. Every file and tool would change, and no reason outweighs that cost. Renaming stays cheap until a release exists.
- **No extension rule.** Rejected. The publisher and check job need one suffix.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name one thing, which breaks constitution principle 1. Any kernel RFC must use `main.gl::add` in its address examples.
- **Use a code prefix other than `E`.** Rejected. RFC 0004 fixes `E` plus four digits.

## Cost

Counted with `tools/check/tokens.py`:

- Core spec, name and extension rule: 25 tokens (`Glyph. Source files end in .gl (lower case, case-sensitive). Compiler: glyphc check|run|build.`).
- Core spec, `E0010` catalogue entry: 21 tokens (`E0010 source file does not end in .gl. The path given is not a source file.`).
- Spec card: 10 tokens (`Glyph` and `Source: *.gl, compiler glyphc`).
- Removes: nothing. Grammar: no production added, so grammar coverage is unchanged.
- Adds one diagnostic code, `E0010`, in the lexical block.

## Test plan

- compile-error, node: `compiler/stage0/src/cli.test.ts`. For `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`, each of `check`, `run` and `build` writes the record in item 4 to standard error, writes nothing to standard output, exits 1, and does not attempt to read the file.
- compile-error, conformance: `conformance/name/bad-extension.test`. Running `glyphc check prog.txt` gives the record in item 4. The runner compares `code`, `span` and `fix` (RFC 0004 section 7). This test needs the conformance runner to pass the test's input file name to `glyphc`, not always `main.gl`.
- compile-error, conformance: `conformance/name/upper-extension.test`. Running `glyphc check PROG.GL` gives `E0010` with the same span. Needs the same runner change.
- check, node: `compiler/stage0/src/e0010.test.ts`. The `E0010` entry exists once in `spec/errors.json` and its code is in `E0001` to `E0099`.
- check, node: `compiler/stage0/src/message.test.ts`. `checkMessage` on the message in item 4 returns no problems.
- run: `conformance/name/run-title.test`. A `main.gl` program prints `Glyph` with `print`. `print` is defined by a kernel RFC, not this one, so this test is written when that RFC defines `print`.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- Whether a second source extension is ever needed. This RFC says no. A later RFC that adds one must remove this rule or justify the second suffix.
