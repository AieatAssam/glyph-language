# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min
Status: draft
Attempt: 2 (replaces RFC 0002, rejected)

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`, as already used in `bin/glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec title, the one source file extension the toolchain needs, and the one diagnostic code that rule uses.

## Motivation

The constitution leaves the name to the agents. The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Every other choice would mean renaming all of that before any kernel code exists.

The file extension is needed now. The check job and the publisher need one fixed suffix to recognise language sources.

Attempt 1 (RFC 0002) was rejected for four objections. This attempt changes only what they objected to:

- **Diagnostic code format.** RFC 0004 section 2 requires `E` followed by four digits, and section 4 assigns blocks. The code is `E0010`, in the lexical block `E0001`-`E0099`. No other RFC uses `E0010`.
- **Owner of `print`.** The run test cites RFC 0005 (kernel), which defines `print`. RFC 0003 is the lexical RFC.
- **Address example.** RFC 0005 gives `main.glyph::add`. Under this RFC that is not a source file. The correct example is `main.gl::add`. RFC 0005 must be corrected if it is revived. This RFC does not edit it.

The check runs on the file name before the file is read, so it works even when the content is not valid Glyph. That is why it is a file-name rule, even though its code sits in the lexical block.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`. This RFC does not edit `README.md`.
2. A source file uses the extension `.gl`, in lower case. A path is a source file when the part after its last `/` ends in `.gl` and has at least one character before the `.gl`. The match is case-sensitive. So `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/` and the empty string are not.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC does not define them; later RFCs do.
4. Names in this RFC are case-sensitive. `Glyph` is the only spelling of the name in the spec.
5. When `glyphc check`, `glyphc run` or `glyphc build` is given a path that is not a source file, it does not open the file. It writes exactly one line to standard error, a diagnostic record as defined by RFC 0004 section 2, and exits with status 1. Nothing is written to standard output. The record is:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`. The file is not read, so the span is the start of the file.
   - no `fix`. Renaming the file is the author's choice, not a mechanical edit.
6. The code `E0010` is recorded in `spec/errors.json` with the message above and the meaning "the path given is not a source file". Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and pick a new name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension question open.
- **Pick a new name.** Rejected. Every existing file and tool would need changing. Collision with other projects was not checked, because this session has no network access. A later RFC can rename the language while renaming is still cheap.
- **No file extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1.
- **Use a diagnostic code from another prefix.** Rejected. RFC 0004 fixes the `E` plus four digits format.

## Cost

Counted with `tools/check/tokens.py` on the spec core and card as they stand after the name is added.

- **Adds to the core spec:** the name in the title and the `.gl` rule (about 30 tokens). The `E0010` line with its message (about 20 tokens).
- **Removes:** nothing.
- **Spec card:** one title line `Glyph` and one line `Source: *.gl, compiler glyphc`. Net change about 10 tokens.
- **Grammar:** no production is added, so grammar coverage is unchanged.

## Test plan

- **run:** `conformance/name/run-title.test`. A kernel program `main.gl` prints `Glyph` with `print`, which RFC 0005 defines. It cannot run until an accepted kernel RFC defines `print`.
- **compile-error (node):** `compiler/stage0/src/cli.test.ts`. For each of `check`, `run` and `build`, and each of `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`, `run` returns 1, writes exactly the record in Design 5 to standard error, writes nothing to standard output, and does not try to open the file. The record is compared on `code`, `span` and the absence of `fix`.
- **Source-file rule (node):** `compiler/stage0/src/source-file.test.ts` tests the accepted and rejected paths in Design 2.

The compile-error cases are node tests because the conformance runner writes every `.test` source to `main.gl` and gives no way to name another input file. A file-name rule cannot be tested that way. If the runner gains an input-name key, a conformance test may replace these cases in a later RFC.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- Whether a second source extension should be accepted later. This RFC says no. A later RFC must remove or justify any second suffix.
- The name has not been checked against existing software or trademarks. That needs a network check outside this session.
- The conformance runner cannot give a `.test` an input file name. An architect change to `tools/` would allow conformance tests for file-name rules.


## Owner ruling (2026-11-20)

The one-sentence rule in RFC 0004 section 2 does not treat a full stop inside a file name or extension, such as `.gl` or `main.gl`, as a sentence break. The RFC 0011 message `source file does not end in .gl` is valid as written. The message checker in `compiler/stage0/src/message.ts` must accept it, with a test. This settles the conflict between RFC 0004 and RFC 0011 (issues 54 and 59).
