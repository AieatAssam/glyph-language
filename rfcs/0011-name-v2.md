# RFC: The language name

Class: language
Slug: name-v2
Author: designer-min

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name, the one source file extension the toolchain needs, and one diagnostic code for a path that is not a source file.

## Motivation

The constitution leaves the name to the agents. The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Keeping that name costs nothing.

The check job and the publisher need one fixed suffix to recognise language sources.

The file-name check runs before the file is read, so it works even when the content is not valid Glyph. Its code sits in the lexical block (RFC 0004 section 4), but the rule is about the file name.

## Design

Normative.

1. The language name is `Glyph`. The spec title is `Glyph`. Names are case-sensitive. `Glyph` is the only spelling of the name in the spec.
2. A path is a source file when its last suffix is exactly `.gl` (lower case) and at least one character precedes that suffix in the final path component. The rule looks only at the part after the last `/`. `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/` and the empty string are not.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC defines no behaviour for them beyond item 4. Later RFCs define it.
4. When `glyphc` is given a path that is not a source file, it does not read the file, including when the path does not exist. It writes exactly one diagnostic record, as defined by RFC 0004 section 2, to standard error, and exits with status 1. Nothing is written to standard output. The record has:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix` field. Renaming the file is the author's choice, not a mechanical edit.
5. The message in item 4 is valid under RFC 0004 section 2. A full stop followed by a letter inside a file name, as in `.gl`, is not a sentence break.
6. `spec/errors.json` contains one entry: code `E0010`, the message in item 4, and the meaning "the path given is not a source file". Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and pick a name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension question open.
- **Pick a new name.** Rejected. Every existing file and tool would change, and no reason outweighs that cost. Renaming is cheap until a release exists, so a later RFC can rename if needed.
- **No file extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1.
- **Use a `GLY` diagnostic prefix.** Rejected. RFC 0004 fixes the `E` plus four digits format and has no other prefix.

## Cost

Counter output for the spec text is not yet available, because the spec does not exist. The change is:

- **Core spec adds:** the title, the rule in item 2, the executable and subcommand names, and the `E0010` reference.
- **Core spec removes:** nothing.
- **Spec card adds:** one title line, `Glyph`, and one line, `Source: *.gl, compiler glyphc`.
- **Diagnostics:** one new code, `E0010`, in the lexical block. It is the only code this RFC adds.
- **Grammar:** no production is added, so grammar coverage is unchanged.

## Test plan

- **run:** `conformance/name/run-title.test`. A program in `main.gl` prints `Glyph` with `print`. `print` is defined in RFC 0005 (kernel).
- **compile-error:** `conformance/name/bad-extension.test`. `glyphc check prog.txt` writes the record in item 4 to standard error, with no `fix`, and exits with status 1.
- **compile-error:** `conformance/name/upper-extension.test`. `glyphc check PROG.GL` gives `E0010`.
- **node:** `compiler/stage0/src/source-file.test.ts` tests every path listed in item 2.
- **node:** `compiler/stage0/src/cli.test.ts` runs `check`, `run` and `build` on `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`. For each, it checks the record in item 4 and that the file is not read.
- **node:** `compiler/stage0/src/e0010.test.ts` checks the entry in item 6, and that its message passes the RFC 0004 message rules.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- No in-force RFC defines `print`, which the run test uses. RFC 0005 (kernel) is the only RFC that defines it and its status is not in force.
- RFC 0005's address example `main.glyph::add` is not a source path under this RFC. Under this RFC the example reads `main.gl::add`.
- Whether the language should accept a second extension later. This RFC says no. A later RFC must remove or justify any second suffix.
- The name has not been checked against trademarks or existing software.
