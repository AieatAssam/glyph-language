# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min
Status: draft
Attempt: 2 (replaces RFC 0002, rejected)

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`, as already used in `bin/glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec title, the one source file extension the toolchain needs, and the one diagnostic code that rule uses.

## Motivation

The constitution leaves the name to the agents. The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Every other choice would mean renaming all of that before any kernel code exists. The cheapest name is the one already in use.

The file extension is needed now. The check job and the publisher need one fixed suffix to recognise language sources. Without an RFC, each component would pick its own.

Attempt 1 (RFC 0002) was rejected for four objections. This attempt keeps everything the voters accepted and changes only what they objected to:

- **Diagnostic code format (designer-safe, impl-1, tester).** Attempt 1 used `GLY0001`. RFC 0004 section 2 requires `E` followed by four digits, and section 4 assigns blocks. The code is now `E0010`, in the lexical block `E0001`-`E0099`. No other RFC in `rfcs/` uses `E0010`.
- **Wrong owner of `print` (tester).** Attempt 1's run test said `print` comes from RFC 0003. Attempt 2 cited RFC 0005, which is now rejected. Revision 3 (below) cites the accepted kernel, RFC 0105.
- **Address example conflict (tester).** RFC 0005 gives the example `main.glyph::add`. The suffix `.glyph` is not `.gl`, so under this RFC that file is not a source file. RFC 0005 is rejected, so its example binds nothing. Any later RFC that writes an address example must use `.gl`.

The check runs on the file name before the file is lexed, so it works even when the content is not valid Glyph. That is why it is a file-name rule, even though its code sits in the lexical block.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`. The spec is `spec/core/` with `spec/card.md`. The word "codename" is removed from `README.md` when the first PR that creates `spec/` is merged. This RFC does not edit that file.
2. A source file uses the extension `.gl`. The extension is lower case. A path is a source file when its last suffix is exactly `.gl`, and the part before it is not empty. A path such as `main.glyph`, `prog.GL`, `.gl` or `dir/` is not a source file.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`, as in the repository's notes. This RFC does not define those subcommands; later RFCs do.
4. Names in this RFC are case-sensitive. `Glyph` is the only spelling of the name in the spec.
5. When `glyphc` is given a path that is not a source file, it does not read the file. It writes exactly one diagnostic record to standard error, and exits with status `1`. The record has:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`. The file is not read, so the span is the start of the file.
   - no `fix`. Renaming the file is the author's choice, not a mechanical edit.
   Nothing is written to standard output. Status `1` is the status for a compile error in `tools/check/conformance.py`, and the status `glyphc` uses for all three subcommands.
6. The code `E0010` is in `spec/errors.json` with the message above and the meaning "the path given is not a source file". Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and pick a new name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension question open.
- **Pick a new name.** Rejected. Every existing file and tool would need changing, and no reason is given that outweighs that cost. Collision with other projects was not checked, because this session has no network access. If a collision is found later, a new RFC can rename the language. Renaming is cheap until a release exists.
- **No file extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1.
- **Use a diagnostic code from the `GLY` prefix.** Rejected. RFC 0004 fixes the `E` plus four digits format and has no other prefix.
- **Add conformance `.test` files for the non-source paths.** Rejected for now. The runner writes every source to `main.gl` and has no key that names another input, so no `.test` can give `glyphc` a path such as `prog.txt`. Open question 1 asks for the runner change. Until then the same cases are tested by node tests.

## Cost

Estimates from the attempt 2 text; not re-measured in revision 3.

- **Adds:** the name in the spec title and the rule for `.gl` (about 30 tokens in the core spec). One new diagnostic code, `E0010`, with its message (about 20 tokens in the core spec).
- **Removes:** nothing. The word "codename" is already outside the spec.
- **Spec card:** one title line, `Glyph`, and one line `Source: *.gl, compiler glyphc`. Net change is about 10 tokens. The card stays far under its 2,000-token cap.
- **Diagnostics:** one new code, `E0010`, in the lexical block. It is the only code this RFC adds.
- **Grammar:** no production is added, so grammar coverage is unchanged.

## Test plan

- **run:** `conformance/name/run-title.test`, with id `name/run-title`, rfc `0011`, kind `run`. The source is `main io{put"Glyph"}`. `expect-stdout` is `Glyph` and `expect-exit` is `0`. The form `put` with a text literal is RFC 0105 (kernel-v46, accepted), P1, P2 and T3. The test needs a compiler that implements RFC 0105. It does not need any rejected RFC.
- **compile-error (node tests, not conformance):** the E0010 behaviour is tested in the `node --test` gate:
  - `compiler/stage0/src/cli.test.ts`: a path that is not a source file (`prog.txt`, `dir/prog.txt`, and the other cases in the test) gives the one E0010 record on standard error, no standard output, and status `1`, for each of `check`, `run` and `build`.
  - `compiler/stage0/src/source-file.test.ts`: the source-file rule, including `PROG.GL`, `main.glyph`, `main.gl.bak` and the empty name.
  - `compiler/stage0/src/e0010.test.ts`: the catalogue entry.
  The conformance `.test` files for `prog.txt` and `PROG.GL` are not added. Open question 1 explains why. Until the runner changes, the RFC's "at least one compile-error test" rule is met only by these node tests. That is an exception the owner or architect must rule on.
- When the runner can take an input name, the expected record for `prog.txt` is `{"code":"E0010","span":{"start":0,"end":0}}`, with no `fix`. The runner matches only the keys it is given, so this expectation holds under either record shape in open question 2.

No grammar production is added, so the coverage script has nothing new to match.

## Open questions

1. **Runner input name (architect; `tools/`).** `tools/check/conformance.py` writes every `.test` source to `main.gl` (line 212). A conformance test for a non-source path needs a meta key, for example `input`, that names the file the runner writes. This RFC cannot add it. Until it exists, the E0010 cases are covered by the node tests in the Test plan.
2. **Record shape (owner ruling needed).** RFC 0004 section 2 (accepted) gives records the keys `code`, `severity`, `message`, and `span` with `file`, `line` and `column`. RFC 0050 section 2 (accepted) gives the keys `code`, `severity`, `span` (with `start` and `end` only) and `fix`, and no `message`. RFC 0104 (accepted) amends RFC 0050's record-shape line. This RFC does not choose between them. The E0010 record must follow whichever rule is in force. The owner ruling below applies to the `message` key only while a record carries one.
3. **Run test status.** RFC 0105 is accepted, but the run test passes only when the compiler implements its `put` form. The orchestrator should update `rfcs/0011.plan.md` subtask 7, which still names RFC 0005 or RFC 0013 as the blocker.
4. The second-extension question: this RFC says no. A later RFC must remove or justify any second suffix.
5. The name has not been checked against existing software or trademarks. That needs a network check outside this session.

## Owner ruling (2026-11-20)

The one-sentence rule in RFC 0004 section 2 does not treat a full stop inside a file name or extension, such as `.gl` or `main.gl`, as a sentence break. The RFC 0011 message `source file does not end in .gl` is valid as written. The message checker in `compiler/stage0/src/message.ts` must accept it, with a test. This settles the conflict between RFC 0004 and RFC 0011 (issues 54 and 59). It does not settle open question 2.
