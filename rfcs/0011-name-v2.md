# RFC 0011: The language name

Class: language
Slug: name-v2

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name, the source-file rule, and one diagnostic code, `E0010`.

## Motivation

The repository already uses the name Glyph in `README.md`, `docs/SPEC.md` and `bin/glyphc`. Keeping it costs nothing.

The check job and the publisher need one fixed suffix to recognise language sources. The source-file check runs on the path before the file is read, so it works even when the content is not valid Glyph. That is why it is a rule about the path and not about the lexer.

The message `source file does not end in .gl` contains a full stop inside a file extension. RFC 0004 section 2 does not treat that full stop as a sentence break (owner ruling, 2026-11-20). The message is valid as written, and the message checker must accept it.

## Design

Normative.

1. The language name is `Glyph`. The spec title is `Glyph`. Names are case-sensitive, and `Glyph` is the only spelling.
2. A path is a source file when its last suffix is exactly `.gl`, case-sensitive, and at least one character comes before `.gl` in the final path segment. A path ending in `/` is not a source file. Examples. Source files: `main.gl`, `dir/prog.gl`, `a.b.gl`. Not source files: `.gl`, `dir/`, the empty string, `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC defines no behaviour for them beyond rule 4.
4. When `glyphc` is given a path that is not a source file, with any subcommand, it does not read the file. It writes exactly one diagnostic record, as RFC 0004 section 2 defines it, and exits with status 1. Nothing is written to stdout. The record has:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix`. Renaming the file is the author's choice, not a mechanical edit.
5. `spec/errors.json` lists `E0010` with message `source file does not end in .gl` and meaning `the path given is not a source file`. Codes are never reused.
6. The message checker accepts a full stop that sits inside a file name or extension, such as the one in `.gl`. A full stop followed by a space or by the end of the message still ends a sentence.

## Alternatives

- **Keep "Glyph" as a codename.** Rejected. It leaves the extension question open, and settling it now costs nothing.
- **Pick a new name.** Rejected. Every file and tool would change, and no reason outweighs that cost. Collision with other software was not checked. If a collision is found, a later RFC can rename the language while renaming is still cheap.
- **No extension rule.** Rejected. The check job and publisher need one suffix.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second spelling of the same thing, which breaks principle 1.
- **A `GLY` diagnostic prefix.** Rejected. RFC 0004 fixes the `E` plus four digits form.

## Cost

Counted with `tools/check/tokens.py` on the text each section adds.

- **Core spec:** the section below adds 114 tokens. It is the title, rules 2 and 4 in prose, and the `E0010` reference.

  ```
  # Glyph

  A source file is a path whose name has at least one character before the last suffix, which is exactly `.gl`. Matching is case-sensitive.
  The compiler is `glyphc`, with subcommands `check`, `run` and `build`.
  A path that is not a source file is not read. `glyphc` writes one diagnostic: code `E0010`, message `source file does not end in .gl`, span start 0, end 0, line 1, column 1, no fix. It exits 1.
  ```

- **Spec card:** adds 11 tokens, `# Glyph` and `Source: *.gl, compiler glyphc`. The card cap is 2,000 tokens.
- **Removes:** nothing.
- **Grammar:** no production is added, so grammar coverage does not change.
- **Diagnostics:** one code, `E0010`, in the lexical block E0001 to E0099.
- **Example programs:** none. The inputs in the test plan are file paths, not Glyph source.

## Test plan

- **run:** `conformance/name/run-title.test`. A `main.gl` prints `Glyph`. The expected output depends on `print` as defined by the kernel RFC in force.
- **compile-error:** `compiler/stage0/src/cli.test.ts`. For each of `check`, `run` and `build`, the paths `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt` each produce exactly the record in Design rule 4, exit with status 1, write nothing to stdout, and do not raise ENOENT. `main.gl` does not produce `E0010`. These are node tests because the conformance runner gives every source the file name `main.gl`, so it cannot supply the other paths.
- **node:** `compiler/stage0/src/source-file.test.ts`. Every example in Design rule 2 gives the stated answer.
- **node:** `compiler/stage0/src/e0010.test.ts`. `E0010` is listed exactly once in `spec/errors.json`, with the message and meaning of Design rule 5.
- **node:** `compiler/stage0/src/message.test.ts`. `source file does not end in .gl` passes the message rules. `see main.gl. then retry` breaks the one-sentence rule.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- A second extension may be wanted later. This RFC allows only `.gl`. A later RFC must justify any second suffix.
- The name has not been checked against existing software or trademarks.
- The RFC 0005 kernel example `main.glyph::add` uses a suffix this RFC does not allow. Its author should correct it to `main.gl::add`.
