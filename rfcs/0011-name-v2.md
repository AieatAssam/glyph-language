# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name, the one source file extension the toolchain needs, and the one diagnostic code that rule uses.

## Motivation

The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Renaming would touch all of them and gain nothing. The check job and the publisher need one fixed suffix to recognise language sources, and the file-name check must run before a file is read, so it works even when the content is not valid Glyph.

## Design

Normative.

1. The language is named `Glyph`. The spec title is `Glyph`. Names are case-sensitive. `Glyph` is the only spelling.
2. A path is a source file when the part after its last `/` ends in `.gl` and has at least one character before `.gl`. The match is case-sensitive. So `main.gl` and `dir/prog.gl` are source files. `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/` and the empty string are not.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC does not define what they do.
4. When `glyphc check`, `glyphc run` or `glyphc build` is given a path that is not a source file, it does not open the file, whether or not the file exists. It writes one record to stderr in the JSON Lines form of RFC 0004 section 2, with these fields:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix` field

   It writes nothing to stdout and exits with status 1.
5. The one-sentence rule of RFC 0004 section 2 does not treat a full stop inside a file name or extension, such as the `.` in `.gl` or `main.gl`, as a sentence break. The message in item 4 is therefore one sentence and is valid as written. `compiler/stage0/src/message.ts` must accept it.
6. `E0010` is the code of the rule in item 4. Its entry in `spec/errors.json` has the message in item 4 and the meaning `the path given is not a source file`. Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and pick a name later.** Rejected. It leaves the extension question open for no gain.
- **Pick a new name.** Rejected. Every existing file and tool would change. Collision with other software was not checked. A later RFC can rename the language, and renaming is cheap before a release exists.
- **No extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same file, which breaks principle 1.
- **A `GLY` code prefix.** Rejected. RFC 0004 fixes the `E` plus four digits format.

## Cost

Measured with `tools/check/tokens.py`:

- The E0010 message, `source file does not end in .gl`: 8 tokens.
- The E0010 record of item 4 as one JSON line: 45 tokens.
- The card's source line, `Source: *.gl, compiler glyphc`: 8 tokens. The card also gets the title line `Glyph`, which was not counted separately.

Changes:

- **Adds:** the name, the rule of item 2, the subcommand names of item 3, and the record of item 4 to the core spec. The core spec count is not measured here, because `spec/` does not exist yet. The merge bot checks it when the file is written.
- **Removes:** nothing.
- **Card:** the title line `Glyph` and the source line above.
- **Diagnostics:** one code, `E0010`, in the lexical block `E0001` to `E0099`. No other code is added.
- **Grammar:** no production is added, so grammar coverage is unchanged.

## Test plan

- **compile-error (node, buildable now):** these tests need no lexer and no kernel.
  - `compiler/stage0/src/source-file.test.ts`: every case in item 2.
  - `compiler/stage0/src/cli.test.ts`: for each of `check`, `run` and `build`, and each of the paths `prog.txt`, `PROG.GL`, `main.glyph`, `missing.txt` and `dir/prog.txt`, the exact record of item 4, exit status 1 and empty stdout.
  - `compiler/stage0/src/e0010.test.ts`: the `E0010` entry in `spec/errors.json` appears exactly once, its code lies in `E0001` to `E0099`, and its message passes the rules of `compiler/stage0/src/message.ts`.
- **run:** `conformance/name/run-title.test`. A `main.gl` calls the output builtin `print` of the kernel RFC in force with the text `Glyph`. It expects stdout `Glyph` and exit status 0. Its meta block has `id`, `rfc: 0011` and `kind: run`.
- **compile-error (conformance):** `conformance/name/bad-extension.test` runs `glyphc check prog.txt` and `conformance/name/upper-extension.test` runs `glyphc check PROG.GL`. Each expects the record of item 4 with `E0010`. Its meta block has `id`, `rfc: 0011` and `kind: compile-error`. The conformance runner currently gives every input the file name `main.gl`, so it cannot pass these names. Until it can, the node tests above are the coverage of this rule.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- RFC 0005 uses the address example `main.glyph::add`. Under item 2 it would read `main.gl::add`. That file is not this RFC's file, so this RFC does not change it.
- The name has not been checked against existing software or trademarks. That needs a network check outside this session.
