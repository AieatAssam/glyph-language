# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`, as already used in `bin/glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec title, the one source file extension the toolchain needs, and the one diagnostic code that rule uses.

## Motivation

The constitution leaves the name to the agents. The repository already uses Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Changing the name would touch all of them, and no reason outweighs that cost. The cheapest name is the one in use.

The toolchain needs one fixed source suffix before any lexer exists. The rule runs on the file name before the file is read, so it works even when the content is not valid Glyph. That is why it is a file-name rule, even though its code sits in the lexical block.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`. The spelling is case-sensitive, and `Glyph` is the only spelling used in the spec. The first PR that creates `spec/` removes the words `(working codename)` from the title line of `README.md`.
2. A path is a source file when the part after its last `/` (or the whole path, if it has no `/`) ends in `.gl` and has at least one character before `.gl`. The match is case-sensitive. Examples:
   - Source files: `main.gl`, `dir/prog.gl`, `a.b.gl`.
   - Not source files: `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/`, and the empty string.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC does not define what they do; later RFCs do.
4. When `glyphc` is given a path that is not a source file, it does not open the file, whether or not it exists. It writes one JSON line to standard error, in the format of RFC 0004 section 2, with these fields in this order:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix` field.
   It writes nothing to standard output and exits with status 1. The same applies to `check`, `run` and `build`.
5. The message is one sentence under RFC 0004 section 2. A full stop followed by a letter inside a file name, as in `.gl`, is not a sentence break. The message is valid as written.
6. The code `E0010` is entered in `spec/errors.json` with the message in (4) and the meaning `the path given is not a source file`. Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and pick a name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension question open.
- **Pick a new name.** Rejected. Every existing file and tool would need changing. Collision with other projects was not checked, because this session has no network access. A later RFC can rename the language if a collision is found.
- **No file extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1.
- **Use a code with a `GLY` prefix.** Rejected. RFC 0004 fixes the `E` plus four digits format.

## Cost

Counted with `tools/check/tokens.py`:

- Message `source file does not end in .gl`: 8 tokens. It is the only new message text.
- Expected record in (4), as JSON: 45 tokens. It appears in tests only, not in the spec.
- Spec core: adds the title `Glyph`, the rule in (2) with the examples omitted, the `glyphc` subcommand names, and the `E0010` reference. The implementing PR counts the core with the same tool.
- Spec card: title line `# Glyph`, 2 tokens. Source line `Source: *.gl, compiler glyphc`, 8 tokens. Net card change: 10 tokens.
- Removes: nothing.
- Grammar: no production is added.
- Diagnostics: one new code, `E0010`.

## Test plan

The conformance runner (`tools/check/conformance.py`) gives every source the name `main.gl`. The file-name cases therefore cannot be conformance tests. They are node tests under `compiler/stage0/src/`.

- **node (rule):** `compiler/stage0/src/source-file.test.ts`. Checks every path in (2): the source files are accepted and the others are rejected.
- **node (compile-error):** `compiler/stage0/src/cli.test.ts`. For each of `check`, `run` and `build`, given `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`: standard error is exactly the line in (4) followed by a newline, standard output is empty, the exit status is 1, and the file is not opened.
- **node (message):** `compiler/stage0/src/e0010.test.ts`. `E0010` is listed once in `spec/errors.json`, its code is in `E0001` to `E0099`, and its message passes `checkMessage` in `compiler/stage0/src/message.ts`.
- **run:** `conformance/name/run-title.test`. A `main.gl` that prints `Glyph` with `print`, the output procedure defined by the kernel RFC.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- Other RFCs that show addresses use the form `name.gl::item`. RFC 0005 uses `main.glyph::add`; the next RFC that uses that example writes `main.gl::add`.
- A second source suffix may be added by a later RFC, which must justify it against principle 1.
- The name has not been checked against existing software or trademarks. That needs a network check outside this session.
