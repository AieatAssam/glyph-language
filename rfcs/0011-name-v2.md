# RFC draft: The language name

Class: language. Slug: name-v2. Author: designer-min.

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler executable is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name, the one source file suffix, and the one diagnostic for a path without that suffix.

## Motivation

The repository already uses the name Glyph in `README.md`, `docs/SPEC.md`, the compiler command `bin/glyphc` and the site. Choosing another name would rename all of them before any kernel code exists.

The check and the publisher need one fixed suffix to recognise language sources. Without a rule, each component would choose its own.

The file-suffix check runs on the path before the file is read, so it works even when the content is not valid Glyph. Its code is in the lexical block because it is a lexical-level rejection of an input, not a syntax error.

## Design

Normative.

1. The language name is `Glyph`, case-sensitive. The spec core begins with the title line `Glyph`.
2. A path is a source file when its last suffix is exactly `.gl`. The suffix is case-sensitive: `prog.GL` is not a source file. The check looks only at the text of the path. The file is not opened to make it.
3. The compiler executable is `glyphc`. Its subcommands `check`, `run` and `build` are named here and defined by later RFCs.
4. When `glyphc check`, `glyphc run` or `glyphc build` is given a path that is not a source file, it does these steps, in this order, before any other work:
   a. It does not open or read the path. A missing path gives the same result as an existing one.
   b. It writes exactly one record to standard error, as one JSON line in the form of RFC 0004 section 2, with these values:
      - `code`: `E0010`
      - `severity`: `error`
      - `message`: `source file does not end in .gl`. A full stop inside a file extension is not a sentence break under RFC 0004 section 2.
      - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
      - no `fix` field.
   c. It writes nothing to standard output and exits with status 1.
5. `spec/errors.json` contains exactly one entry for this rule: code `E0010`, message `source file does not end in .gl`, meaning `the path given is not a source file`. Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and decide later.** Rejected. The extension rule is needed now, and it cannot be written without a name.
- **Pick a new name.** Rejected. It renames every existing file and tool, and nothing in the repository argues for it. Collisions with other projects were not checked; a later RFC can rename the language if one is found.
- **No suffix rule.** Rejected. The publisher and the check need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same file, which breaks principle 1.
- **A code with another prefix.** Rejected. RFC 0004 section 2 fixes the form `E` followed by four digits.

## Cost

Counted with `tools/check/tokens.py`:

- Core spec: the rules in Design 1 to 5, as written in the spec, are 80 tokens. No other core text changes.
- Spec card: the lines `Glyph` and `Source: *.gl, compiler glyphc` are 10 tokens.
- Diagnostics: one new code, `E0010`. It is the only code this RFC adds.
- Grammar: no production is added, so the grammar and its coverage are unchanged.
- Removes: nothing.

## Test plan

- **run:** `conformance/name/run-empty-gl.test`. Input `main.gl` is a zero-byte file. Expected: exit status 0, no lines on standard error, no lines on standard output. A zero-byte file has no tokens, so no lexical rule fires. This is the same check as RFC 0004 `diag/no-output-clean.test`, pinned to the source-file name.
- **compile-error, file name:** the conformance runner gives every source the name `main.gl`, so the file-name cases cannot be conformance tests. They are node tests in `compiler/stage0/src/e0010.test.ts`. For each of `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`, and for each of `check`, `run` and `build`, the test asserts: standard error is exactly the one JSON line in Design 4b, standard output is empty, the exit status is 1, and the file system was not read.
- **message:** the same node test asserts that the message `source file does not end in .gl` passes the RFC 0004 section 2 message rule, with the full stop inside `.gl` not treated as a sentence break.
- **catalogue:** the entry in `spec/errors.json` exists exactly once, with code `E0010` in the range `E0001` to `E0099`.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- Whether a second source suffix is ever wanted. This RFC allows only `.gl`. A later RFC must justify any second suffix and remove this rule's exclusivity.
- Whether the name has been checked against existing software or trademarks. That needs a network check, which this RFC does not do.
