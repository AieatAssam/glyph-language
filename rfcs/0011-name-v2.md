# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min
Status: draft
Attempt: 2 (replaces RFC 0002, rejected)

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`, as already used in `bin/glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec title, the one source file extension the toolchain needs, and the one diagnostic code that rule uses.

## Motivation

The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Changing the name would mean renaming all of that before any kernel code exists. The file extension is needed now: the check job and the publisher need one fixed suffix to recognise language sources.

The rule reads the file name before the file is opened or lexed, so it works even when the content is not valid Glyph. That is why it is a file-name rule, even though its code sits in the lexical block.

The code is `E0010`, in the lexical block E0001 to E0099 of RFC 0004 section 4. Its message follows the message rules of RFC 0004 section 2. The owner ruling below settles how a full stop inside a file name is read.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`. The word "codename" is removed from `README.md` by the PR that first creates `spec/`. This RFC does not edit that file.
2. A source file uses the extension `.gl`, in lower case. A path is a source file when the part after its last `/` ends in `.gl` and has at least one character before `.gl`. Matching is case-sensitive. These are not source files: `main.glyph`, `prog.GL`, `main.gl.bak`, `.gl`, `dir/` and the empty string.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. Later RFCs define what they do.
4. `Glyph` is the only spelling of the name in the spec.
5. When `check`, `run` or `build` is given a path that is not a source file, `glyphc` does not open the file. It writes nothing to standard output. It writes exactly one line to standard error, a JSON Lines record as defined by RFC 0004 section 2, with these fields:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`. The file is not read, so the span is the start of the file.
   - no `fix` field.

   It then exits with status 1.
6. `E0010` is added to `spec/errors.json` by the implementing PR, with the message above and the meaning "the path given is not a source file". Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and pick a name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension open.
- **A different name.** Rejected. Every existing file and tool would change, and no reason outweighs that cost. Collision with other software was not checked, because this session has no network access. A later RFC can rename the language if a collision is found; renaming is cheap before a release.
- **No extension rule.** Rejected. The publisher and check job need one suffix.
- **Accept `.glyph` as well.** Rejected. A second suffix is a second way to name one thing, which breaks principle 1.
- **A `GLY` code prefix.** Rejected. RFC 0004 fixes `E` plus four digits.

## Cost

Counted with `tools.check.tokens`:

- The title word `Glyph`: 1 token.
- The card lines `Glyph` and `Source: *.gl, compiler glyphc`: the second is 8 tokens. The card stays far under its 2,000-token cap.
- The E0010 message `source file does not end in .gl`: 8 tokens in `spec/errors.json`.
- The core spec's added rule text (Design 2 to 5) is counted by the implementing PR, which must keep the core under 12,000 tokens.
- **Removes:** nothing.
- **Diagnostics:** one new code, `E0010`. It is the only code this RFC adds.
- **Grammar:** no production is added, so grammar coverage is unchanged.

For each of `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`, and for each of `check`, `run` and `build`: stdout is empty; stderr is exactly the one record in Design 5; the exit status is 1; no file-open error is reported, so `missing.txt` gives the same record as the others.
- **name rule (node):** `compiler/stage0/src/source-file.test.ts`. Every path listed in Design 2 gives the stated result.
- **message (node):** `compiler/stage0/src/message.test.ts`. `source file does not end in .gl` passes the RFC 0004 message rules.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- Whether the language should accept a second extension later. This RFC says no. A later RFC must remove or justify any second suffix.
- The name has not been checked against existing software or trademarks. That needs a network check outside this session.

## Owner ruling (2026-11-20)

The one-sentence rule in RFC 0004 section 2 does not treat a full stop inside a file name or extension, such as `.gl` or `main.gl`, as a sentence break. The RFC 0011 message `source file does not end in .gl` is valid as written. The message checker in `compiler/stage0/src/message.ts` must accept it, with a test. This settles the conflict between RFC 0004 and RFC 0011 (issues 54 and 59).
