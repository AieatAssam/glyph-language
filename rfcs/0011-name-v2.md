# RFC 0011: The language name

Class: language
Slug: name-v2
Author: designer-min

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the spec title, the source-file rule, and the one diagnostic code that rule uses.

## Motivation

The repository already calls the language Glyph (`README.md`, `docs/SPEC.md`, `bin/glyphc`). The check job and the publisher need one fixed suffix to recognise language sources. The source-file rule is a file-name rule. It applies before the file is read or lexed, so it works on content that is not valid Glyph, which is why its code sits in the lexical block.

## Design

Normative.

1. The language is named `Glyph`. The spec title is `Glyph`. Names are case-sensitive, and `Glyph` is the only spelling.
2. Take the part of a path after its last `/`, or the whole path if it has no `/`. The path is a source file when that part ends in `.gl` and has at least one character before `.gl`. The match is case-sensitive. Examples. Source files: `main.gl`, `dir/prog.gl`, `a.b.gl`. Not source files: `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/`, and the empty string.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC does not define what they do.
4. When `glyphc check`, `glyphc run` or `glyphc build` is given a path that is not a source file, it does not open the file. It writes exactly one record to stderr, in the form that RFC 0004 section 2 defines, with these values:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix` field.
   It writes nothing to stdout. Its exit status is `1`, the status for a compile error. The same rule holds for a path that does not exist, because the file is not opened.
5. `spec/errors.json` gains one entry: `{"code":"E0010","message":"source file does not end in .gl","meaning":"the path given is not a source file"}`. Codes are never reused.
6. The message is valid under RFC 0004 section 2. A full stop inside a file name is not a sentence break (owner ruling, 2026-11-20). The checker in `compiler/stage0/src/message.ts` accepts the message, and its test covers that case.
7. `spec/core.md` gains a section with the title `Glyph`, the source-file rule of item 2 in short form, the executable `glyphc` with its three subcommands named, and a reference to `E0010` by code. `spec/card.md` gains the title line `Glyph` and the line `Source: *.gl, compiler glyphc`.
8. A conformance test may name the input file with the meta key `input:`, whose value is a path. The runner writes the test's source to that path before it runs `glyphc`. Without `input:`, the source is named `main.gl`. This key is needed for the file-name tests in the Test plan. It is a change to the runner in `tools/`, which this RFC asks for and does not make.

## Alternatives

- **Keep "Glyph" as a codename and pick a name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension question open.
- **Pick a new name.** Rejected. Every existing file and tool would need changing. Collision with other software was not checked, because this session has no network access. A later RFC can rename the language, and renaming is cheap until a release exists.
- **No file-extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1.
- **Use a `GLY` prefix for the code.** Rejected. RFC 0004 fixes the form `E` followed by four digits.

## Cost

Estimates, not counted. The merge bot's count is the real one.

- **Adds to the core:** the title, the rule of item 2 in short form, and the `E0010` entry. About 60 tokens.
- **Removes:** nothing.
- **Spec card:** about 10 tokens. The card stays far under its 2,000-token cap.
- **Diagnostics:** one code, `E0010`, in the lexical block.
- **Grammar:** no production is added, so grammar coverage is unchanged.

## Test plan

Node tests, run by `node --test 'compiler/stage0/**/*.test.ts'`:

- `compiler/stage0/src/source-file.test.ts`: every example in Design item 2, on both sides of the rule.
- `compiler/stage0/src/cli.test.ts`: for each of `check`, `run` and `build`, and each of `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`, stderr is exactly the record of Design item 4, stdout is empty, the exit status is 1, and the file is not opened.
- `compiler/stage0/src/e0010.test.ts`: `spec/errors.json` has `E0010` exactly once, its code is in `E0001` to `E0099`, and its message passes `checkMessage` in `message.ts`.
- `compiler/stage0/src/message.test.ts`: `source file does not end in .gl` passes the message rules.

Conformance tests:

- run: `conformance/name/run-title.test`. A `main.gl` prints `Glyph` with `print`. This test is written together with the RFC that defines `print`.
- compile-error: `conformance/name/bad-extension.test`, with `input: prog.txt`, expects `glyphc check` to give the record of Design item 4 with `span.file` `prog.txt`.
- compile-error: `conformance/name/upper-extension.test`, with `input: PROG.GL`, expects `E0010`.

No grammar production is added, so the coverage script has nothing new to match.

## Open questions

- RFC 0005's address example `main.glyph::add` conflicts with Design item 2. A kernel RFC that writes a source address must use `main.gl::add`. The fix belongs in that RFC's file.
- Whether a second extension is ever needed. This RFC says no. A later RFC must justify any second suffix.
- Whether the name collides with existing software or trademarks. That needs a check outside this session.
