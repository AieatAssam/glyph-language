# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min
Status: draft

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name, the source file rule, and the one diagnostic code that rule uses.

## Motivation

The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, `bin/glyphc` and the site. Renaming would touch all of them before any code exists.

The publisher and check job need one fixed suffix to recognise language sources, so the file rule is needed now. The rule runs before the file is read, so it applies even when the content is not valid Glyph. Its diagnostic code is in the lexical block, because RFC 0004 section 4 assigns E0001 to E0099 to lexical errors.

## Design

Normative.

1. The language name is `Glyph`, case-sensitive. The title of `spec/core.md` is `Glyph`. The spec does not call the name a codename.
2. A source file is a path whose last component (the part after the last `/`) is spelled in lower case, ends in `.gl`, and is longer than `.gl`. Matching is case-sensitive. These are not source files: `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/`, and the empty string.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. Later RFCs define what they do. This RFC defines only rule 4.
4. When `check`, `run` or `build` is given a path that is not a source file, it does not open the file. It writes exactly one diagnostic record to stderr, in the form RFC 0004 section 2 defines, with:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix` field.
   It writes nothing to stdout and exits with status 1.
5. The message in rule 4 passes the message rules of RFC 0004 section 2. A full stop followed by a letter inside a file name, such as the one in `.gl`, is not a sentence break.
6. `spec/errors.json` gets this entry: code `E0010`, message `source file does not end in .gl`, meaning `the path given is not a source file`. Codes are never reused.
7. `spec/core.md` states rule 2 and names `glyphc` with its three subcommands. `spec/card.md` gets the two lines in Cost.

## Alternatives

- **Keep "Glyph" as a codename and decide later.** Rejected. It leaves the file extension open, and the rule is needed now.
- **Choose another name.** Rejected. Every existing file and tool would change. No collision check was made, because this session has no network access. A later RFC can rename the language, since renaming is cheap before a release.
- **No file rule.** Rejected. The publisher and check job need one suffix.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing.
- **A `GLY` diagnostic prefix.** Rejected. RFC 0004 uses `E` and four digits only.

## Cost

Counted with `tools/check/tokens.py --text` on the exact text this RFC adds:

- Core spec: 34 tokens of new text (the title, rule 2, and the `glyphc` line). Nothing is removed.
- Spec card: 10 tokens (`Glyph` and `Source: *.gl, compiler glyphc`).
- `spec/errors.json`: one entry, 29 tokens. This is a catalogue entry, not core spec text.
- Grammar: no production is added, so grammar coverage is unchanged.
- Diagnostics: one new code, `E0010`.

## Test plan

The conformance runner writes every `.test` source to `main.gl`, so `E0010` cannot be tested as a `.test` file (see Open questions). Its compile-error tests are node tests.

- compile-error (node): `compiler/stage0/src/cli.test.ts`. For each of `check`, `run` and `build`, and each of `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`: stderr is exactly the record in Design 4, stdout is empty, the exit status is 1, and the file is not opened (a missing file gives no ENOENT).
- node: `compiler/stage0/src/source-file.test.ts`. `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. Every non-example in Design 2 is not.
- node: `compiler/stage0/src/e0010.test.ts`. The `E0010` entry exists exactly once in `spec/errors.json`, its code is in E0001 to E0099, and its message passes `checkMessage` in `message.ts`.
- node: a case in `compiler/stage0/src/message.test.ts`. `source file does not end in .gl` gives no problems from `checkMessage`.
- run: `conformance/name/run-title.test`. A `main.gl` prints `Glyph` with `print`, which the kernel RFC defines.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- The conformance runner cannot name an input file other than `main.gl`, so the gate has no `E0010` conformance test. The node tests above cover it. Adding an input-name key is a change to `tools/`, which only the architect can make. This RFC does not depend on it.
- RFC 0005's example `main.glyph::add` conflicts with rule 2. It must read `main.gl::add`. This RFC does not edit RFC 0005.
- Whether a second source extension is ever wanted. This RFC says no. A later RFC must remove or justify any second suffix.
- The name has not been checked against existing software or trademarks. That needs a network check outside this session.
