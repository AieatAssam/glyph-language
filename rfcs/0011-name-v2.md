# RFC draft: The language name

Class: language
Slug: name-v2

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name, the one source-file suffix the toolchain needs, and the diagnostic for a path that is not a source file.

## Motivation

The name is already used in `README.md`, `docs/SPEC.md`, the compiler command `bin/glyphc` and the site. Any other name would rename all of them before any kernel code exists.

The publisher and the check job need one fixed suffix to recognise language sources. The check runs on the path before the file is read or lexed, so it is a path rule even though its code sits in the lexical block of RFC 0004 section 4. It works even when the file content is not valid Glyph.

## Design

Normative.

1. The language name is `Glyph`. The spec title is `Glyph`. `Glyph` is the only spelling of the name in the spec. Names are case-sensitive.
2. A path is a source file when the part after its last `/` (the whole path if it has no `/`) ends in `.gl`, has at least one character before `.gl`, and the match is case-sensitive. `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/` and the empty string are not.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. Later RFCs define what they do.
4. When a subcommand is given a path that is not a source file, it applies rule 2 before any other step. It does not read the file. It writes exactly one record to standard error, as one line of JSON Lines per RFC 0004 sections 1 and 2:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix` field.

   It writes nothing to standard output and exits with status 1. Under RFC 0004 section 2, a full stop inside a file name, such as `.gl`, does not end a sentence, so the message is valid.
5. `spec/errors.json` contains `E0010` with the message in rule 4 and the meaning `the path given is not a source file`. No other entry changes.

## Alternatives

- **Keep "Glyph" as a codename and choose a name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension open.
- **Pick a new name.** Rejected. Every existing file and tool would change. Renaming stays cheap until a release exists. This RFC does not check the name against other software.
- **No file rule.** Rejected. The publisher and the check job need one suffix.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1 of the constitution.
- **Use a `GLY` code prefix.** Rejected. RFC 0004 section 2 fixes the form `E` plus four digits.

## Cost

Counted with `tools/check/tokens.py`:

- Spec card: the line `Glyph` is 1 token. The line `Source: *.gl, compiler glyphc` is 8 tokens. Net change is 9 tokens. The card stays under its 2,000-token cap.
- Spec core: the spec text for rules 1 to 4, written tersely, is 128 tokens, with the record shown as one example line of 45 tokens. The core stays far under 12,000 tokens.
- Diagnostics: one new code, `E0010`. Its message `source file does not end in .gl` is 8 tokens.
- Grammar: no production is added, so grammar coverage is unchanged.
- Removes: nothing.

## Test plan

- run: `conformance/name/run-title.test`. A `main.gl` prints `Glyph` with `print`, the text output defined by the kernel language RFC.
- compile-error (node): `compiler/stage0/src/cli.test.ts`. For each of `check`, `run` and `build`, given `prog.txt`, `PROG.GL`, `main.glyph` and a missing `missing.txt`, standard error holds exactly the record in rule 4 with the given path, standard output is empty, the status is 1, and no file-system error is reported.
- node: `compiler/stage0/src/source-file.test.ts`. Every path listed in rule 2 gives the stated answer.
- node: `compiler/stage0/src/message.test.ts`. The message in rule 4 passes the RFC 0004 message checker, and `spec/errors.json` lists `E0010` exactly once.

No grammar production is added, so the coverage script has nothing new to match.
