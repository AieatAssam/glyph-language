# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`, as already used in `bin/glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec title, the one source file extension the toolchain needs, and the one diagnostic code that rule uses.

## Motivation

The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Keeping that name needs no file or tool change. Any other name would.

The check and the publisher need one fixed suffix to recognise language sources. The check runs on the file name before the file is read, so it works even when the content is not valid Glyph. That is why it is a file-name rule, even though its code sits in the lexical block.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`. `Glyph` is the only spelling of the name in the spec. Names are case-sensitive.
2. A source file uses the extension `.gl`, in lower case. Take the part of a path after its last `/`. It is a source file name when it ends in `.gl` and has at least one character before `.gl`. The check is case-sensitive. `main.gl`, `dir/prog.gl` and `a.b.gl` are source file names. `main.glyph`, `prog.GL`, `.gl`, `main.gl.bak`, `dir/` and the empty string are not.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. Later RFCs define what they do.
4. When `glyphc` is given a path that is not a source file name, it does not read the file. It writes exactly one diagnostic record, as defined by RFC 0004 section 2, to standard error, and exits with status 1. Nothing is written to standard output. The record has these fields:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`. The file is not read, so the span is the start of the file.
   - no `fix`. Renaming the file is the author's choice, not a mechanical edit.
5. A full stop inside a file name is not a sentence break under RFC 0004 section 2. The message in item 4 is therefore valid. The message checker in `compiler/stage0/src/message.ts` accepts it.
6. `spec/errors.json` contains `E0010` with the message in item 4 and the meaning "the path given is not a source file". Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and pick a new name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension question open.
- **Pick a new name.** Rejected. Every existing file and tool would need changing, and no reason is given that outweighs that cost. Renaming stays cheap until a release exists.
- **No file extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1.
- **Use a diagnostic code with a `GLY` prefix.** Rejected. RFC 0004 fixes the `E` plus four digits format and has no other prefix.

## Cost

Measured with `python3 -m tools.check.tokens --text`:

- **Core spec:** the candidate text `Glyph. Source files end in .gl, case-sensitive. Compiler: glyphc. Code E0010: source file does not end in .gl.` is 31 tokens. This RFC adds about that much to the core spec.
- **Diagnostic entry:** `E0010 error source file does not end in .gl` is 12 tokens.
- **Spec card:** adds `Glyph` (1 token) and `Source: *.gl, compiler glyphc` (8 tokens). Net change is 9 tokens.
- **Removes:** nothing.
- **Grammar:** no production is added, so grammar coverage is unchanged.
- **Diagnostics:** one new code, `E0010`, in the lexical block. It is the only code this RFC adds.

## Test plan

- **run:** `conformance/name/run-title.test`. The program in `main.gl` writes `Glyph` to standard output with `print` and exits 0. `print` writes its text and a newline.
- **compile-error:** `conformance/name/bad-extension.test`. `glyphc check prog.txt` gives exactly the record in item 4, with no `fix`, and exit status 1. The runner compares `code`, `span` and `fix`, as RFC 0004 section 7 requires.
- **compile-error:** `conformance/name/upper-extension.test`. `glyphc check PROG.GL` gives `E0010`, because the extension is lower case only.
- **unit:** `compiler/stage0/src/source-file.test.ts` tests the name rule in item 2. `compiler/stage0/src/cli.test.ts` tests item 4 for `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`, where the file is never opened, and checks that `main.gl` is not rejected by the rule.

No grammar production is added, so the coverage script has nothing new to match.

Not applicable. This RFC adds no heap values.

## Open questions

- The run test relies on `print`, whose definition belongs to the kernel and not to this RFC.
- The name has not been checked against existing software or trademarks.
