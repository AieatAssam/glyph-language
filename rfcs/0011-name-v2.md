# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min
Status: draft

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`, as already used in `bin/glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name, the source-file rule, and one diagnostic code that the rule uses.

## Motivation

The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Keeping that name costs nothing. Every other choice would rename all of it before any kernel code exists.

The check job and the publisher need one fixed suffix to recognise language sources, so the file rule is needed now. The rule reads the path before the file is opened, so it works even when the content is not valid Glyph.

The message `source file does not end in .gl` is valid under RFC 0004 section 2. A full stop inside a file name is not a sentence break.

## Design

Normative.

1. The name of the language is `Glyph`, spelled with that case in every spec title and in the spec card. The word "codename" is removed from the title line of `README.md` by the implementing PR that first creates `spec/`.
2. A path is a source file when the part after its last `/` (or the whole path, if it has no `/`) is longer than `.gl` and ends in exactly `.gl`. The match is case-sensitive. So `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. `.gl`, `dir/`, the empty path, `main.gl.bak`, `main.glyph`, `prog.txt` and `PROG.GL` are not.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC names them. Their behaviour beyond rule 5 is defined by later RFCs.
4. The spec core `spec/core.md` has the title `Glyph`, the source-file rule of rule 2, and the executable name with its three subcommands. The spec card `spec/card.md` has the title `Glyph` and the line `Source: *.gl, compiler glyphc`.
5. For `check`, `run` and `build`, when the path given is not a source file, `glyphc` does not open the file, whether or not it exists. It writes exactly one record, in the form of RFC 0004 section 2, to standard error:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix`.
   It writes nothing to standard output and exits with status 1.
6. The code `E0010` is added to `spec/errors.json` with the message in rule 5 and the meaning `the path given is not a source file`. It is in the lexical block `E0001`-`E0099`. Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and pick a name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension question open.
- **Pick a new name.** Rejected. Every existing file and tool would change, for no gain. Renaming stays cheap until a release exists.
- **No file extension rule.** Rejected. Tools need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same file, which breaks principle 1.
- **Use a `GLY` diagnostic prefix.** Rejected. RFC 0004 section 2 fixes the form `E` followed by four digits.

## Cost

Counted with `tools/check/tokens.py`:

- The record in rule 5 is 45 tokens.
- A one-line summary of rules 2, 3 and 5 is 52 tokens. The full text in the spec core is counted by the spec gate when it is written.
- Spec core: adds the name, the source-file rule, the command name and the E0010 entry. Removes nothing.
- Spec card: adds two lines, `Glyph` and `Source: *.gl, compiler glyphc`.
- Grammar: no production is added, so grammar coverage is unchanged.
- Diagnostics: one new code, `E0010`.

## Test plan

- **run:** `conformance/name/run-title.test`. A `main.gl` prints `Glyph` with `print`, as the kernel RFC in force defines it. This RFC defines no output.
- **compile-error (node):** `compiler/stage0/src/cli.test.ts`. For each subcommand `check`, `run` and `build`, and each path `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`: standard output is empty, standard error is exactly the record in rule 5 with that path, there is no `fix`, and the exit status is 1. The conformance runner names every input `main.gl`, so these file-name cases are tested through the CLI and not as conformance files.
- **unit (node):** `compiler/stage0/src/source-file.test.ts`. The rule in rule 2 gives the true and false cases listed there.
- **catalogue (node):** `compiler/stage0/src/e0010.test.ts`. `E0010` is listed once in `spec/errors.json`, in the lexical block, and its message passes the message rules of RFC 0004 section 2.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- Whether the language ever needs a second source suffix. This RFC says no. A later RFC must remove or justify any second suffix.
- The name has not been checked against existing software or trademarks.
