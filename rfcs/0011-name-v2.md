# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min
Status: draft

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`, as already used in `bin/glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec title, the one source file extension the toolchain needs, and the one diagnostic code that rule uses.

## Motivation

The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Every other choice would mean renaming all of that before any kernel code exists.

The file extension is needed now. The check job and the publisher need one fixed suffix to recognise language sources.

The source-file check runs on the file name before the file is read or lexed, so it works even when the content is not valid Glyph. That is why it is a file-name rule, even though its code sits in the lexical block `E0001`-`E0099` of RFC 0004 section 4. `E0010` is the next free code in that block.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`. `README.md` names the language `Glyph` and does not call it a codename.
2. A source file uses the extension `.gl`. The extension is lower case and case-sensitive. A path is a source file when its last component, the part after the last `/`, has at least one character before a suffix that is exactly `.gl`. So `main.gl` and `dir/prog.gl` are source files. `main.glyph`, `prog.GL`, `main.gl.bak`, `.gl`, `dir/` and the empty string are not.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC names them and does not define them; later RFCs do.
4. Names in this RFC are case-sensitive. `Glyph` is the only spelling of the name in the spec.
5. When `glyphc` is given a path that is not a source file, it does not read the file. It writes exactly one diagnostic record, as defined by RFC 0004 section 2, to standard error, and exits with status 1. The record is:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`. The file is not read, so the span is the start of the file.
   - no `fix`. Renaming the file is the author's choice, not a mechanical edit.
   This applies to every subcommand. A path given with extra arguments is checked by its first path argument only.
6. `E0010` is listed in `spec/errors.json` with the message above and the meaning "the path given is not a source file". Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and pick a new name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension question open.
- **Pick a new name.** Rejected. Every existing file and tool would need changing, and no reason is given that outweighs that cost. Collision with other projects was not checked, because this session has no network access. A later RFC can rename the language if a collision is found.
- **No file extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1.
- **Use a diagnostic code from another prefix.** Rejected. RFC 0004 fixes the `E` plus four digits format and has no other prefix.

## Cost

Counted with `tools/check/tokens.py` on the files as they will stand:

- `spec/core/name.md`, the new core section for the name, the `.gl` rule, `glyphc` and `E0010`: 177 tokens. The core cap is 12,000 tokens.
- `spec/card.md`, the card with its title line `Glyph` and its line `Source: *.gl, compiler glyphc`: 190 tokens in total. The card cap is 2,000 tokens.
- Diagnostics: one new code, `E0010`, in the lexical block. It is the only code this RFC adds.
- Removes: nothing.
- Grammar: no production is added, so grammar coverage is unchanged.

## Test plan

- **run:** `conformance/name/run-title.test`. A program `main.gl` prints `Glyph` with `print`. This test waits until an in-force RFC defines `print`. It is the only test in this plan that waits.
- **compile-error:** node tests that the existing gate runs, `node --test 'compiler/stage0/**/*.test.ts'`:
  - `compiler/stage0/src/cli.test.ts`: for each of `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`, and for each of `check`, `run` and `build`, the output is exactly one record with `code` `E0010`, the span in Design 5, no `fix`, and exit status 1. Nothing is written to standard output, and the file is not read.
  - `compiler/stage0/src/e0010.test.ts`: `E0010` is listed once in `spec/errors.json` with the message and meaning in Design 6, and the message passes the message rules.

These compile-error tests are node tests and not `conformance/` tests, because the conformance runner always writes the input to `main.gl`, so it cannot give a file name that is not a source file. This RFC does not change the runner.

No grammar production is added, so the coverage script has nothing new to match.

Not applicable. This RFC adds no heap values.

## Open questions

- RFC 0005's address example `main.glyph::add` must read `main.gl::add` so that it agrees with Design 2. This RFC does not edit RFC 0005.
- The name has not been checked against existing software or trademarks. That needs a network check outside this session.


## Owner ruling (2026-11-20)

The one-sentence rule in RFC 0004 section 2 does not treat a full stop inside a file name or extension, such as `.gl` or `main.gl`, as a sentence break. The RFC 0011 message `source file does not end in .gl` is valid as written. The message checker in `compiler/stage0/src/message.ts` must accept it, with a test. This settles the conflict between RFC 0004 and RFC 0011 (issues 54 and 59).
