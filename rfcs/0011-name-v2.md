# RFC draft: The language name

Class: language
Slug: name-v2

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name, the source file extension, and one diagnostic code for the extension rule.

## Motivation

The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command `bin/glyphc` and the site. The cheapest name is the one already in use.

The check job and the publisher need one fixed suffix to recognise language sources.

The extension rule runs on the file name before the file is read, so it works even when the content is not valid Glyph. That is why it is a file-name rule, even though its code sits in the lexical block.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`. The spec core is `spec/core.md` and the spec card is `spec/card.md`. Names are case-sensitive. `Glyph` is the only spelling.
2. Only the part of a path after its last `/` is tested. That name is a source file when it ends in exactly `.gl` (lower case) and has at least one character before `.gl`.
   - Source files: `main.gl`, `dir/prog.gl`, `a.b.gl`.
   - Not source files: `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/`, and the empty string.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC does not define what they do.
4. When `check`, `run` or `build` is given a path that is not a source file, `glyphc` does not open the file, whether or not it exists. It writes exactly one record to standard error, in the form RFC 0004 section 2 defines, and exits with status 1. Nothing is written to standard output. The record has:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix`. Renaming the file is the author's choice, not a mechanical edit.
5. The code `E0010` is added to `spec/errors.json` with the message in rule 4 and the meaning `the path given is not a source file`. It is in the lexical block `E0001`-`E0099`. No other RFC uses it.
6. Owner ruling (2026-11-20). The one-sentence rule in RFC 0004 section 2 does not treat a full stop inside a file name, such as the one in `main.gl`, as a sentence break. The message in rule 4 is valid. `compiler/stage0/src/message.ts` accepts it, and `compiler/stage0/src/message.test.ts` asserts this.

## Alternatives

- **Keep "Glyph" as a codename and choose a name later.** Rejected. It leaves the extension question open for no gain.
- **Choose a different name.** Rejected. Every file and tool would change, and renaming stays cheap until a release exists. Collision with other software was not checked, because there is no network access. A later RFC can rename the language if a collision is found.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing.
- **Use a code with a `GLY` prefix.** Rejected. RFC 0004 section 2 fixes `E` followed by four digits.

## Cost

Measured with `tools.check.tokens`:

- The message in rule 4, `source file does not end in .gl`: 8 tokens.
- The whole record in rule 4, as JSON with `prog.txt` as the file: 45 tokens.
- Spec card: the two added lines `Glyph` and `Source: *.gl, compiler glyphc` cost 10 tokens together.

Not measured: the spec core. `spec/` is not in this checkout, so the core's added section (title, rules 2 and 3, the `E0010` reference) has no count yet. The merge bot's count is the real one.

Adds: the core section above, and one code, `E0010`. Removes: nothing. Grammar: no production is added.

## Test plan

- **run:** `conformance/name/run-title.test`. A `main.gl` prints `Glyph` with `print`. No RFC in force defines `print`, so this test is added with the RFC that defines it.
- **compile-error (node):** `compiler/stage0/src/cli.test.ts`. For each of `check`, `run` and `build`, given `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`: standard error holds exactly the record in rule 4 with that file name, the exit status is 1, and standard output is empty. The test compares `code`, `span`, `fix` and `message`.
- **unit:** `compiler/stage0/src/source-file.test.ts`. Each accepted and rejected name in rule 2.
- **unit:** `compiler/stage0/src/e0010.test.ts`. `spec/errors.json` has exactly one `E0010` entry, its code is in `E0001`-`E0099`, and its message passes `checkMessage` in `message.ts`.
- **unit:** `compiler/stage0/src/message.test.ts`, which already asserts that `source file does not end in .gl` has no problems.

The file-name cases are node tests, not conformance tests. The conformance runner (`tools/check/conformance.py`) writes every source to `main.gl` and has no key for another input name, so it cannot give `glyphc` a `prog.txt` or `PROG.GL` input.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- RFC 0005's address example `main.glyph::add` does not follow rule 2. Any kernel RFC that keeps the example should write `main.gl::add`. This RFC does not edit RFC 0005.
- A second source extension would need a later RFC that justifies it.
- Whether the file-name cases should also be conformance tests. That needs the conformance runner to accept an input file name.
