# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min
Status: draft

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`, as already used in `bin/glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec title, the one source file extension the toolchain needs, and the one diagnostic code that rule uses.

## Motivation

The constitution leaves the name to the agents. The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Every other choice would mean renaming all of that before any kernel code exists. The cheapest name is the one already in use.

The file extension is needed now. The check job and the publisher need one fixed suffix to recognise language sources.

The file-name check runs before the file is read or lexed, so it works even when the content is not valid Glyph. That is why it is a file-name rule, even though its code sits in the lexical block.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`. The first PR that creates `spec/` removes the words "(working codename)" from the title line of `README.md`. This RFC does not change `docs/SPEC.md`.
2. A source file has the extension `.gl`, in lower case. Take the part of the path after its last `/`. It is a source file when it ends in `.gl` and has at least one character before `.gl`. Matching is case-sensitive. So `main.gl` and `dir/prog.gl` are source files. `main.glyph`, `prog.GL`, `main.gl.bak`, `.gl`, `dir/` and the empty path are not.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC does not define what they do; later RFCs do.
4. `Glyph` is the only spelling of the name in the spec.
5. When `glyphc check`, `glyphc run` or `glyphc build` is given a path that is not a source file, it does not open that path. It writes one line to stderr: the JSON record defined by RFC 0004 section 2, with these values:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix` field.

   It writes nothing to stdout and exits with status 1.
6. `spec/errors.json` lists `E0010` once, with the message in rule 5 and the meaning "the path given is not a source file". Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and pick a new name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension question open.
- **Pick a new name.** Rejected. Every existing file and tool would need changing, and no reason is given that outweighs that cost. Collision with other projects was not checked, because this session has no network access. If a collision is found later, a new RFC can rename the language. Renaming is cheap until a release exists.
- **No file extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1. RFC 0005's `main.glyph` example is therefore a conflict to be fixed there, not a reason to add the suffix here.
- **Use a diagnostic code from the `GLY` prefix.** Rejected. RFC 0004 fixes the `E` plus four digits format and has no other prefix.

## Cost

Counted with `tools/check/tokens.py`:

- The E0010 message `source file does not end in .gl`: 8 tokens.
- The example E0010 record in rule 5, with `prog.txt` as the path: 45 tokens.
- Spec card: adds the title `Glyph` and the line `Source: *.gl, compiler glyphc`, which counts 8 tokens. The card stays far under its 2,000-token cap.
- Spec core: adds the title, the `.gl` rule and a reference to `E0010` by code. The core text is not yet written, so its count is not known here. The implementing PR counts it against the 12,000-token cap.
- Removes: nothing.
- Grammar: no production is added, so grammar coverage is unchanged.
- Diagnostics: one new code, `E0010`, in the lexical block. It is the only code this RFC adds.

## Test plan

- **run:** `conformance/name/run-title.test`. A `main.gl` prints `Glyph` with `print`, which RFC 0005 (kernel) defines.
- **compile-error (CLI):** `compiler/stage0/src/cli.test.ts`. For each of `check`, `run` and `build`, and each of the paths `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`: exit status 1, empty stdout, and stderr is exactly the rule 5 record for that path. The `missing.txt` case shows the path is not opened, so no "no such file" error appears.
- **rule:** `compiler/stage0/src/source-file.test.ts`. The examples in Design rule 2 give the stated results.
- **message:** `compiler/stage0/src/e0010.test.ts`. The `E0010` entry in `spec/errors.json` is listed once, and its message passes `checkMessage` in `compiler/stage0/src/message.ts`.

The conformance runner gives every `.test` source the file name `main.gl` (`tools/check/conformance.py`). A `.test` file therefore cannot trigger E0010, so the file-name cases are tested at CLI level as listed above.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- **RFC 0005 must change its address example.** Its `main.glyph::add` must read `main.gl::add` so that it agrees with this RFC. This RFC does not edit RFC 0005.
- Whether the language should accept a second extension later. This RFC says no. A later RFC must remove or justify any second suffix.
- The name has not been checked against existing software or trademarks. That needs a network check outside this session.

## Owner ruling (2026-11-20)

The one-sentence rule in RFC 0004 section 2 does not treat a full stop inside a file name or extension, such as `.gl` or `main.gl`, as a sentence break. The RFC 0011 message `source file does not end in .gl` is valid as written. The message checker in `compiler/stage0/src/message.ts` must accept it, with a test. This settles the conflict between RFC 0004 and RFC 0011 (issues 54 and 59).
