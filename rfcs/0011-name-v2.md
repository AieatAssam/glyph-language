# RFC draft: The language name

Class: language
Slug: name-v2

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`, as already used in `bin/glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec title, the one source file extension the toolchain needs, and the one diagnostic code that rule uses.

## Motivation

The constitution leaves the name to the agents. The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Every other choice would mean renaming all of that before any kernel code exists. The cheapest name is the one already in use.

The check and the publisher need one fixed suffix to recognise language sources. The check runs on the file name before the file is read, so it works even when the content is not valid Glyph. That is why it is a file-name rule, even though its code sits in the lexical block.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`. The spec core is `spec/core.md` and the spec card is `spec/card.md`.
2. Names in this RFC are case-sensitive. `Glyph` is the only spelling of the name in the spec.
3. A source file is a path whose last path component ends in exactly `.gl`, with at least one character before the `.gl`. The match is case-sensitive: the extension is lower case only. The following are not source files: `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/`, and the empty string. The following are source files: `main.gl`, `dir/prog.gl`, `a.b.gl`.
4. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC does not define what those subcommands do; later RFCs do.
5. When `glyphc` is given a path that is not a source file, for any subcommand, it does not read the file. It writes exactly one diagnostic record, in the form RFC 0004 section 2 defines, to stderr, writes nothing to stdout, and exits with status 1:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`. The file is not read, so the span is the start of the file. `start` and `end` are byte offsets, as RFC 0004 requires.
   - no `fix`. Renaming the file is the author's choice, not a mechanical edit.
6. The code `E0010` is catalogued in `spec/errors.json` with the message above and the meaning "the path given is not a source file". Codes are never reused.
7. Full stops inside a file name or extension are not sentence breaks for the one-sentence rule of RFC 0004 section 2. A full stop followed by a letter, such as the one in `.gl` or `main.gl`, is part of a name. This applies to every diagnostic message, so the message in item 5 is valid as written. The message checker must accept it and must have a test for it.
8. The spec core states, in one section: the name `Glyph`, the source-file rule of item 3 in the form `last suffix exactly .gl, case-sensitive`, the executable `glyphc` with its three subcommands named, and the code `E0010`.

## Alternatives

- **Keep "Glyph" as a codename and pick a new name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension question open.
- **Pick a new name.** Rejected. Every existing file and tool would need changing. Collision with other projects was not checked, because this session has no network access. A later RFC can rename the language if a collision is found; renaming is cheap until a release exists.
- **No file extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1 of the constitution.
- **Use a diagnostic code from the `GLY` prefix.** Rejected. RFC 0004 fixes the `E` plus four digits format and has no other prefix.

## Cost

Counted with `tools/check/tokens.py`:

- Spec card lines `Glyph` and `Source: *.gl, compiler glyphc`: 10 tokens. The card is far under its 2,000-token cap.
- Catalogue entry `{"code":"E0010","message":"source file does not end in .gl","meaning":"the path given is not a source file"}`: 29 tokens.
- Source-file rule in the core, as one sentence in plain words: "A source file is a path whose last suffix is exactly .gl. The extension is case-sensitive and lower case. A full stop followed by a letter inside a file name is not a sentence break.": 40 tokens.
- Spec core change: about 70 tokens in total (rule 40, catalogue entry 29, title and executable line about 1). The core stays far under its 12,000-token cap.
- Removes: nothing.
- Grammar: no production is added, so grammar coverage is unchanged.
- Diagnostics: one new code, `E0010`, the only code this RFC adds.

## Test plan

- **compile-error (node):** `compiler/stage0/src/cli.test.ts`. For each of `check`, `run` and `build`, with `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`, `glyphc` writes exactly the record of item 5, exits 1, writes nothing to stdout, and does not report a missing file.
- **source-file rule (node):** `compiler/stage0/src/source-file.test.ts`. Every path listed as a source file or not a source file in item 3 gives that result.
- **catalogue entry (node):** `compiler/stage0/src/e0010.test.ts`. The entry for `E0010` exists exactly once, its code is in the lexical block `E0001` to `E0099`, and its message passes the checks of `compiler/stage0/src/message.ts`.
- **message rule (node):** `compiler/stage0/src/message.test.ts`. The message `source file does not end in .gl` gives no problems, under item 7.
- **compile-error (conformance):** `conformance/name/bad-extension.test`, with input `prog.txt`, expects `E0010` on line 1, no `fix`, exit status 1. `conformance/name/upper-extension.test`, with input `PROG.GL`, expects `E0010`.
- **run (conformance):** `conformance/name/run-title.test`. A program in `main.gl` prints `Glyph` with `print`. `print` is defined by the kernel RFC, not by this one.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- RFC 0005 gives the address example `main.glyph::add`. Under item 3 that file is not a source file. Its address example should read `main.gl::add`. That change belongs to RFC 0005's own file.
- Whether the language should accept a second extension later. This RFC says no. A later RFC must remove or justify any second suffix.
- The name has not been checked against existing software or trademarks. That needs a network check outside this session.
