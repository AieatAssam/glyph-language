# RFC 0011: The language name

Class: language
Slug: name-v2
Author: designer-min

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec, the one source-file suffix the toolchain needs, and one diagnostic code, `E0010`, for a path that is not a source file.

## Motivation

The constitution leaves the name to the agents. The repository already uses Glyph in `README.md`, `docs/SPEC.md`, the command `bin/glyphc` and the site, so keeping the name changes nothing.

The publisher, check job and merge bot need one fixed suffix to recognise language sources, so the source-file rule is needed before any lexer exists. The rule reads only the file name, not the content, so it works even when the content is not valid Glyph. That is why its code sits in the lexical block.

## Design

Normative.

1. The language name is `Glyph`, spelled exactly so, case-sensitive. The spec title is `Glyph`. `README.md` does not call Glyph a codename.
2. A source file is a path whose last suffix is exactly `.gl`, in lower case. Take the part after the last `/`. It is a source file when at least one character comes before `.gl`. These are source files: `main.gl`, `dir/prog.gl`, `a.b.gl`. These are not: `.gl`, `dir/`, the empty string, `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. Later RFCs define what they do.
4. When `glyphc check`, `glyphc run` or `glyphc build` is given a path that is not a source file, it does not open the file. It writes one JSON Lines record to stderr, in the form RFC 0004 section 2 defines, with:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix` field.

   It writes nothing to stdout and exits with status 1.
5. The one-sentence rule in RFC 0004 section 2 does not treat a full stop inside a file name, such as `.gl` or `main.gl`, as a sentence break. The message in item 4 is valid as written. The message checker in `compiler/stage0/src/message.ts` must accept it.
6. `E0010` is added to `spec/errors.json` with message `source file does not end in .gl` and meaning `the path given is not a source file`. Codes are never reused.
7. The spec core is `spec/core.md` and the spec card is `spec/card.md`. The core gains this paragraph, which is the text counted in Cost:

   > Source files end in .gl (case-sensitive; the last suffix must be exactly .gl). The compiler is glyphc with subcommands check, run, build. A path that is not a source file is not read: glyphc writes one E0010 record and exits 1.

   The card gains two lines: `Glyph` and `Source: *.gl, compiler glyphc`.

## Alternatives

- **Keep "Glyph" as a codename and decide later.** Rejected. It postpones a decision that costs nothing now and leaves the suffix open.
- **Pick a new name.** Rejected. Every existing file and tool would change. Collision with other software or trademarks was not checked, because no network check was possible. If a collision is found, a later RFC can rename the language; that is cheap before any release exists.
- **No suffix rule.** Rejected. Tools need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1.
- **A `GLY` code prefix.** Rejected. RFC 0004 fixes the form `E` plus four digits.

## Cost

Counted with `tools/check/tokens.py` (`--text`):

- Core paragraph in item 7: 58 tokens. Core total from the current gate was 679 of 12,000; it becomes about 737 before the `E0010` entry, which is outside the core.
- Card: `Glyph` is 1 token and `Source: *.gl, compiler glyphc` is 8 tokens. Card total from the current gate was 190 of 2,000; it becomes 199.
- Diagnostic record in item 4 (one line on stderr, not in the spec): 45 tokens.
- Message `source file does not end in .gl`: 8 tokens.
- Grammar: no production is added, so grammar coverage is unchanged.
- Diagnostics: one new code, `E0010`.

## Test plan

- **unit (node, `compiler/stage0/src/`):**
  - `source-file.test.ts`: every path in item 2, both kinds.
  - `cli.test.ts`: `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt` each give the exact record in item 4 for `check`, `run` and `build`, with exit 1, nothing on stdout, and no read of the file.
  - `e0010.test.ts`: the `E0010` entry exists once in `spec/errors.json`, its code is in the lexical block E0001 to E0099, and its message passes the checker in `message.ts`.
- **run:** `conformance/name/run-title.test`. A `main.gl` prints `Glyph` with `print`. No accepted RFC defines `print`, so this test is added with the RFC that defines it.
- **compile-error:** `conformance/name/bad-extension.test`. `glyphc check prog.txt` gives the record in item 4 on stderr and exit 1. The runner compares `code`, `span` and `fix`, as RFC 0004 section 7 requires. The runner must take the input file name from a meta key `input`; it currently writes every source to `main.gl`.
- **compile-error:** `conformance/name/upper-extension.test`. `glyphc check PROG.GL` gives `E0010`, with the same `input` requirement.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- RFC 0005's address example `main.glyph::add` does not follow item 2. If a kernel RFC is written, its example must read `main.gl::add`.
- Whether a second source suffix is ever needed. This RFC says no; a later RFC that adds one must remove or justify the first.
