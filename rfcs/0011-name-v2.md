# RFC 0011: The language name

Class: language
Slug: name-v2

## Summary

The language is named **Glyph**. A source file ends in `.gl`. The compiler is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name, the source file suffix, and one diagnostic code, `E0010`.

## Motivation

Every tool and document already uses the name Glyph and the command `glyphc`. The publisher and check job need one fixed suffix to recognise language sources, so the suffix is fixed here, before any component picks its own.

The file-name rule runs before the file is read, so it works when the content is not valid Glyph. Its code is in the lexical block because it concerns how a source is named, not what it contains.

## Design

Normative.

1. The language name is `Glyph`. The spec title is `Glyph`. Names are case-sensitive. `Glyph` is the only spelling of the name in the spec.
2. A source file is a path whose last suffix is exactly `.gl` (lower case). `main.gl` is a source file. `main.glyph`, `prog.GL` and `prog.txt` are not.
3. The compiler executable is `glyphc`. This RFC defines no subcommand.
4. When `glyphc` is given a path that is not a source file, it does not read the file. It writes exactly one diagnostic record, in the format of RFC 0004 section 2, and exits with a nonzero status:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix` field.
5. A full stop inside a file name or extension does not end a sentence. The message in rule 4 is one sentence. A message checker that splits sentences at full stops must not split inside `.gl`.
6. `E0010` is added to `spec/errors.json` with the message in rule 4 and the meaning "the path given is not a source file". Codes are never reused.

## Alternatives

- **Keep "Glyph" as a codename and fix the name later.** Rejected. It leaves the suffix open, and the suffix is needed now.
- **A different name.** Rejected. Every existing file and tool would change, and no reason is given that outweighs that cost. A later RFC can rename the language while renaming is still cheap.
- **No suffix rule.** Rejected. The publisher and check job need one suffix.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name one thing, which breaks principle 1 of the constitution.
- **Diagnostic code with a `GLY` prefix.** Rejected. RFC 0004 section 2 fixes `E` plus four digits, and has no other prefix.

## Cost

Not yet counted. The implementing PR runs `sbx python3 -m tools.check.tokens` on the spec text and the card text and records the counts here.

- **Adds:** the name in the spec title, the suffix rule (Design rules 1 to 3), and the file-name diagnostic (rules 4 to 6).
- **Removes:** nothing.
- **Spec card:** adds the title line `Glyph` and the line `Source: *.gl, compiler glyphc`.
- **Grammar:** no production is added, so grammar coverage is unchanged.

## Test plan

- **compile-error:** `conformance/name/bad-extension.test`. `glyphc check prog.txt` gives `--- expect-errors` with `E0010 1`, exit status nonzero, and the one record of Design rule 4 with no `fix` field.
- **compile-error:** `conformance/name/upper-extension.test`. `glyphc check PROG.GL` gives `E0010 1`.
- **unit:** `compiler/stage0/src/message.test.ts`. The message `source file does not end in .gl` passes the message checker with no sentence split inside `.gl`.
- **run:** `conformance/name/run-title.test`. `main.gl` contains a program that writes the text `Glyph` followed by a newline, and the test expects stdout `Glyph\n` and exit status 0. The program uses the kernel's text output statement.

Every test file begins with a `--- meta` block that has `id`, `rfc: 0011` and `kind`, where `kind` is `run` or `compile-error`.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- Whether a second source suffix is ever needed. This RFC says no. A later RFC must remove or justify any second suffix.
- Whether the name collides with existing software or trademarks. This RFC does not check it.
