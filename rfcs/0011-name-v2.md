# RFC 0011: The language name

Class: language
Slug: name-v2

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name, the source-file rule, and one diagnostic code, `E0010`, that reports a path which is not a source file.

## Motivation

The repository already uses the name Glyph in `README.md`, `docs/SPEC.md`, `bin/glyphc` and the site. Keeping it costs nothing. The check job and the publisher need one fixed suffix to recognise language sources, and the check must run on the path alone, before any file is read or lexed.

## Design

Normative.

1. The language is named `Glyph`. The spec title is `Glyph`.
2. A path is a source file when the last part of the path after the final `/` has at least one character before a final `.gl`. The match is case-sensitive. So `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/`, and the empty string are not.
3. The compiler executable is `glyphc`. Its subcommands `check`, `run` and `build` are named here. Later RFCs define them.
4. When `glyphc check`, `glyphc run` or `glyphc build` is given a path that is not a source file, or a path that does not exist, it does not read the path. It writes exactly one record to stderr, as RFC 0004 section 2 defines it:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix`

   It writes nothing to stdout and exits with status 1.
5. The message in rule 4 is valid under RFC 0004 section 2. The full stop inside `.gl` is part of a file name, not a sentence break. Owner ruling, 2026-11-20. The message checker accepts this message and has a test for it.
6. `E0010` is added to `spec/errors.json` with the message in rule 4 and the meaning "the path given is not a source file". The implementing PR adds it. Codes are never reused.
7. The spec core gets a title line `Glyph` and a section stating the rule in 2, the executable `glyphc` and its three subcommands, and the code `E0010`. The spec card gets the title line `Glyph` and the line `Source: *.gl, compiler glyphc`.

## Alternatives

- **Keep the name as a codename and decide later.** Rejected. It leaves the extension open, and the check job needs it now.
- **A different name.** Rejected. Every existing file and tool would change for no gain. Trademark and software collisions were not checked, because this session has no network access. A later RFC can rename the language while renaming is still cheap.
- **No extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1.
- **A `GLY` diagnostic prefix.** Rejected. RFC 0004 section 2 fixes the form `E` followed by four digits.

## Cost

Counted with `tools/check/tokens.py` on the exact text proposed for the spec and card:

- **Core spec:** 67 tokens added (the title, the rule, the executable and subcommands, and the reference to `E0010`). Nothing removed.
- **Spec card:** 12 tokens added. The card stays far under its 2,000-token cap.
- **Grammar:** no production added, so grammar coverage is unchanged.
- **Diagnostics:** one code, `E0010`, in the lexical block E0001 to E0099. It is the only code this RFC adds.
- **Programs:** this RFC adds no program syntax, so there are no example programs to count.

## Test plan

The rule in Design 2 and 4 runs before any file is read. The conformance runner writes every input as `main.gl`, so the cases below are node tests, not conformance tests.

- **compile-error (node):** `compiler/stage0/src/cli.test.ts`. For each of `check`, `run` and `build`, and each of `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`, the call returns 1, stdout is empty, and stderr is exactly the one JSON line of Design 4 with no `fix` field. A `main.gl` path does not produce `E0010`.
- **source-file rule (node):** `compiler/stage0/src/source-file.test.ts`. Every path in Design 2 gets the stated answer.
- **catalogue (node):** `compiler/stage0/src/e0010.test.ts`. `spec/errors.json` has exactly one `E0010` entry, its code is in E0001 to E0099, and its message passes the message checker.
- **run:** `conformance/name/run-title.test`. The input `main.gl` prints `Glyph` with `print`, and stdout is `Glyph` followed by a line feed.
