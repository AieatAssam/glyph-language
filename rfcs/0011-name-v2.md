# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min
Status: draft
Attempt: 2 (replaces RFC 0002, rejected)

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`, as already used in `bin/glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec title, the one source file extension the toolchain needs, and the one diagnostic code that rule uses.

## Motivation

The constitution leaves the name to the agents. The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Every other choice would mean renaming all of that before any kernel code exists. The cheapest name is the one already in use.

The file extension is needed now. The check job and the publisher need one fixed suffix to recognise language sources. Without an RFC, each component would pick its own.

Attempt 1 (RFC 0002) was rejected for four objections. This attempt keeps everything the voters accepted and changes only what they objected to:

- **Diagnostic code format (designer-safe, impl-1, tester).** Attempt 1 used `GLY0001`. RFC 0004 section 2 requires `E` followed by four digits, and section 4 assigns blocks. The code is now `E0010`, in the lexical block `E0001`-`E0099`. No other RFC in `rfcs/` uses `E0010`.
- **Wrong owner of `print` (tester).** Attempt 1's run test said `print` comes from RFC 0003. `print` is defined in RFC 0005 (kernel). The run test now cites RFC 0005.
- **Address example conflict (tester).** RFC 0005 gives the example `main.glyph::add`. The suffix `.glyph` is not `.gl`, so under this RFC that file is not a source file. This RFC does not edit RFC 0005. The correct example is `main.gl::add`. See Open questions.

The check runs on the file name before the file is lexed, so it works even when the content is not valid Glyph. That is why it is a file-name rule, even though its code sits in the lexical block.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`. The spec core is `spec/core.md` and the spec card is `spec/card.md`. The word "codename" is removed from `README.md` when the first RFC that creates `spec/` is implemented. This RFC does not edit that file.
2. A source file uses the extension `.gl`. The extension is lower case and the match is case-sensitive. A path is a source file when the part after its last `/` ends in `.gl` and has at least one character before the `.gl`. So `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. `main.glyph`, `prog.GL`, `main.gl.bak`, `.gl`, `dir/` and the empty string are not.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. This RFC names them but does not define them; later RFCs do.
4. Names in this RFC are case-sensitive. `Glyph` is the only spelling of the name in the spec.
5. When `glyphc check`, `glyphc run` or `glyphc build` is given a path that is not a source file, it does not open the file, whether or not it exists. It writes exactly one line to stderr, the diagnostic record of RFC 0004 section 2 in JSON Lines form, with these values:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`. The span is the start of the file, because the file is not read.
   - no `fix` key. Renaming the file is the author's choice, not a mechanical edit.

   It writes nothing to stdout, and it exits with status 1.
6. The code `E0010` is added to `spec/errors.json` by the first implementing PR, with the message above and the meaning "the path given is not a source file". Codes are never reused.
7. Full stops in file names. The one-sentence rule of RFC 0004 section 2 does not treat a full stop inside a file name or extension, such as `.gl` or `main.gl`, as a sentence break. The message checker in `compiler/stage0/src/message.ts` follows this.

## Alternatives

- **Keep "Glyph" as a codename and pick a new name later.** Rejected. It postpones a decision that costs nothing now and leaves the extension question open.
- **Pick a new name.** Rejected. Every existing file and tool would need changing, and no reason is given that outweighs that cost. Collision with other projects was not checked, because this session has no network access. Renaming is cheap until a release exists.
- **No file extension rule.** Rejected. The publisher and check job need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing, which breaks principle 1.
- **Use a diagnostic code from the `GLY` prefix.** Rejected. RFC 0004 fixes the `E` plus four digits format and has no other prefix.

## Cost

Estimates. The tokeniser has not run on the spec text, because `spec/` does not exist yet. The merge bot's count is the real one.

- **Adds:** the name in the spec title and the `.gl` rule (about 30 tokens in the core spec). One diagnostic code, `E0010`, with its message and meaning (about 20 tokens in the core spec).
- **Removes:** nothing. The word "codename" is already outside the spec.
- **Spec card:** one title line, `Glyph`, and one line `Source: *.gl, compiler glyphc`. Net change about 10 tokens.
- **Diagnostics:** one new code, `E0010`. It is the only code this RFC adds.
- **Grammar:** no production is added, so grammar coverage is unchanged.

## Test plan

- **compile-error (node, the tests of record for `E0010` now):** `compiler/stage0/src/cli.test.ts`. For each of `check`, `run` and `build`, and each of the paths `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`, the test calls `run` with fake writers and checks that stderr is exactly the record in Design 5 with the path as given, stdout is empty, the return value is 1, and the file is never opened. `compiler/stage0/src/source-file.test.ts` checks the cases in Design 2. `compiler/stage0/src/e0010.test.ts` checks that the `E0010` entry exists once and is in the block E0001 to E0099.
- **compile-error (conformance):** `conformance/name/bad-extension.test` (`glyphc check prog.txt` gives the record in Design 5) and `conformance/name/upper-extension.test` (`glyphc check PROG.GL` gives `E0010`). The conformance runner writes every source to `main.gl` and has no key that names another input file, so these files cannot be added until the runner gains that key. That change is in `tools/` and is not part of this RFC. Until then the node tests above are the record of this rule.
- **run:** `conformance/name/run-title.test`. A program `main.gl` prints `Glyph` with `print`, which RFC 0005 defines. It cannot run until RFC 0005 or another RFC that defines `print` is accepted and implemented.
- **node:** `compiler/stage0/src/message.test.ts` has the case that a full stop inside a file name is not a sentence break.

No grammar production is added, so the coverage script has nothing new to match.

## Open questions

- **RFC 0005 must change its address example** from `main.glyph::add` to `main.gl::add`. This RFC does not edit RFC 0005.
- **The run test depends on `print`.** No accepted RFC defines it today. The compile-error tests do not depend on it.
- Whether the language should also accept a second extension later. This RFC says no. A later RFC must remove or justify any second suffix.
- The name has not been checked against existing software or trademarks. That needs a network check outside this session.


## Owner ruling (2026-11-20)

The one-sentence rule in RFC 0004 section 2 does not treat a full stop inside a file name or extension, such as `.gl` or `main.gl`, as a sentence break. The RFC 0011 message `source file does not end in .gl` is valid as written. The message checker in `compiler/stage0/src/message.ts` must accept it, with a test. This settles the conflict between RFC 0004 and RFC 0011 (issues 54 and 59).
