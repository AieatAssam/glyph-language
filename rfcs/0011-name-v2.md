# RFC 0011: The language name

Class: language
Slug: name-v2
Author: designer-min

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name in the spec title, the one source file extension the toolchain needs, and one diagnostic code for that rule.

## Motivation

The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Keeping the name costs nothing. Renaming would touch every file before any kernel code exists.

The check job and the publisher need one fixed suffix to recognise language sources.

The file-name check runs before the file is read, so it works even when the content is not valid Glyph. Its code therefore sits in the lexical block with the other early codes.

## Design

Normative.

1. The language name is `Glyph`. The spec title is `Glyph`. Names are case-sensitive; `Glyph` is the only spelling.
2. A path is a source file when the part after its last `/` ends in `.gl` and has at least one character before `.gl`. The match is case-sensitive. `main.gl`, `dir/prog.gl` and `a.b.gl` are source files. `main.glyph`, `prog.txt`, `PROG.GL`, `main.gl.bak`, `.gl`, `dir/` and the empty string are not.
3. The compiler executable is `glyphc`. Its subcommands are `check`, `run` and `build`. Later RFCs define what they do.
4. When `glyphc check`, `glyphc run` or `glyphc build` is given a path that is not a source file, it does not read the file. It writes one diagnostic record, in the form RFC 0004 section 2 defines, to stderr, and exits with status 1. Nothing is written to stdout. The record is:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix` field.
5. A full stop inside a file name or extension, such as `.gl`, is not a sentence break under RFC 0004 section 2. The message in rule 4 is valid as written, and the message checker accepts it.
6. `E0010` is added to `spec/errors.json` with `code` `E0010`, `message` `source file does not end in .gl`, and `meaning` `the path given is not a source file`. No other entry changes. Codes are never reused.
7. The spec core is `spec/core.md`. It gets the title `Glyph`, the rule of design 2, the executable name `glyphc` with its three subcommands named, and a reference to `E0010` by code. The spec card is `spec/card.md`. It gets the title line `Glyph` and the line `Source: *.gl, compiler glyphc`.

## Alternatives

- **Pick a new name.** Rejected. Every existing file and tool would change, and nothing gained outweighs that. A later RFC can rename the language while renaming is still cheap.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name the same thing. `main.glyph` is a rejected name under design 2.
- **No file extension rule.** Rejected. Tools need one suffix to find sources.
- **A `GLY` code prefix.** Rejected. RFC 0004 fixes the form `E` plus four digits.

## Cost

Counted with `tools/check/tokens.py`:

- Core spec: the name and `.gl` rule text is 45 tokens. The `E0010` catalogue entry is 29 tokens.
- Spec card: the two lines are 10 tokens.
- Removes: nothing.
- Grammar: no production is added, so grammar coverage is unchanged.
- Diagnostics: one new code, `E0010`.

## Test plan

- compile-error, node test `compiler/stage0/src/cli.test.ts`: the inputs `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt`, each with `check`, `run` and `build`. Each case gives exactly the record of design 4 on stderr, exit status 1, and no read of the file. The check does not depend on a lexer.
- unit test `compiler/stage0/src/source-file.test.ts`: every example in design 2.
- unit test `compiler/stage0/src/e0010.test.ts`: `E0010` appears exactly once in `spec/errors.json`, is in the range E0001 to E0099, and its message passes the message checker of RFC 0004, including the full stop in `.gl`.
- compile-error, conformance `conformance/name/bad-extension.test`: `glyphc check prog.txt` gives the record of design 4 and exit status 1. Conformance `conformance/name/upper-extension.test`: `glyphc check PROG.GL` gives `E0010`. Both need the runner to set the input file name from the test's meta block. The runner takes it from `main.gl` today.
- run, conformance `conformance/name/run-title.test`: a program `main.gl` prints `Glyph` with `print`, as defined by the kernel RFC in force.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- RFC 0005's address example `main.glyph::add` uses a suffix that design 2 rejects. Any kernel RFC that carries that example must use `main.gl::add`.
- Whether a second extension should ever be allowed. A later RFC must justify it and remove this one's rule.
- The name has not been checked against existing software or trademarks. That check needs network access and is outside this RFC.
