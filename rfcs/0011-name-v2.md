# RFC draft: The language name

Class: language
Slug: name-v2
Author: designer-min

## Summary

The language is called **Glyph**. Source files end in `.gl`. The compiler command is `glyphc`, as already used in `bin/glyphc`. This RFC adds no grammar, no types and no runtime behaviour. It fixes the name, the source-file suffix, and one diagnostic code, `E0010`, for a path that is not a source file.

## Motivation

The repository already calls the language Glyph in `README.md`, `docs/SPEC.md`, the compiler command and the site. Keeping that name costs nothing. A new name would rename every file before any code exists.

Tools need one fixed suffix to recognise language sources. The source-file check looks at the path before the file is read, so it works even when the content is not valid Glyph. That is why it is a path rule, although its code is in the lexical block.

## Design

Normative.

1. The name of the language is `Glyph`. The spec title is `Glyph`. Names in this RFC are case-sensitive.
2. A path is a source file when the part after its last `/` ends in `.gl`, the match is case-sensitive, and at least one character comes before `.gl`. So `main.gl` and `dir/prog.gl` are source files. `main.glyph`, `prog.GL`, `main.gl.bak`, `.gl`, `dir/` and the empty string are not.
3. The compiler executable is `glyphc`. This RFC names its subcommands `check`, `run` and `build`. Later RFCs define them.
4. When `glyphc` is given a path that is not a source file, it does not read the file. It writes exactly one record, as RFC 0004 section 2 defines, to standard error, and exits with status 1. Nothing is written to standard output. The record is:
   - `code`: `E0010`
   - `severity`: `error`
   - `message`: `source file does not end in .gl`
   - `span`: `{"file": <path as given>, "start": 0, "end": 0, "line": 1, "column": 1}`
   - no `fix`, because renaming the file is the author's choice.
5. `E0010` has the message in (4) and the meaning "the path given is not a source file". It is entered in `spec/errors.json` as RFC 0004 section 4 requires.
6. The spec core is `spec/core.md`. It has the title `Glyph`, the rules in (2) and (3), and the code `E0010` by reference. The spec card is `spec/card.md`. It has the title line `Glyph` and the line `Source: *.gl, compiler glyphc`.

## Alternatives

- **Keep "Glyph" as a codename and pick a name later.** Rejected. It postpones a decision that costs nothing now and leaves the suffix open.
- **Pick a new name.** Rejected. It renames every existing file for no gain. Collision with other software was not checked. A later RFC can rename the language while that is still cheap.
- **No suffix rule.** Rejected. Tools need one suffix to find sources.
- **Accept `.glyph` as well as `.gl`.** Rejected. A second suffix is a second way to name one thing, which breaks principle 1.
- **A `GLY` code prefix.** Rejected. RFC 0004 section 2 fixes `E` plus four digits.

## Cost

Counted with `tools/check/tokens.py`:

- **Card:** the two lines in (6) are 11 tokens. Net change to the card: 11 tokens. The card stays far under its 2,000-token cap.
- **E0010 record:** the JSON record in (4) for `prog.txt` is 45 tokens. It is written only on error, so it adds no cost to a valid program.
- **Removes:** nothing.
- **Grammar:** no production is added, so grammar coverage is unchanged.
- **Diagnostics:** one new code, `E0010`, in the lexical block. It is the only code this RFC adds.

## Test plan

Conformance inputs are always named `main.gl`, so the cases that depend on a file name are node tests. Each one is named here.

- **run:** `conformance/name/run-title.test`. A `main.gl` prints `Glyph` with `print`, which the kernel RFC defines. This RFC defines no runtime behaviour, so the test belongs to the kernel RFC's test set.
- **compile-error (node):** `compiler/stage0/src/source-file.test.ts`. Each path in (2) gives the expected true or false.
- **compile-error (node):** `compiler/stage0/src/cli.test.ts`. For each of `check`, `run` and `build`, the paths `prog.txt`, `PROG.GL`, `main.glyph` and `missing.txt` each write exactly the record in (4) to standard error, return 1, and do not read the file, so a missing file gives no read error.
- **check (node):** `compiler/stage0/src/e0010.test.ts`. `spec/errors.json` has exactly one `E0010` entry, its code is in `E0001`-`E0099`, and its message passes `checkMessage` in `compiler/stage0/src/message.ts`. A full stop inside `.gl` is not a sentence break, so that check must pass.

No grammar production is added, so the coverage script has nothing new to match.

## Memory allocation

Not applicable. This RFC adds no heap values.

## Open questions

- Whether a second suffix is ever accepted. This RFC says no. A later RFC must justify any second suffix.
- Whether the name collides with existing software or trademarks. That needs a check outside this RFC.
