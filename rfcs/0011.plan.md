# Plan: RFC 0011 The language name

RFC 0011 is accepted. Its name and `.gl` rule need no lexer and no kernel. Its run test needs `print`, which no accepted RFC defines. Subtasks 1 to 5 can be built and tested without anything else in this plan.

## Prerequisites outside this plan

- RFC 0004 (accepted) is not implemented. Its plan (`rfcs/0004.plan.md`) creates `spec/errors.json` (its subtask 1), `compiler/stage0/src/diagnostic.ts` with `toJsonLine` (its subtask 2), `compiler/stage0/src/message.ts` (its subtask 5) and the spec core and card (its subtask 8). Subtasks 2, 3 and 5 below need those files. If a file is missing when you reach the subtask, stop there and report it. Do not create a stand-in.
- `bin/glyphc` runs `compiler/stage0/src/main.ts`. That file does not exist. Subtask 3 creates it.

## Conflicts to settle first

- Runner. `tools/check/conformance.py` writes every `.test` source to `main.gl` and has no meta key for another input name. Its `compile-error` kind compares `code`, `span` and `fix` when `expect-errors` gives a JSON object, so the span and fix part is settled. The file-name part is not: `prog.txt` and `PROG.GL` cannot be inputs, and `main.gl` is accepted, so the two RFC 0011 `.test` files would fail the gate. Only the architect can change `tools/`.
- Runner again. RFC 0004 removed `--json` and writes JSON Lines to stderr. The runner passes `--json` and reads `span.start` as a `[line, column]` pair. RFC 0004's `span.start` is a byte offset. Same conflict as in `rfcs/0004.plan.md`. This plan uses RFC 0004's form and passes no `--json`.
- Exit status. RFC 0011 says "nonzero". The runner expects 1 for a compile error. This plan uses 1.
- Run test. `print` is defined in RFC 0005 (kernel), which is rejected. RFC 0013 (kernel-v2), which would replace it, is also rejected. No accepted RFC defines `print`.
- Address example. RFC 0005 uses `main.glyph::add`. RFC 0011 says it must read `main.gl::add`. This matters only if a kernel RFC is revived. No subtask here edits RFC 0005.
- Spec path. RFC 0011 says "the spec title" without a path. `spec/` does not exist. This plan assumes `spec/core.md` and `spec/card.md`, as `rfcs/0004.plan.md` does. The repo also has `docs/SPEC.md`, the build spec. Confirm the path before subtask 5.
- Source-file rule edge cases. RFC 0011 does not say whether `.gl` alone or a path ending in `/` is a source file. Subtask 1 decides: neither is a source file.
