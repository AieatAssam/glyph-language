# Plan: RFC 0001 Toy print

Source: `rfcs/0001-toy-print.md` (status accepted). Each subtask is one compiler stage where possible and is expected to change fewer than 400 lines. Tests for a subtask land in the same subtask as the code they exercise, so every subtask passes the gate on its own.

Notes for implementers:

- `compiler/ACTIVE` names `stage0`, but `compiler/stage0/` does not exist in this checkout. Subtask 1 creates the spec only; subtask 2 creates the stage0 layout.
- `bin/glyphc` is protected. The `check`, `run` and `build` subcommands must reach stage0 without editing it. If they cannot, stop and open an issue; do not work around it.
- `spec/errors.json` does not exist yet. Subtask 1 creates it with E0001 to E0004 only. Codes are not edited once added.
- Open question 1 in the RFC (blank line is an error) is implemented as written: E0002.

- [ ] 1. Spec text and error catalogue. Add the Text, Tokens, Grammar, Parsing rules, Values, Output and Errors sections of RFC 0001 to `spec/core.md`. Create `spec/card.md` with the four error lines, the grammar block and the one-decimal-per-line rule. Create `spec/errors.json` with E0001 to E0004. Docs only; no code and no tests.
- [ ] 2. Stage0 layout and conformance runner. Create `compiler/stage0/` with `src/` and a test entry for `node --test`. Define the conformance file format for run tests (source plus expected stdout) and compile-error tests (source plus expected code and line/column). Add a runner that reads `conformance/toy/`. Add one runner self-test that uses an in-memory case. No toy tests yet.
- [ ] 3. Lexer, with its errors. Add `compiler/stage0/src/lexer.ts`. Produce INT, operator, paren, `print` and EOL tokens with line and column. Emit E0001 for tabs, non-ASCII, and words other than `print`. Emit E0004 for an integer above 2147483647. Add conformance tests `bad-character.test`, `bad-word.test` and `literal-range.test`.
- [ ] 4. Parser, with its errors. Add `compiler/stage0/src/parser.ts` as recursive descent over `program`, `line`, `expr`, `term` and `factor`. Stop at the first error and report only that error. Emit E0002 for a blank line, a line not starting with `print`, and `print` with no expression. Emit E0003 for an unclosed `(` and for a trailing token after an expression. Add conformance tests `blank-line.test`, `missing-expr.test`, `unclosed-paren.test` and `extra-token.test`.
- [ ] 5. Parser output contract. Parsing returns the whole program or an error; no partial result is returned. Add `no-output-on-error.test`, which checks that a later bad line prints nothing even when an earlier line is valid. Add tests for associativity and precedence at the AST level: `1-2-3` groups as `(1-2)-3` and `1+2*3` groups as `1+(2*3)`. This subtask is about the tree shape only; no value is computed.
- [ ] 6. Evaluator with i32 wrapping. Add `compiler/stage0/src/eval.ts`, which computes each `print` value on 32-bit two's-complement wrapping, left to right. Add run tests `print-int.test`, `print-zero-prefix.test`, `print-add-sub.test`, `print-precedence.test`, `print-parens.test` and `print-wrap.test`. Output format is decimal with a leading `-` when negative, followed by `\n`.
- [ ] 7. Whole-program run path. Connect lexer, parser and evaluator into one run function. Output is produced only after the whole program parses. Add `print-multi.test` (two lines print in order) and `empty.test` (empty file prints nothing and succeeds). Add a unit test that confirms a file with a valid first line and a bad last line writes nothing.
- [ ] 8. Code generator: arithmetic. Add `compiler/stage0/src/codegen.ts`, which lowers the expression tree to WebAssembly with the toolkit `ModuleBuilder` and `Op`. Use `i32.add`, `i32.sub` and `i32.mul`, which already wrap. The module has no output yet; it returns each value on the operand stack for a unit test. Check the emitted module with `toolkit/validate.ts`.
- [ ] 9. Code generator: output through WASI. Import `fd_write` from `wasi_snapshot_preview1` with `importFunc`. Emit a decimal-to-text routine in wasm that handles 0 and negative values, including -2147483648. Export `_start` with `addFunc` and `exportFunc`, export memory with `exportMemory`, and set memory with `setMemory`. The module imports only WASI preview 1 functions. Add a test that the import list has only `wasi_snapshot_preview1` entries.
- [ ] 10. Build and determinism. Wire the `build` path so `bin/glyphc build` produces a wasm file from stage0 without editing `bin/glyphc`. Add a test that compiles each run test twice and compares bytes. Add a test that runs each run-test wasm under the toolkit's WASI harness and compares stdout to the expected output.
- [ ] 11. Examples and coverage. Add a grammar-to-test map in the conformance folder listing every production (`program`, `line`, `expr`, `term`, `factor`, `INT`, `EOL`) and the tests that cover it. Confirm every error code in `spec/errors.json` has a compile-error test. This subtask adds no compiler code.

Out of scope for this plan: variables, unary minus, multi-argument print, runtime traps. The RFC defers or rejects them.
